# Changelog

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).
Версии следуют [Semantic Versioning](https://semver.org/lang/ru/).

Правило проекта: любое изменение поведения, инфраструктуры или публичных
интерфейсов попадает сюда и в `docs/adr/` (см. `AGENTS.md`).

## [Unreleased]

### Added

- OCR изображений-вложений: `electron/lib/ocr.js` с четырьмя движками за одним
  интерфейсом — `winrt` (Windows, офлайн), `vision` (macOS, офлайн), `tesseract`
  (любая ОС) и `mai` (шлюз, `hunyuan-ocr`). В режиме `auto` локальные движки идут
  первыми, сеть последней. См. ADR 0023 и `docs/OCR.md`.
- `electron/lib/ocr-winrt.ps1`: мост к `Windows.Media.Ocr`. Файл только ASCII —
  PowerShell 5.1 читает скрипт без BOM как ANSI. Результат пишется в UTF-8 файл,
  потому что консоль 5.1 использует OEM-кодовую страницу.
- `recognizeAttachment()` в `electron/lib/attachments.js`: распознаёт текст и
  пишет `.txt` рядом с изображением. Отдельная асинхронная функция, поэтому
  `saveFromPaths` остаётся синхронным.
- IPC `ocr:status`, `ocr:recognize` и мост `window.mai.ocr`.
- Раздел `ocr` в настройках: движок, язык, провайдер, модель, таймаут.
- `scripts/test-ocr.mjs` и команда `npm run test:ocr`: 24 проверки без сети.
- `.gitignore`: `.mai-code/artifacts/` — результаты прогонов и отладочные блобы
  не попадают в `git status`.
- Кнопка «текст» у изображения-вложения в поле задачи: распознаёт текст и
  добавляет путь к `.txt` в манифест промпта. Видна только для изображений и
  исчезает, когда текст получен.
- Голосовой ввод в поле задачи: кнопка микрофона записывает фразу, MAS
  распознаёт её локально, текст вставляется в позицию курсора. Запись идёт
  через `AudioContext`, в MAS уходит WAV. См. ADR 0021 и `docs/MAS.md`.
- `electron/lib/mas.js`: клиент MAS. Токен читается из
  `%APPDATA%\MAS\data\api-token`, адрес и модель задаются в настройках,
  `MAS_API_URL` / `MAS_API_TOKEN` / `MAS_API_MODEL` перекрывают их для тестов.
- IPC `mas:status`, `mas:config`, `mas:transcribe` и мост `window.mai.mas`.
- Раздел «MAS — распознавание речи» в настройках: включение, адрес, модель,
  токен и кнопка «Проверить связь».
- Сервис `services/mav`: озвучка русского текста на моделях шлюза MAI.
  Синтез речи пятью голосами Silero, озвучка книги по главам Markdown,
  дубляж (распознавание → текст → синтез), подбор голоса по референсной
  записи. HTTP API и веб-интерфейс, зависимостей нет, запуск
  `node src/index.js`. См. ADR 0020 и `services/mav/README.md`.
- `services/mav/src/audio.js`: измерение высоты тона (F0) и темпа без
  зависимостей. Автокорреляция с защитой от ошибки на октаву: выбирается
  наименьший лаг, у которого корреляция близка к максимуму.
- `services/mav/src/wav.js`: разбор, сборка и склейка WAV PCM16 без ffmpeg.
  Позволяет озвучивать текст длиннее лимита шлюза (~900 символов).
- `services/mav/src/engines.js`: движки синтеза за общим интерфейсом.
  `mai` — сетевой шлюз, `piper` — локальный офлайн (код есть, бинарник
  не установлен, не проверено).
- `services/mav/test/measure-voices.mjs`: пересъёмка эталонных F0 голосов.
  Эталоны в `src/mai.js` получены замером, а не из документации.
- Тесты MAV: `test/unit.mjs` (31, без сети), `test/live.mjs` (14, живой
  шлюз), `test/server.mjs` (18, HTTP).
- `scripts/docker-mem.mjs` и команды `npm run docker:mem` / `docker:mem:check`:
  отчёт по памяти Docker — потребление, лимит, сумма лимитов и запас до памяти
  демона. `--check` возвращает код 1, если найден контейнер без `mem_limit` или
  если сумма лимитов больше памяти, доступной демону (в WSL2 — лимита ВМ).
  Вторая проверка ловит случай «ограничили WSL2 слишком сильно, и контейнеры
  падают по OOM». При сбое `docker stats` отчёт деградирует: лимиты берутся из
  `docker inspect`.
- Лимиты `mem_limit`, `cpus`, `pids_limit` и ротация логов (`x-logging`,
  10 МБ × 3 файла) во всех сервисах `infra/docker-compose.yml`,
  `infra/keycloak/docker-compose.yml`, `infra/multica/docker-compose.yml`,
  `infra/observability/docker-compose.yml`. См. ADR 0019.
- `JAVA_OPTS_APPEND: -XX:MaxRAMPercentage=70 -XX:+UseSerialGC` для Keycloak:
  JVM учитывает лимит контейнера, а не память хоста.

- Полоса заголовка окна тёмная: `titleBarStyle: 'hidden'` и `titleBarOverlay`

- `docs/DEPLOYMENT.md`, раздел 11: правило выбора лимита WSL2 — не меньше суммы
  `mem_limit` одновременно работающих стеков плюс запас на Docker Desktop и k3d.
  Слишком малый лимит ВМ останавливает Docker, это уже наблюдалось.

- Правило 7 в `AGENTS.md`: один проход, независимые вызовы инструментов одним
  блоком, остановка только при секрете, решении пользователя или блокере.
- Правило 8 в `AGENTS.md`: слово «продолжи» — сигнал сбоя агента. При нём агент
  не задаёт вопросов, не пересказывает сделанное и сразу выполняет следующий
  шаг из своего плана. Запрещено заканчивать ответ вопросом «продолжать?», если
  следующий шаг уже назван.
- `scripts/granola-proxy.ps1`: запуск Granola через прокси. Приложение Granola
  не запускается в РФ: `api.granola.ai` и `*.api.granola.ai` отдают HTTP 451
  (блокировка по региону). Скрипт проверяет прокси, выставляет
  `HTTPS_PROXY`/`HTTP_PROXY` и передаёт Chromium-флаги `--proxy-server` и
  `--proxy-bypass-list`. Проверено: без прокси `api.granola.ai` возвращает 451,
  окно приложения висит на «Taking longer than usual». С рабочим прокси не
  проверено — на машине нет прокси и VPN.
- Режимы разрешений как в Claude Code: «Авто», «Вручную», «Принимать правки»,
  «План». Переключатель рядом с полем ввода. Режим хранится **в сессии**:
  разные чаты могут работать в разных режимах, а `settings.permissionMode`
  служит значением по умолчанию для новых чатов. В режиме «План» агент только
  читает и предлагает план с альтернативами. См. ADR 0017.
- `scripts/test-permissions.mjs`: 55 проверок режимов;
  `scripts/test-permissions-integration.mjs`: 24 проверки связки «режим →
  approve → инструмент → файл на диске»; `scripts/test-shell.mjs`: 4 проверки

### Changed

- Вложения больше не вставляются в текст промпта: файл копируется в проект, в
  контекст уходит манифест с путями. Пределы выросли с 64 КБ до 200 МБ на файл.
  Бинарные файлы, PDF, Office и архивы теперь поддерживаются (ADR 0016).
- Сборка Electron облегчена (ADR 0015): из `electron-builder.yml` исключены
  карты исходников, TypeScript-декларации, тесты и документация зависимостей.
  `mermaid` грузится лениво при первом показе диаграммы, а не при открытии
  доски. В окнах отключены проверка орфографии и троттлинг фона.
- Multica CLI: официальная установка, поиск в `%USERPROFILE%\.multica\bin`,
  декодирование UTF-8/cp866/cp1251, кнопка «Установить CLI».
- Документация: `docs/GUARDRAILS.md`, `docs/RUNTIMES.md`,
  `docs/OBSERVABILITY.md`; обновлены `MULTICA.md`, `PRESETS.md`, `SANDBOXES.md`,
  `DEPLOYMENT.md`, `SUMMARY.md` и ADR 0011–0014.
- `README.md` и `docs/BACKLOG.md` отражают фактическое состояние, а не планы.
- `package.json`: новые скрипты `pack:offline`, `docs:check`, `multica:*`.
- `pack:offline`: архив собирается как tar и сжимается gzip level 1. На Windows
  используется `7za` из кеша electron-builder, иначе — `tar` и `zlib` Node.

### Fixed

- Сохранение настроек больше не стирает токен MAS. Пустое поле «Токен» теперь
  значит «оставить прежний». Раньше запись пустой строки переключала клиент на
  локальный `%APPDATA%\MAS\data\api-token`, и удалённый MAS отвечал 401.
- `edit_file` действительно записывает файл. Раньше `fs.writeFileSync` стоял в
  одной строке после `return` и был недостижим: инструмент отвечал «Изменено»,
  файл на диске не менялся, агент повторял правку до `maxIterations`. Снаружи
  это выглядело как зависание.
- `grep` ищет в файле, если `path` указывает на файл. Раньше `readdirSync` падал
  на файле, ошибка глушилась, и инструмент молча возвращал «Совпадений нет» —
  агент делал лишние итерации. Теперь несуществующий путь даёт явную ошибку.
- Подтверждение действия больше не ждёт вечно. `approve` получил таймаут 10
  минут и событие `approval:expired`. Закрытие модалки крестиком или кликом по
  фону считается отказом. Второе подтверждение при открытом первом отклоняется,
  а не открывается поверх. См. ADR 0018.
- `mcp.call` ограничен таймаутом 120 с. Раньше `callTool` мог висеть
  бесконечно: таймауты были только у `connect` и `listTools`.
- Правило «один проход» было записано только в память, но отсутствовало в
  `AGENTS.md`. Память ссылалась на несуществующее правило 7, поэтому цикл
  «сделал шаг → жду продолжения» повторился. Правило добавлено в `AGENTS.md`.
- Раскрытый список селектора режимов разрешений больше не показывает белый
  текст на белом фоне: в `renderer/styles.css` и `renderer/board.css` добавлен
  `color-scheme: dark` и явные цвета `option`. Сам `.mode-select` оформлен как
  `.model-select`: фон `--bg-elev-2`, своя стрелка, состояния `mode-auto` и
  `mode-plan`.
- `run_shell` больше не подставляет `repowise distill` в каждую команду, когда
  `repowise` не установлен. Раньше любая команда падала с «не является
  внутренней или внешней командой». Доступность проверяется один раз и
  кешируется.
- Отказ в подтверждении больше не проглатывается: `approve` возвращает строку
  с причиной, а инструменты сравнивают результат строго с `true`. Раньше
  нестрогая проверка `if (!allowed)` пропускала отказ, и режим «План» мог
  записать файл.
- Упакованное приложение при самоперезапуске больше не теряет первый CLI-аргумент.
- `npm` в PowerShell заменён на `npm.cmd` в инструкциях.
- Multica CLI больше не считается отсутствующим, если установлен в
  `%USERPROFILE%\.multica\bin`, но PATH ещё не обновился.
- Вывод Multica на Windows больше не превращается в «кракозябры»: буфер
  декодируется как UTF-8, затем cp866/cp1251.
- `multica issue create/update` не ломается на кириллице и переводах строк:
  процесс запускается без `shell: true`.
- Встроенный агент: остальные рантаймы теперь можно включить, а несколько —
  запустить параллельно; выключенные не выбираются.
- Kubernetes: `DATABASE_URL` в Multica собирался с пустым паролем, потому что
  `$(MULTICA_DB_PASSWORD)` раскрывается только для ранее объявленных переменных.
  Переменная перенесена выше `DATABASE_URL`; живой прогон подтвердил `/healthz`.
- Kubernetes: readiness-пробы Postgres/Keycloak/Multica получили
  `timeoutSeconds`, иначе поды мигали `0/1` под нагрузкой.
- Observability: `minio/mc` больше не доступен (Docker Hub 404, quay 401);
  бакеты создаются через `weed shell` из образа SeaweedFS.
- Observability: порты SeaweedFS сдвинуты на `18333/18888/19333`, чтобы не
  конфликтовать с основным SeaweedFS приложения.
- GitHub Pages: деплой падал, потому что Pages не был включён в настройках
  репозитория. Workflow теперь включает его сам (`enablement: true`), добавлен
  `site/.nojekyll`.
