# Changelog

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).
Версии следуют [Semantic Versioning](https://semver.org/lang/ru/).

Правило проекта: любое изменение поведения, инфраструктуры или публичных
интерфейсов попадает сюда и в `docs/adr/` (см. `AGENTS.md`).

## [Unreleased]

### Security

- Доверие к папке проекта (ADR 0028): без доверия не загружаются плагины,
  MCP-серверы, `AGENTS.md`, память и навыки проекта, не запускаются стадии
  досок, «Без вопросов» понижается до «Вручную». Раньше открытие папки
  исполняло её плагины в main-процессе.
- Матрица прав IPC (ADR 0028): каждый канал помечен `any`, `admin` или `self`,
  канал вне матрицы закрыт. Гостю закрыты `runtimes:run`, `mcp:connect`,
  `infra:pushSecrets`, `repowise:install`, `repowise:distill` и другие.
- `app:openPath` открывает только папки (раньше запускал любой файл).
- `repowise:distill` проверяет команду guardrails.
- Внешние CLI соблюдают режим разрешений (ADR 0029); запрос больше не
  разбирается `cmd.exe` (`%VAR%`, переводы строк, кавычки).

- PolicyEngine (ADR 0027): разрешение проверяется в цикле агента для любого
  инструмента. Раньше MCP-инструменты и плагины выполнялись без проверки, в том
  числе в режиме «План». MCP — `read` только при `readOnlyHint`, иначе спросить.
- `run_shell` с параметром `cwd` больше не выходит за пределы проекта.
- Роль `guest` не может включить режим «Без вопросов»: проверка в main.

### Changed

- OpenCode и другие CLI без флагов режима на хосте запускаются только в режиме
  «Без вопросов»; в остальных режимах — через docker (проект `:ro`) или свои
  `permissionArgs`. Группа рантаймов с правом записи в одну папку не запускается.

- Режим «Авто» переименован в «Без вопросов» (`bypass`), помечен предупреждением.
  Сохранённое `auto` читается как `bypass`.
- В режиме «Принимать правки» запись в память спрашивает подтверждение.
- Окно подтверждения: риск, причина, рекомендованный ответ с подсветкой и
  фокусом, ответы «Да» / «Да, и не спрашивать» / «Нет» с пояснением для агента,
  клавиши 1–3.
- Замечание ревизора хранится с ролью `review`: в чате и экспорте это не реплика
  пользователя.
- У каждого ответа сохраняется модель; подпись в истории больше не меняется
  при смене модели.

### Fixed

- Транспорт Responses превращал картинку в текст с base64.

- MCP-инструменты уходили в `chat.completions` пустыми схемами.
- Сообщения внешнего рантайма (`role: runtime`) ломали следующий запрос
  встроенного агента ошибкой 400.
- Ошибка посреди прогона теряла выполненные шаги: история сохраняется после
  каждого шага.
- Обрезка истории могла оставить результат инструмента без вызова; обрезанное
  начало удалялось из сохранённой сессии.
- `edit_file` раскрывал `$&` и `$1` в новом тексте.
- `edit_file` спрашивал разрешение, даже если фрагмента нет.
- Смена режима посреди прогона откатывалась при сохранении сессии.
- `sessions.json` пишется атомарно.

### Added

- Изображения из вложений уходят модели с поддержкой изображений частью
  `image_url` (`input_image` в Responses API); при отказе шлюза шаг повторяется
  без картинки.
- Учёт токенов по шагам: `usage` в ответе, событие `usage`, подпись в чате.
- Блокировка проекта: чат, самокоррекция и рантайм с правом записи не правят
  одну папку одновременно.
- Тесты `test-trust`, `test-ipc-permissions`, `test-runtimes`, `test-vision`,
  `test-usage`, `test-project-lock`; разделы [8]–[10] `test-agent-loop`, [15] `test-ui`.
- Режим «Только разрешённое» (`dontAsk`) для фоновых задач.
- Правила разрешений `allow` / `ask` / `deny`: `settings.permissions` и правила
  чата; IPC `permissions:rules`.
- Журнал решений `audit.jsonl`, IPC `permissions:audit`.
- Тесты `test-policy`, `test-agent-loop`, матрица «режим × источник» в
  `test-permissions-integration`, раздел [14] в `test-ui`; электронные тесты в CI.

- `docs/BACKLOG-NEXT.md` — бэклог выравнивания по аудиту кода: движок разрешений,
  диалоговый интерфейс, рекомендованные варианты, противоречия между фичами.
- Инструменты агента `memory_read` и `memory_append` (`electron/lib/tools/memory.js`).
  `memory_read` читает оба уровня памяти и историю версий, подтверждения не требует.
  `memory_append` дописывает блок в конец памяти и создаёт версию через `saveMemory`,
  поэтому история и откат работают так же, как из панели «Память». Повторный текст
  версию не создаёт. Предел блока — 20 000 символов. См. `docs/MEMORY.md`.
- Индикатор суммарного размера вложений в композере: число файлов из 20 и общий
  размер. При превышении 500 МБ индикатор подсвечивается. См. бэклог №5.
- Экспорт ответа агента в MD, TXT, DOCX и XLSX. Меню «Скачать» у сообщения
  и кнопка «Скачать чат» в боковой панели. DOCX и XLSX собираются без внешних
  библиотек: ZIP с XML внутри, `zlib` входит в Node. См. ADR 0025 и
  `electron/lib/export/`.
- `scripts/make-sums.mjs` и `npm run pack:sums`: пересчёт SHA-256 для всех
  артефактов `dist/`. Раньше `make-offline.mjs` дописывал только строку архива,
  и хеши EXE оставались от прошлой сборки.
- `scripts/test-export.mjs` и `npm run test:export`: 92 проверки экспорта —
  ZIP, разбор Markdown, DOCX, XLSX, имена файлов, запись на диск.
- Второй транспорт к шлюзу — OpenAI Responses API (`electron/lib/responses.js`).
  Модели, которым не дан `/v1/chat/completions` (`gpt-5.6-sol`, `gpt-6.1-sol` на
  AgentRouter), работают: цикл агента тот же, ход оборачивается в `/v1/responses`
  после первой же ошибки шлюза и остаётся выбранным на всю сессию. См. ADR 0026.
- `providerUserAgent()` в `electron/lib/config.js`: User-Agent провайдера для
  запросов к шлюзу. AgentRouter пропускает только клиент Claude Code и отвечает
  401 остальным. Применяется в SDK, в `models.js` и в проверке провайдера из UI.
- `scripts/test-responses.mjs` и `npm run test:responses`: 17 проверок транспорта
  без сети — конвертация сообщений и схем инструментов, разбор ответа, детектор
  «нужен responses», температура по имени модели.
- `scripts/test-memory-tools.mjs` — 40 проверок инструментов памяти: схемы, чтение,
  дописывание, версии, дубли, отказ пользователя, лимиты, режимы разрешений.
  Запуск: `npm.cmd run test:memory` (нужен Electron).
- Блок `[12]` в `scripts/test-ui.mjs`: проверка индикатора размера вложений.
- Версии памяти и откат: `electron/lib/memory.js` хранит историю правок
  `memory.md` в хранилище артефактов (тип `memory`, идентификаторы
  `memory:project` и `memory:global`). Повторное сохранение того же текста версию
  не создаёт — сравнение по SHA-256. Откат добавляет версию, а не удаляет
  историю. См. ADR 0024 и `docs/MEMORY.md`.
- IPC `memory:save`, `memory:version`, `memory:restore` и мост `window.mai.memory`.
  `memory:write` принимает `projectDir` и версионирует запись, если путь совпал с
  файлом памяти. Запись и откат требуют роль `admin`.
- Панель «Память»: кнопки «Версии проекта» и «Версии глобальной», список версий
  с действиями «Показать» и «Откатить».
- `scripts/smoke-electron.mjs`, блок `[7]`: 9 проверок версий памяти внутри
  Electron. Прогон: 40 OK, 0 FAIL.
- OCR изображений-вложений: `electron/lib/ocr.js` с четырьмя движками за одним
  интерфейсом — `winrt` (Windows, офлайн), `vision` (macOS, офлайн), `tesseract`
  (любая ОС) и `mai` (шлюз, `hunyuan-ocr`). В режиме `auto` локальные движки идут
  первыми, сеть последней. См. ADR 0023 и `docs/OCR.md`.
- `electron/lib/ocr-winrt.ps1`: мост к `Windows.Media.Ocr`. Файл только ASCII —
  PowerShell 5.1 читает скрипт без BOM как ANSI. Результат пишется в UTF-8 файл,
  потому что консоль 5.1 использует OEM-кодовую страницу.
- `recognizeAttachment()` в `electron/lib/attachments.js`: распознаёт текст и
  пишет `.txt` рядом с изображением. Отдельная асинхронная функция, поэтому
  `saveFromPaths` остаётся синхронным.
- IPC `ocr:status`, `ocr:recognize` и мост `window.mai.ocr`.
- Раздел `ocr` в настройках: движок, язык, провайдер, модель, таймаут.
- `scripts/test-ocr.mjs` и команда `npm run test:ocr`: 24 проверки без сети.
- `.gitignore`: `.mai-code/artifacts/` — результаты прогонов и отладочные блобы
  не попадают в `git status`.
- Кнопка «текст» у изображения-вложения в поле задачи: распознаёт текст и
  добавляет путь к `.txt` в манифест промпта. Видна только для изображений и
  исчезает, когда текст получен.
- Голосовой ввод в поле задачи: кнопка микрофона записывает фразу, MAS
  распознаёт её локально, текст вставляется в позицию курсора. Запись идёт
  через `AudioContext`, в MAS уходит WAV. См. ADR 0021 и `docs/MAS.md`.

### Changed

- Ветки: только `dev` и `main`. Разработка ведётся в `dev`, в `main` попадает
  только проверенное через pull request. Прямой push в `main` запрещён.
  Правило 9 в `AGENTS.md`.
  Прямой push в `main` блокирует хук `scripts/hooks/pre-push`;
  установка — `npm run hooks:install` (копирует хуки в `.git/hooks`,
  `core.hooksPath` не трогает, чтобы не отключить `post-commit` от repowise).
- `.github/workflows/ci.yml`: тесты, проверки транспорта и экспорта, ссылки в
  документации и `git diff --check` на push и pull request в `dev` и `main`.
  Раньше автоматических проверок в CI не было — только сборка релиза по тегу
  и публикация сайта.
- `make-offline.mjs` вызывает `make-sums.mjs` вместо дописывания одной строки
  в `SHA256SUMS.txt`.
- `memory_append` добавлен в `WRITE_TOOLS`, `memory_read` — в `READ_TOOLS`
  (`electron/lib/permissions.js`). В режиме «План» запись в память скрыта от модели.
- В системный промпт добавлен раздел «Память» с описанием обоих инструментов.
- `docs/BACKLOG.md` — единственный источник статусов. `docs/ROADMAP.md` больше не
  дублирует статусы, а ссылается на пункты бэклога: расхождение «сделано в коде,
  не начато в плане» устранено.
- Статусы бэклога приведены к коду: пункты 4 и 5 закрыты полностью.

### Removed

- Неиспользуемые экспорты: `docsRoot()` в `electron/lib/docs.js`, `OCR_DEFAULTS`
  в `electron/lib/ocr.js`, экспорт `KINDS` в `electron/lib/artifacts.js`
  (константа осталась локальной). Найдено `repowise dead-code`.

### Fixed

- GitHub Pages не публиковался: два упавших пайплайна `pages` (#1, #2).
  Причина в двух дефектах: сайт Pages никогда не был создан, а `GITHUB_TOKEN`
  не имел прав его создать — в настройках репозитория разрешения workflow
  стояли в read-only и переопределяли `permissions: pages: write` из файла
  workflow. Ошибка в логе: «Create Pages site failed. Resource not accessible
  by integration». Исправлено: сайт Pages создан через API с `build_type:
  workflow`, разрешения workflow подняты до write. Прогон #3 — success,
  сайт отвечает 200: https://crruton.github.io/MAI/
- Защита ветки `main` включена на GitHub: слияние только через pull request,
  обязательная проверка CI `check`, запрет force push и удаления ветки.
  Push в `main` отклоняется сервером даже с `--no-verify` и у администратора
  (`GH006`). На приватном репозитории бесплатного тарифа это было недоступно
  (403 «Upgrade to GitHub Pro»); репозиторий сделан публичным после проверки
  истории на ключи — находок нет.
- Выпадающий список моделей показывал недоступное и прятал доступное: статические
  списки разошлись с каталогами шлюзов. В `STATIC_MODELS` у MAI четыре живые
  чат-модели вместо исчезнувшей `Qwen3.5-122B-A10B`, у AgentRouter — `gpt-5.6-sol`
  и `gpt-6.1-sol` вместо трёх моделей, которых под этим ключом нет.
- Миграция из `.env` записывала в провайдер одну модель из `LLM_MODEL`; теперь
  берётся полный список `STATIC_MODELS.mai`.
- `temperature` больше не уходит моделям GPT-5+: шлюз отвечает `400 Unsupported
  parameter`. Проверка по имени модели, в обоих транспортах.
- Индикатор размера вложений больше не добавляется при пустом списке:
  `renderAttachments` выходит раньше. Найдено тестом `[12]` в `scripts/test-ui.mjs`.
- Битая ссылка `docs/adr/0021-mav-audio-service.md` в `services/mav/README.md` →
  `docs/adr/0020-mav-servis-ozvuchki.md`.
- Ссылки на `docs/API.md` в `docs/MAS.md` и ADR 0021 помечены как внешние:
  файл живёт в репозитории MAS, в этом репозитории его нет.
- Файл окружения MAV в README помечен как отсутствующий в git.
