# Changelog

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).
Версии следуют [Semantic Versioning](https://semver.org/lang/ru/).

Правило проекта: любое изменение поведения, инфраструктуры или публичных
интерфейсов попадает сюда и в `docs/adr/` (см. `AGENTS.md`).

## [Unreleased]

### Added

- Наборы навыков каталога по ролям (ADR 0115): поле `roles` в `mai-marketplace.json`
  (developer, analyst, pm, qa, lead). Мастер первого запуска ставит навыки роли из
  каталога команды; `--role` у `skills:export` и `multica:skills`. Проверка каталога
  проверяет роли. Модуль `electron/lib/catalog-roles.js`, тест `test-catalog-roles` (19).
- Каталог: навыки `openspec` (change по PBC, delta specs, архив) и `task-breakdown`
  (нарезка PBC на задачи по логике). Проверка каталога не пропускает ссылку на навык,
  которого нет ни в каталоге, ни среди встроенных навыков MAI.
- Каталог: 7 навыков продуктового цикла (`request-triage`, `product-discovery`,
  `customer-interview`, `product-prd`, `pbc`, `change-request`, `use-cases`) — одна копия
  вместо двух расходящихся, без привязки к конкретному продукту. Проверка каталога ищет
  внутренние названия (`denyTerms` в `catalog/catalog-policy.json`).
- Экспорт навыков каталога в Claude Code, OpenCode и Codex (ADR 0114):
  `npm.cmd run skills:export -- --target claude,opencode,codex` (`--dry-run`, `--prune`,
  `--project`, имена). Метка `.mai-catalog.json`; чужие папки не перезаписываются; запись
  через временную папку. Модуль `electron/lib/skills-export.js`, тест `test-skills-export` (18).
- Навыки каталога → Multica MAI (ADR 0113): кнопка «Навыки → Multica» в панели и
  `npm.cmd run multica:skills` (`--dry-run`, `--prune`, имена). Свои навыки помечаются
  `config.managed_by: mai-code` с версией и хэшем; повтор ничего не меняет; навык,
  созданный вручную, не перезаписывается. Хэш и загрузка — с LF, чтобы Windows и Linux
  не гоняли навыки по кругу. IPC `multica:pushSkills`, тест `test-multica-skills` (23).
- Multica: workspace и проект для репозитория (ADR 0112). Выбор в панели «Multica» →
  «Этот проект», хранение в `.mai-code/settings.json` (для команды, в git) или
  `settings.local.json` (личное). CLI получает `--workspace-id` и `--project`; id
  проверяется, чтобы значение из файла не стало флагом. IPC `multica:target`,
  `multica:workspaces`, `multica:projects`, `multica:setTarget`; модуль
  `electron/lib/multica-target.js`, тест `test-multica-target` (25 проверок).
- Каталог навыков команды (ADR 0111): `mai-marketplace.json` в корне и 18 пакетов
  в `catalog/` версии 1.0.0 — подключается в `/packages` адресом репозитория.
  Проверка `electron/lib/catalog-check.js` и `scripts/test-catalog.mjs`: версии,
  владелец, лицензии upstream, токены, внутренние хосты и email. Документация —
  `docs/CATALOG.md`.
- Бэклог командной работы `docs/BACKLOG-TEAM.md`: единое хранилище скиллов на
  каталоге пакетов MAI, MAI для команды с Multica MAI, MAI Ship (декомпозиция
  Claude Ship под GitLab), маркетплейс на Authentik; челлендж 73 входных скиллов.
- MAI Ship: модуль политики апрува `electron/lib/ship/policy.js` (ADR 0109) —
  чистая функция `evaluate` без модели: самозащита конфигурации, бюджет и
  выключатель, гейты, правила (строгое решение сильнее), классификаторы только
  ужесточают, observe никогда не ставит approve; семейства моделей и проверка
  независимости approver'а `electron/lib/model-families.js` (ADR 0110). Тест
  `scripts/test-ship-policy.mjs`, 65 проверок. Разбор YAML и вызовы GitLab — дальше.
- MAI Ship для GitLab — спецификация (ADR 0108, 0109, 0110, статус proposed):
  ревью, steward и approver MR по образцу Claude Ship на примитивах GitLab;
  политика апрува `.mai-code/approval-policy.yaml` и настройки `.mai-code/ship.yaml`
  с JSON-схемами и примерами; approver от другого семейства моделей; старт в
  observe-only. Изменение `openspec/changes/mai-ship-gitlab/`, кода пока нет.
- Инструменты (ADR 0054): `glob` — поиск файлов по маске; `edit_file` —
  `replace_all`, несколько правок за вызов (атомарно), файлы с CRLF; длинный
  вывод любого инструмента — целиком в файл, модели — начало, конец и путь;
  `read_file` показывает модели со зрением картинки и читает текст PDF.
- Фоновые команды (ADR 0055): `run_shell` с `background: true` — сервер
  разработки или долгая сборка в фоне; `shell_output` — вывод, `shell_kill` —
  остановка; при выходе из приложения останавливаются.
- Веб (ADR 0056): `web_fetch` — страница текстом, `web_search` — поиск
  (DuckDuckGo без ключа, свой SearXNG или Brave). С вопросом или по правилу
  на домен; адреса локальной сети запрещены.
- Повторы и запасная модель (ADR 0057): при перегрузке или обрыве шаг
  повторяется до трёх раз с уведомлением (учитывается `Retry-After`); если не
  помогло или модель недоступна — продолжает запасная модель из настроек.
- Глубина рассуждений (ADR 0058): у поля ввода «Глубина: быстро / средняя /
  глубоко» для моделей, которые это поддерживают; `temperature` и
  `reasoning_effort` шлются только поддерживаемые. Возможности модели можно
  задать флагами в списке моделей провайдера.
- `/commit` — агент пишет сообщение по diff и коммитит после подтверждения
  (подпись настраивается); `/review [PR]` — ревью изменений с `файл:строка`
  (ADR 0059). Своя команда с тем же именем сильнее встроенной.
- Презентации (ADR 0066): `create_document` создаёт `.pptx` из списка слайдов
  или Markdown, `read_document` читает презентации по слайдам.
- PDF (ADR 0067): `create_document` создаёт `.pdf` из Markdown (A4, кириллица,
  таблицы) встроенным Chromium — без JavaScript и без сети.
- Самопроверка документов (ADR 0068): `preview_document` показывает модели со
  зрением первые страницы DOCX/PPTX/XLSX/MD (и PDF, если есть `pdftoppm`)
  картинками; в «Задаче» агент смотрит на документ перед сдачей.
- Браузер агента (ADR 0069): `browser_open`, `browser_read`, `browser_click`,
  `browser_type`, `browser_screenshot` в отдельном видимом окне. Разрешения по
  доменам, «Сайты без вопросов» и «под запретом» в настройках; пароли, коды и
  карты агент не вводит, оплату подтверждает только пользователь.
- Роли и онбординг (ADR 0070): при первом запуске — выбор роли (разработчик,
  аналитик, юрист, продажи, финансы), набор навыков и команд, подходящие
  коннекторы и примеры задач; вернуться — `/onboarding`.
- MCP (ADR 0071): ресурсы серверов — `@сервер:uri` в поле ввода (содержимое
  уходит агенту как данные); промпты — команды `/mcp__сервер__промпт` с
  аргументами; старые серверы по SSE (`transport`/`type: "sse"` или
  автоматически, если streamable HTTP не поддержан).
- Локальные коннекторы (ADR 0072): Repowise, Multica, Postgres, Vault и
  SeaweedFS — в окне «Коннекторы» со статусом; Repowise включается там же,
  «Настроить» открывает нужную вкладку «Хранилища».
- Чаты (ADR 0073): переименование (✎, `/rename`) и автозаголовок моделью;
  копия чата (⑂, `/fork`); срок хранения в настройках; файл чата MAI —
  экспорт и `/import`; двойной Esc или `/rewind` — список точек отката.
- Интерфейс (ADR 0074): `!команда` — выполнить самому, вывод уходит агенту;
  статусная строка (модель, режим, ветка, контекст, стоимость); светлая,
  тёмная и системная тема; окна доступны с клавиатуры (фокус, Esc, Tab),
  контраст мелкого текста не ниже 4.5:1.
- Субагенты (ADR 0075): `isolation: worktree` — правки в отдельной копии
  проекта, в проект — только после подтверждения (трёхстороннее слияние);
  `background: true` — субагент в фоне, итог приходит в чат и уведомлением,
  `agent_result` — проверить раньше.
- Git (ADR 0076): `/pr` — ветка, push и pull request по шаблону репозитория
  (gh/glab); `/security-review` — ревью уязвимостей с путём атаки;
  `/worktree` — чат в отдельной рабочей копии на своей ветке.
- Безголовый режим (ADR 0077): `mai -p "задача"` без окна для скриптов и CI —
  `--output text|json|stream-json`, `--mode`, `--allow`, задача из stdin;
  те же ключи, правила и хуки, что в приложении.
- Модели (ADR 0078): модели и шлюзы без tool calling вызывают инструменты
  текстовым протоколом (`<tool_call>`), отказ шлюза распознаётся сам;
  «Модель для «Плана»» — сильная модель составляет план, основная выполняет.
- Инструменты (ADR 0079): ноутбуки Jupyter — чтение по ячейкам и
  `notebook_edit`; `diagnostics` — ошибки tsc, ESLint, Ruff/Pyright проекта
  (и проверка после правки по настройке); при множестве MCP их схемы
  загружаются по запросу (`tool_search`).
- Контекст (ADR 0080): обрезанная память помечена в промпте и видна в панели;
  читаются CLAUDE.md, GEMINI.md, правила Cursor и Copilot (без повторов
  AGENTS.md); кэш промпта для Claude (`cache_control`); дубли навыков —
  предупреждение при установке и пометка в панели.
- Уведомления (ADR 0081): когда окно не в фокусе — «готово», «нужно
  подтверждение», «агент спрашивает», ошибка, фоновый субагент, плановая
  задача; по желанию — в мессенджеры каналами: Telegram, MAX, WhatsApp,
  Rocket.Chat и webhook (Slack, Mattermost, Discord, Teams), у каждого свои
  события; токены хранятся зашифрованными.
- Набор сценариев (ADR 0082): `npm run eval` — 20 типовых задач «Код» и
  «Задача» с автоматической проверкой результата, прогон по профилям (модель,
  режим, правила) и отчёт Markdown/JSON.
- PDF (ADR 0083): агент собирает PDF из нескольких файлов и вырезает страницы
  (`pdf_merge`), читает и заполняет формы (`pdf_fields`, `pdf_form`), в том
  числе кириллицей. Новая зависимость — pdf-lib (MIT).
- «Запомнить?» (ADR 0084): после работы с правками модель предлагает один урок
  для памяти — плашка «В проект / Глобально / Нет». Инструмент агента `ocr` —
  текст с картинки и скана PDF.
- Рантаймы (ADR 0085): проба показывает версию CLI и предупреждает о старой
  (`minVersion`); экспорт и импорт настроек в JSON без ключей env.
- Агент схем (ADR 0086): правка модели архитектуры — предложением с diff;
  запись только по «Применить», с проверкой, что модель не изменилась.
- Хранилище (ADR 0087): автосинхронизация артефактов с Postgres и SeaweedFS в
  фоне — очередь с задержкой и повторами, состояние и «Синхронизировать сейчас»
  во вкладке «Инфраструктура».
- MCP (ADR 0088): зависший stdio-сервер перезапускается по таймауту вызова или
  ping; чтение повторяется само. Repowise — таймаут 60 с, карточка «MCP-сервер»
  с числом перезапусков и кнопкой «Перезапустить».
- Multica (ADR 0089): «Статусы → tasks.md» — задачи, закрытые в Multica,
  отмечаются `[x]` в `openspec/changes/*/tasks.md`; `multica-sync.mjs --pull`.
- Калибратор (ADR 0090): «Откалибровать» на доске «Архитектура» — противоречия,
  пробелы, риски и вопросы по PRD, C1–C3, ADR и OpenSpec; отчёт — артефакт с
  версиями и сравнением с прошлым. Встроенный субагент `calibrator`.
- Голос (ADR 0092): ошибка видна на кнопке микрофона с причиной, «↻» повторяет
  распознавание той же записи; движок — MAS или провайдер (`audio/transcriptions`).
- Keycloak (ADR 0093): корпоративный режим из `managed-settings.json` — без входа
  только экран «только вход», каналы IPC закрыты; access token продлевается по
  `refresh_token` с пересчётом роли, отзыв закрывает сессию.
- Наблюдаемость (ADR 0094): метрики агента по OTLP — токены, стоимость
  (`telemetry.pricing`), ошибки инструментов и модели, решения о разрешениях;
  строка «Агент» на дашборде Grafana.
- Установщик (ADR 0095): `MAI Code.exe --self-check` и задача CI `installer` —
  сборка NSIS и portable, тихая установка, самопроверка без Node.js, удаление.
- Кроссплатформенность (ADR 0096): выбор оболочки `run_shell` (auto, cmd,
  PowerShell, pwsh, bash, zsh, sh), ОС и оболочка в системном промпте, CI на macOS.
- `/signoff` (ADR 0097, по мотивам gh-signoff): тесты проекта прошли → статус
  `signoff[/контекст]` на HEAD в GitHub; `/signoff fail` — отклонить.
- `/privacy` (ADR 0098, по мотивам OpenJarvis): куда уходят данные — модели,
  плановые задачи, телеметрия, MCP, коннекторы, веб, уведомления, голос; чек-лист
  «строго локально».
- Фильтр секретов (ADR 0099, по мотивам OpenJarvis): ключи, токены, пароли и
  номера карт в запросе к модели — знаками `[СКРЫТО:тип:хеш]`; при правке файлов
  значения подставляются обратно. Режимы: маскировать (по умолчанию),
  предупреждать, блокировать, выключен.
- Локальные модели (ADR 0100): «Провайдеры» находят запущенные Ollama, LM Studio,
  colibri, llama.cpp и Jan и добавляют провайдером в один клик.
- Пакет-пример `impeccable-check` (ADR 0101): хук PostToolUse после правок UI-файлов
  сообщает агенту частые ошибки интерфейса; `${MAI_PACKAGE_DIR}` в хуках пакетов.
- Сканер обновлений (ADR 0102): раз в сутки — устаревшие зависимости, уязвимости,
  конфликты версий, навыки, CLI и новые релизы MAI Code с риском; `/updates` —
  обновить выбранное на отдельной ветке и прогнать тесты.
- `/cleanup` (ADR 0103): после стабильной работы версии — старые копии навыков,
  вывод инструментов, временные папки и кеши каталогов; удаляется только отмеченное.
- Песочница для задач (ADR 0040, дополнение): команды агента в Docker только в
  чатах «Задача» или по настройке проекта.
- Проекты (ADR 0065): «🗂 Проекты» — основная и дополнительные папки,
  инструкции, коннекторы и вид чатов вместе; «Открыть» — и новый чат сразу с
  ними.
- Трассировка агента в OpenTelemetry (ADR 0063): дерево спанов прогон → шаг
  модели → инструмент → субагент с токенами и решениями PolicyEngine.

- Каталог коннекторов (ADR 0052): `/connectors` — Linear, Notion, GitHub, Sentry
  в два клика (вход в браузере или токен); свои коннекторы — у организации в
  `managed-settings.json`.
- Прерванная работа (ADR 0051): если приложение закрыли посреди ответа агента,
  чат помечен «⏸», а в нём — «Работа прервалась… Продолжить»: агент проверит
  сделанное и продолжит с места. В заголовке списка задач — текущий шаг.
- Плановые задачи (ADR 0050): `/schedule` — «по будням в 9:00», «каждый день»,
  «каждые N минут». Задача выполняется сама, пока открыто приложение, в режиме
  «Только разрешённое», результат — новый чат «⏰ …», уведомление и журнал.
- Документы (ADR 0049): агент создаёт Word и Excel (`create_document`: DOCX из
  Markdown, XLSX из листов с числами и формулами, CSV) и читает их
  (`read_document`). Без внешних библиотек; проверено LibreOffice.
- Результаты чата (ADR 0047): кнопка «📄 Результаты · N» — файлы, которые
  агент создал, изменил или удалил, с превью, «Открыть» (только документы и
  картинки) и «В папке».
- Режим «Задача» (ADR 0046): переключатель «Код / Задача» у чата — для работы
  с документами и данными: свой системный промпт (уточнить задачу, результат —
  новым файлом, без git), без инструментов кода. Права те же, что в «Коде».
- Рабочие папки чата (ADR 0045): «＋ папка» над полем ввода даёт агенту доступ
  к ещё одной папке в этом чате; обращение — `@имя/путь`, правила —
  `write_file(@имя/**)`, вне папок файлы недоступны. В Docker-песочнице —
  `/mnt/<имя>`.
- Защита от удаления (ADR 0044): инструмент `delete_file` переносит файлы в
  корзину приложения, удаление спрашивается во всех режимах, кроме «Без
  вопросов»; правила на правки его не покрывают. `/trash` — восстановление.

- Пакеты плагинов (ADR 0037): папка с `mai-package.json`, в которой собраны
  команды, типы субагентов, навыки, плагины, хуки и MCP-серверы. Глобальные —
  `%APPDATA%\mai-code\packages\`, проектные — `.mai-code/packages/`
  (доверенная папка). Установка из папки или git-URL, выключение без удаления,
  `/packages`. Установка, удаление и включение — только admin.
- Уровни настроек (ADR 0038): организация (`managed-settings.json` в системной
  папке, нельзя переопределить), пользователь, проект
  (`.mai-code/settings.json`, в git), локальные (`.mai-code/settings.local.json`,
  только у вас), чат. Организация может запретить режим «Без вопросов» и
  добавить свои хуки. Запрет с любого уровня сильнее любого разрешения.
- В запросе разрешения — вариант «в этом проекте (только у меня)».
- `/permissions`: все правила по уровням, удаление, проверка «что будет с этой
  командой» (ADR 0038).
- Режим «Авто» (ADR 0039): правки проекта и команды без высокого риска внутри
  проекта — без вопросов; сеть, установка пакетов, удаление, `git push`, пути
  вне проекта, встроенный код интерпретатора и MCP — с вопросом, причина видна
  в карточке. Доступен гостю. Сохранённый старый `auto` по-прежнему означает
  «Без вопросов».
- Песочница для команд агента (ADR 0040): «Настройки» → «Команды агента» —

### Fixed

- Каталог: `change-request` ссылался на `mr-publish`, которого нет в каталоге; теперь
  `to-mr` и `openspec`, версия 1.0.1.
- Каталог: в `UPSTREAM.md` навыка `grilling` было название внутреннего workspace;
  убрано, версия 1.0.1.
- Запросы к модели (ADR 0107): обрезка текста по `slice` резала суррогатную
  пару (эмодзи, редкие иероглифы) — в истории оставался одиночный surrogate,
  `JSON.stringify` превращал его в `\ud83d`, и шлюз отвечал `400 Invalid JSON
  payload: no low surrogate in string`. Один такой обрывок ломал все следующие
  запросы сессии. Теперь `text-safe.js`: `safeSlice`/`safeTail` не рвут пару,
  `sanitizeMessages` заменяет одиночные суррогаты на U+FFFD перед отправкой;
  применено в `buildRequest`, `spillOutput` и снимках браузера. Дополнение:
  санитайз опущен на уровень клиента (`safe-client.js::withTextSafety` —
  `chat.completions.create` и `responses.create`), поэтому побочные вызовы
  (компакция, ревизор, калибратор, диаграмма, заголовок, урок) тоже защищены;
  `session-store.js::getSession` чистит историю при чтении, так что сессия,
  записанная старой версией, больше не ломает новые запросы.
- Интерфейс (ADR 0105): атрибут `hidden` перебивался правилами `display` —
  «скрытый» баннер прерванной работы (ADR 0051) оставался пустой жёлтой полосой
  под шапкой. Теперь `[hidden]` скрывает всегда.
- Git (ADR 0106): `git commit` ждал окончания индексации repowise — 58.7 с
  вместо 0.8 с. Хук `post-commit` запускал `repowise update` в подоболочке,
  которая наследовала дескрипторы git: EOF приходил только после выхода внука.
  Теперь `nohup` с перенаправлением всех дескрипторов — коммит не ждёт.

- Процессы (ADR 0096): на macOS/Linux «Стоп» стадии деплоя и рантайма
  останавливал только родителя — потомки (`npm` → `node`) оставались жить.

- Сертификаты (ADR 0095): установленный EXE не доверял корпоративному корню
  Windows — в собранном Electron `NODE_OPTIONS=--use-system-ca` игнорируется.
  Системные корни теперь подключаются в процессе (`tls.setDefaultCACertificates`).

- Windows: блокировка индекса артефактов и запись досок падали с `EPERM`,
  когда два процесса писали одновременно (удаляемый файл блокировки и замена
  открытого файла дают `EPERM`, а не `EEXIST`). Теперь это «занято» с
  повторами (ADR 0062, дополнение).
- Диагностика (ADR 0079): в Windows `python3.exe` из PATH — заглушка Microsoft
  Store. `onPath()` проверял только наличие файла, поэтому `py_compile`
  запускал заглушку, получал пустой вывод и показывал «Ошибок нет» на файле
  с синтаксической ошибкой. Теперь интерпретатор проверяется запуском
  (`python -c pass`), при отказе берётся следующий кандидат.
- «Стоп» не действовал на MCP-инструмент: `withTimeout()` не учитывал сигнал и
  ждал 120 с. Теперь `mcp.call(name, args, signal)` рвёт ожидание сразу.
- Молчащий шлюз вешал ход агента навсегда: `for await` по стриму не имел
  ограничения по времени. Добавлен сторож простоя `idleGuard` — тишина 120 с
  прерывает ход с понятным сообщением; `chat:stop` освобождает состояние через
  5 с, если прогон не завершился. См. ADR 0061.

### Security

- Зависимости (ADR 0104): Electron 38.8.6 → 45.4.1 (уязвимость высокого риска в
  Electron ≤ 42.11.15), openai 6 → 7.62, electron-builder → 26.18, hono — `npm audit
  fix`, `minimatch` 7–11.0.8 в инструментах сборки — через `overrides`. `npm audit` —
  0 уязвимостей. `postinstall: install-electron`: Electron 45 сам бинарник при
  установке не скачивает. Удаление папок — `removeTree`: на Windows Node 24 не
  удаляет файлы «только для чтения» (объекты git).

- Данные от окна проверяются в main до обработчика (ADR 0060): структура для
  всех каналов (размеры, глубина, ключи `__proto__`/`constructor`/`prototype`)
  и типы полей для каналов, которые меняют права, файлы и настройки.

- Пуш в защищённые ветки (`main`, `master` или свои — «Настройки») запрещён
  самим приложением в любом режиме и при любом правиле `allow` (ADR 0059).

- Защита от prompt injection (ADR 0053): прочитанное (файлы, документы, MCP)
  уходит модели в рамке «данные»; если в нём есть признаки внушённых указаний
  («игнорируй инструкции», `curl … | sh`, «не говори пользователю»), «Авто» до
  конца ответа спрашивает про любые действия и показывает, где найдено.

- `allowOutsideProject` и песочницу команд меняет только admin (ADR 0040).
- Токены MCP-серверов (`headers`, `env` в `settings.json`) шифруются хранилищем

- Отправка через коннекторы (ADR 0048): MCP-инструменты, которые отправляют
  письма, сообщения, события или публикуют (`send_*`, `post_*`, `reply_*`,

  раскрытым превью того, что уйдёт; «Да, и не спрашивать» для них нет.

### Security

- PolicyEngine (ADR 0027): разрешение проверяется в цикле агента для любого
  инструмента. Раньше MCP-инструменты и плагины выполнялись без проверки, в
  том числе в режиме «План». MCP — `read` только при `readOnlyHint`.
- Доверие к папке проекта (ADR 0028): без доверия не загружаются плагины,
  MCP-серверы, `AGENTS.md`, память, навыки, команды, хуки и типы субагентов
  проекта, не запускаются стадии досок, «Без вопросов» понижается до «Вручную».
  Раньше открытие папки исполняло её плагины в main-процессе.
- Матрица прав IPC (ADR 0028): каждый канал помечен `any`, `admin` или `self`,
  канал вне матрицы закрыт. Гостю закрыты `runtimes:run`, `mcp:connect`,
  `infra:pushSecrets`, `repowise:install`, `repowise:distill` и другие. Роль
  `guest` не может включить «Без вопросов».
- Внешние CLI соблюдают режим разрешений; запрос больше не разбирается
  `cmd.exe` (`%VAR%`, переводы строк, кавычки) (ADR 0029).
- Плагины исполняются в отдельном процессе без доступа к памяти main, Electron
  API, окнам и переменным окружения с ключами (ADR 0030).
- Окна работают в песочнице (`sandbox: true`) с CSP без inline-скриптов и eval;
  окно досок экранирует данные `boards.json` (раньше файл мог внедрить разметку).
- Ключи провайдеров, токены Vault и MAS шифруются хранилищем ОС (`enc:v1:`);
  уровень защиты виден в «Настройках» (ADR 0031).
- `run_shell` с `cwd` больше не выходит за пределы проекта; `app:openPath`
  открывает только папки; `repowise:distill` — admin и guardrails.
