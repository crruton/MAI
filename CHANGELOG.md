# Changelog

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).
Версии следуют [Semantic Versioning](https://semver.org/lang/ru/).

Правило проекта: любое изменение поведения, инфраструктуры или публичных
интерфейсов попадает сюда и в `docs/adr/` (см. `AGENTS.md`).

## [Unreleased]

### Added

- Пакеты плагинов (ADR 0037): папка с `mai-package.json`, в которой собраны
  команды, типы субагентов, навыки, плагины, хуки и MCP-серверы. Глобальные —
  `%APPDATA%\mai-code\packages\`, проектные — `.mai-code/packages/`
  (доверенная папка). Установка из папки или git-URL, выключение без удаления,
  `/packages`. Установка, удаление и включение — только admin.
- Уровни настроек (ADR 0038): организация (`managed-settings.json` в системной
  папке, нельзя переопределить), пользователь, проект
  (`.mai-code/settings.json`, в git), локальные (`.mai-code/settings.local.json`,
  только у вас), чат. Организация может запретить режим «Без вопросов» и
  добавить свои хуки. Запрет с любого уровня сильнее любого разрешения.
- В запросе разрешения — вариант «в этом проекте (только у меня)».
- `/permissions`: все правила по уровням, удаление, проверка «что будет с этой
  командой» (ADR 0038).
- Режим «Авто» (ADR 0039): правки проекта и команды без высокого риска внутри
  проекта — без вопросов; сеть, установка пакетов, удаление, `git push`, пути
  вне проекта, встроенный код интерпретатора и MCP — с вопросом, причина видна
  в карточке. Доступен гостю. Сохранённый старый `auto` по-прежнему означает
  «Без вопросов».
- Песочница для команд агента (ADR 0040): «Настройки» → «Команды агента» —
  `run_shell` в одноразовом Docker-контейнере (проект в `/workspace`, корневая
  ФС только на чтение, без capabilities и сети, лимиты), команды по маскам — на
  хосте. Если Docker не запущен, команда не выполняется на хосте молча.
  По умолчанию выключено.
- OAuth для удалённых MCP-серверов (ADR 0041): статус «нужен вход» и кнопка
  «Войти» в окне «MCP» — вход в системном браузере (PKCE, регистрация
  клиента, проверка `state`), токены зашифрованы хранилищем ОС и обновляются
  сами; «Выйти» удаляет их. `"oauth": false` выключает OAuth для сервера.
- Готовые хуки для правил проекта (ADR 0035): `examples/hooks/no-push-main.mjs`
  не даёт агенту пушить в `main`, `require-docs.mjs` не принимает работу без
  CHANGELOG и ADR при изменённом коде. Репозиторий MAI подключает их в
  `.mai-code/hooks.json`.
- Навыки (ADR 0043): `load_skill` показывает файлы навыка и читает их по
  запросу (`file`); `allowed-tools` во frontmatter разрешает узкие правила на
  текущий прогон — с уведомлением, без `*` и голых `run_shell`/`write_file`.
- MCP-серверы «в этом проекте (только у меня)» — `.mai-code/mcp.local.json`,
  не попадает в git; в окне «MCP» видна область каждого сервера (ADR 0038).
- Каталоги пакетов (ADR 0042): git-репозиторий или папка с
  `mai-marketplace.json`; в `/packages` → «Каталоги» видно версии, «Установить»
  и «Обновить». Имя и версия пакета проверяются по каталогу. Только admin.

## [0.2.0] — 2026-11-20

Вехи M1–M3 и начало M4 из [бэклога выравнивания](docs/BACKLOG-NEXT.md):
режимы разрешений реально ограничивают движок, диалог как у Claude Code,
контекст и сессии, хуки и субагенты. Решения — ADR 0027–0036. Как этим
пользоваться — [руководство пользователя](docs/USER-GUIDE.md).

### При обновлении

- При первом запуске в папке приложение спросит, доверять ли ей (ADR 0028).
- `sessions.json` переносится в `sessions/` (файл на чат) и сохраняется как
  `sessions.json.migrated` (ADR 0034).
- Открытые ключи провайдеров, токены Vault и MAS в `settings.json` шифруются
  хранилищем ОС (ADR 0031). Перенос `settings.json` на другую машину или в
  другую учётную запись — ключи нужно ввести заново.
- Сохранённый режим «Авто» читается как «Без вопросов» (`bypass`).
- OpenCode и другие CLI без флагов режима на хосте запускаются только в
  «Без вопросов» или в docker-режиме (ADR 0029).

### Security

- PolicyEngine (ADR 0027): разрешение проверяется в цикле агента для любого
  инструмента. Раньше MCP-инструменты и плагины выполнялись без проверки, в
  том числе в режиме «План». MCP — `read` только при `readOnlyHint`.
- Доверие к папке проекта (ADR 0028): без доверия не загружаются плагины,
  MCP-серверы, `AGENTS.md`, память, навыки, команды, хуки и типы субагентов
  проекта, не запускаются стадии досок, «Без вопросов» понижается до «Вручную».
  Раньше открытие папки исполняло её плагины в main-процессе.
- Матрица прав IPC (ADR 0028): каждый канал помечен `any`, `admin` или `self`,
  канал вне матрицы закрыт. Гостю закрыты `runtimes:run`, `mcp:connect`,
  `infra:pushSecrets`, `repowise:install`, `repowise:distill` и другие. Роль
  `guest` не может включить «Без вопросов».
- Внешние CLI соблюдают режим разрешений; запрос больше не разбирается
  `cmd.exe` (`%VAR%`, переводы строк, кавычки) (ADR 0029).
- Плагины исполняются в отдельном процессе без доступа к памяти main, Electron
  API, окнам и переменным окружения с ключами (ADR 0030).
- Окна работают в песочнице (`sandbox: true`) с CSP без inline-скриптов и eval;
  окно досок экранирует данные `boards.json` (раньше файл мог внедрить разметку).
- Ключи провайдеров, токены Vault и MAS шифруются хранилищем ОС (`enc:v1:`);
  уровень защиты виден в «Настройках» (ADR 0031).
- `run_shell` с `cwd` больше не выходит за пределы проекта; `app:openPath`
  открывает только папки; `repowise:distill` — admin и guardrails.

### Changed

- Режимы разрешений: «Вручную», «Принимать правки», «План», «Только
  разрешённое», «Без вопросов» (бывший «Авто», с предупреждением). В «Принимать
  правки» запись в память спрашивает подтверждение.
- Запрос разрешения — карточкой в ленте: риск, причина, рекомендованный ответ
  с подсветкой и фокусом, «Да» / «Да, и не спрашивать» / «Нет» с пояснением
  для агента, клавиши 1–3; diff правки.
- Длинный чат больше не обрезается молча: сначала компакция в сводку (ADR 0032).
- Чаты хранятся файлом на сессию с индексом (ADR 0034).
- Замечание ревизора хранится с ролью `review`, замечание хука `Stop` — с ролью
  `hook`: в чате и экспорте это не реплики пользователя.
- У каждого ответа сохраняется модель и токены шага.
- `transformMessages` плагина вызывается асинхронно; буфер обмена в окнах —
  через IPC `app:clipboard`.
- Группа рантаймов с правом записи в одну папку не запускается; чат,
  самокоррекция и пишущий рантайм не правят одну папку одновременно.
- Ветки: только `dev` и `main`, в `main` — только через pull request; прямой
  push блокирует хук `scripts/hooks/pre-push` и защита ветки на GitHub
  (правило 9 в `AGENTS.md`).
- CI: проверки на `ubuntu-latest` и `windows-latest` на push и pull request в
  `dev` и `main`, включая электронные наборы и `scripts/test-windows.mjs`.
- `docs/BACKLOG.md` — источник статусов старого бэклога, `docs/ROADMAP.md`
  ссылается на него; новая работа ведётся в `docs/BACKLOG-NEXT.md`.
- `make-offline.mjs` вызывает `make-sums.mjs` вместо дописывания одной строки
  в `SHA256SUMS.txt`.

### Added

- `ask_user` — вопросы с вариантами, рекомендованный вариант первым, подсвечен

### Fixed

- Windows: кириллица в выводе `run_shell`, стадий досок, хуков и рантаймов
  превращалась в кракозябры или «?????» — консоль переводится в UTF-8,
  команда идёт во вложенном `cmd`, вывод в cp866/cp1251 перекодируется.
- Windows: процесс плагинов держал папку проекта и после смены проекта.
- «Стоп» не останавливал команду `run_shell` — процесс доживал до таймаута;
  таймаут хука не останавливал его дочерние процессы.
- MCP-инструменты уходили в `chat.completions` пустыми схемами.
- Сообщения внешнего рантайма ломали следующий запрос встроенного агента (400).
- Ошибка посреди прогона теряла выполненные шаги — история сохраняется после
  каждого шага; обрезка истории могла оставить результат инструмента без
  вызова и удаляла начало сохранённого чата.
- `edit_file` раскрывал `$&` и `$1` в новом тексте и спрашивал разрешение,
  даже если фрагмента нет.
- Смена режима посреди прогона откатывалась при сохранении сессии; запись
  сессий не была атомарной.
- Транспорт Responses превращал картинку в текст с base64; при сохранении
  провайдера терялся флаг `vision`.
- Вопрос агента в пустом чате не отрисовывался; пояснение к отказу терялось
  без события input; правка сообщения могла обрезать диалог до проверок.
- Список моделей расходился с каталогами шлюзов; миграция из `.env` брала одну
  модель; `temperature` уходила моделям GPT-5+ (400).
- GitHub Pages не публиковался (сайт не был создан, токен workflow без прав);
  защита ветки `main` включена.
- Индикатор вложений при пустом списке; битые ссылки в документации MAV и MAS.

### Removed

- Неиспользуемые экспорты `docsRoot()`, `OCR_DEFAULTS`, экспорт `KINDS`
  (найдено `repowise dead-code`).
