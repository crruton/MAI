# Harness refine

Идея взята из Harness2 (Google Research): harness — это промпт, инструменты, память,
навыки и оркестрация вокруг модели. Улучшать его нужно по наблюдаемому поведению,
а не по вкусу.

## Когда применять

- Агент стабильно ошибается на однотипных задачах.
- Приходится вручную дописывать одни и те же указания.
- Нужно сравнить два подхода на одинаковых задачах.

## Цикл

1. **Propose.** Сформулируй 2–4 правки harness: промпт, набор инструментов, лимит шагов,
   правило памяти, порядок проверок. Каждая правка должна быть независимой.
2. **Probe.** Прогони одинаковый набор задач (3–5) со старой и новой версией.
   Фиксируй: успех/провал, число шагов, число tool-call'ов, время, стоимость.
3. **Compose.** Собери новую версию из правок, которые дали улучшение без регрессий.
   Не смешивай правки, эффект которых не измерен.
4. **Record.** Сохрани версию harness как артефакт с датой, списком правок и результатами.
5. **Reflect.** Запиши урок в `memory.md`: что сработало, на каких задачах, где не сработало.

## Формат отчёта

```md
## Задача
## Гипотеза
## Правки harness
## Прогон (до / после)
| Метрика | До | После |
## Решение
## Урок
```

## Правила

- Одна правка — одна гипотеза. Иначе непонятно, что сработало.
- Не подгоняй harness под один пример: минимум 3 задачи, лучше 5.
- Если улучшения нет — зафиксируй это и откати правку.
- Не меняй модель и не обещай «стало умнее»: измеряй поведение, а не впечатление.
