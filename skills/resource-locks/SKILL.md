# Resource locks

Используй перед запуском нескольких агентов или стадий, которые могут мешать друг другу.

## Что считать общим ресурсом

- git-ветка, на которую делается push;
- тестовая или staging-среда;
- порт, база данных, очередь;
- папка с артефактами или кэшем;
- внешний аккаунт с лимитом запросов.

## Шаги

1. Составь список ресурсов, которые задача будет менять.
2. Для каждого укажи режим: `read` или `write`.
3. Проверь, не держит ли ресурс другая задача (журнал досок, handoff, сообщение в чате).
4. Если ресурс занят — не начинай запись: выбери другой ресурс или дождись освобождения.
5. Зафиксируй блокировку в `<проект>/.mai-code/locks.json`:

```json
{
  "locks": [
    { "resource": "branch:main", "mode": "write", "owner": "agent-1", "task": "A-12", "at": "ISO" }
  ]
}
```

6. Снимай блокировку сразу после завершения, а не «когда-нибудь».

## Правила

- Блокировка без владельца и задачи недействительна.
- Чтение не блокирует чтение; запись блокирует и чтение, и запись.
- Не обходи блокировку «на минутку»: это источник конфликтов и потерянных правок.
- Если процесс упал, блокировка остаётся; перед повторным запуском проверь,
  жив ли владелец, и сними устаревшую запись явно.
