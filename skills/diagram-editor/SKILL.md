# Diagram editor

Используй, когда пользователь просит изменить схему на доске «Архитектура».

## Модель

Источник истины — `architecture.model` в `<проект>/.mai-code/boards.json`.
Все представления генерируются из неё, поэтому менять нужно модель, а не Mermaid-текст.

## Порядок

1. Прочитай текущую модель и выбранное представление.
2. Определи минимальный набор изменений: контейнер, компонент, связь, участник, сущность.
3. Проверь ссылочную целостность:
   - `components[].container` существует в `containers[].id`;
   - `relations[].from/to` существуют среди компонентов или контейнеров;
   - `sequence.messages[].from/to` есть в `participants`;
   - `er.relations[].from/to` есть в `entities[].name`;
   - `deployment.links[].from/to` есть в `nodes[].id`.
4. Обнови модель целиком, не сокращая существующие разделы.
5. После сохранения проверь, что C1–C4, sequence, ER и deployment не потеряли элементы.

## Правила

- Не удаляй сущности, о которых не просили.
- Новые id — латиница, короткие, в стиле существующих (`api`, `worker`, `pg`).
- Если меняется контейнер, обнови его компоненты и связи.
- Если добавляется внешняя система — добавь её в `system.externals` и в C1.
- Если меняется API — обнови `openapi.paths`, а не только диаграмму.
- Не рисуй секреты и реальные ключи на схемах.
