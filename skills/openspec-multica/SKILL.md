# OpenSpec → Multica

Используй навык, когда задача больше одного шага или меняет поведение.

## Порядок

1. Создай `openspec/changes/<name>/`.
2. Заполни `proposal.md`:
   - проблема;
   - решение;
   - критерии приёмки;
   - что вне scope.
3. Заполни `design.md`: архитектура, альтернативы, риски.
4. Разбей работу в `tasks.md`:
   ```md
   - [ ] Добавить поле портов в форму песочницы.
   - [ ] Проверить публикацию только на 127.0.0.1.
   - [ ] Обновить docs/SANDBOXES.md.
   ```
5. Синхронизируй: `npm.cmd run multica:sync`.
6. После работы отметь `- [x]`.
7. Обнови `CHANGELOG.md` и ADR, если решение архитектурное.

## Формат задач

ASD-STE100:

- одна инструкция на предложение;
- активный залог;
- глагол в начале;
- без идиом и жаргона;
- конкретный результат.

| Плохо | Хорошо |
|---|---|
| «Разобраться с синком» | «Добавить sync OpenSpec → Multica» |
| «Починить, если падает» | «Добавить таймаут 30 с. Показать ошибку.» |

## Проверка

- `openspec validate` (если установлен CLI).
- `npm.cmd run docs:check`.
- Повторный `multica:sync` не создаёт дублей.
