# Безопасность

## Ключи и токены

В репозитории не должно быть ключей. В `.gitignore` уже исключены:

- `.env`, `.env.*` (кроме `.env.example`);
- `mai-api-key.txt`, `*.key`, `*.pem`;
- `settings.json`, `sessions.json`.

Ключ MAI хранится только локально в `%APPDATA%\mai-code\settings.json` и передаётся
в заголовке `Authorization: Bearer …`.

Если ключ всё же попал в коммит:

1. отзовите его у провайдера;
2. выпустите новый;
3. почистите историю (`git filter-repo` или BFG) — обычный `git rm` не удаляет секрет
   из прошлых коммитов.

## Что делает агент

- Читает и ищет файлы внутри папки проекта.
- Пишет и правит файлы только после подтверждения в интерфейсе.
- Запускает команды оболочки только после подтверждения, с таймаутом 180 секунд.
- Не коммитит в git и не удаляет данные без явной просьбы в промпте.

## Границы доверия

- Вывод инструментов и файлов попадает в контекст модели: файл проекта может содержать
  инструкции, которые модель воспримет как команды. Не открывайте агенту чужие каталоги.
- MCP-серверы и плагины исполняют сторонний код с правами пользователя. Подключайте только
  те, которым доверяете.
- `allowOutsideProject` снимает ограничение на пути — включайте осознанно.

## Сообщить о проблеме

Откройте issue в репозитории. Пожалуйста, без реальных ключей и токенов в тексте.
