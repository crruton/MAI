# OpenScion и локальный git

Короткий ответ: **нет, OpenScion не заменяет локальный git.** Это серверная
SCM-система для больших монорепозиториев, а MAI Code работает с обычным
локальным git-репозиторием.

## Что такое OpenScion

- Серверная система контроля версий для монорепозиториев, где клиенты — агенты
  и CI, а не люди.
- Rust, лицензия GPL-3.0.
- Changeset'ы вместо полных снапшотов, контентная адресация BLAKE3, серверный
  rebase/merge.
- Требует развёрнутого сервера и клиента `opnscn`.

## Почему не замена

| Критерий | Локальный git | OpenScion |
|---|---|---|
| Работа без сервера | да | нет |
| Привычные GitHub/GitLab | да | нет |
| Лицензия | GPL-2.0 (git) | GPL-3.0 |
| Встраивание в MIT-проект | — | несовместимо |
| Задача | повседневная разработка | огромные монорепозитории |

GPL-3.0 несовместима с MIT при встраивании кода. MAI Code может подключаться к
OpenScion только как к внешнему сервису, без копирования кода.

## Когда имеет смысл

- Монорепозиторий, где большинство клиентов — агенты и CI.
- Нужны changeset'ы и серверный rebase/merge.
- Есть команда, которая готова держать сервер OpenScion.

## Как подключить

1. Разверните сервер OpenScion по инструкции проекта.
2. Создайте репозиторий на сервере.
3. Импортируйте текущий проект:

   ```powershell
   opnscn import . <url-сервера>
   ```

4. Проверьте, что клиенты и CI умеют работать с `opnscn`.

## Что делает MAI Code

При создании песочницы с `repoHost = openscion`:

- создаётся обычный локальный git и начальный коммит;
- в `docs/OPENSCION.md` песочницы кладётся инструкция;
- remote не создаётся автоматически;
- приложение не устанавливает сервер OpenScion.

## Ограничения

- Интеграция не проверена на живом сервере.
- Нет автоматического импорта и синхронизации.
- Нет поддержки `opnscn` как CLI-рантайма.
- Решение зафиксировано в
  [ADR 0009](adr/0009-openscion-ne-zamena-git.md).
