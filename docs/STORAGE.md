# Хранилище артефактов

MAI Code хранит навыки, `AGENTS.md`, OpenSpec, ADR, диаграммы, OpenAPI и заметки как
**версионируемые артефакты**. Источник истины — локальные файлы проекта. Postgres,
pgvector, Vault и SeaweedFS — опциональный слой: без них приложение работает полностью.

## Раскладка

```
<проект>/.mai-code/
  artifacts/
    index.json              метаданные и история версий
    blobs/<sha256>          содержимое версий (content-addressed)
    files/<kind>/<slug>.*   актуальная версия для git и внешних инструментов
    exports/*.puml          экспорт PlantUML с доски архитектуры
  boards.json               задачи, ADR, стадии, проблемы, baseline
```

`index.json` — единственный «журнал». Версия не создаётся, если хеш содержимого не
изменился. Блобы дедуплицируются: одинаковая версия двух артефактов хранится один раз.
Зеркало в `files/` перезаписывается при каждом сохранении и удобно для code review.

Типы артефактов: `skill`, `agents`, `openspec`, `adr`, `diagram`, `openapi`, `note`,
`plugin`.

## Что умеет

- создать артефакт и сохранить новую версию;
- показать историю, содержимое любой версии и diff между версиями;
- восстановить старую версию как новую (история не переписывается);
- искать по имени и содержимому;
- импортировать существующие навыки, `AGENTS.md`, плагины, OpenSpec и ADR из проекта;
- экспортировать артефакт в файл и записывать обратно в привязанный файл;
- синхронизировать версии в Postgres/pgvector и SeaweedFS.

Импорт идемпотентен: повторный запуск не плодит версии, если файлы не менялись.

## Инфраструктура

```powershell
npm.cmd run infra:up      # docker compose -f infra/docker-compose.yml up -d
npm.cmd run infra:logs
npm.cmd run infra:down
```

| Сервис | Адрес | Назначение |
|---|---|---|
| Postgres 17 + pgvector | `127.0.0.1:5433` | версии, полнотекстовый и векторный поиск |
| Vault (dev) | `http://127.0.0.1:8200` | ключи провайдеров, KV v2 |
| SeaweedFS filer | `http://127.0.0.1:8888` | резервная копия блобов |
| SeaweedFS S3 | `127.0.0.1:8333` | S3-совместимый доступ |
| SeaweedFS master | `127.0.0.1:9333` | кластер |

Порт `5433` выбран, чтобы не пересекаться со стеком CNC, который занимает `5432`.

Настройки — доска **Хранилище → Инфраструктура**:

- `Postgres URL`: `postgres://mai:mai@127.0.0.1:5433/mai`
- `Vault адрес`: `http://127.0.0.1:8200`
- `Vault token`: `root` (dev-режим; в compose задаётся `MAI_VAULT_TOKEN`)
- `SeaweedFS filer URL`: `http://127.0.0.1:8888`
- модель эмбеддингов: `bge-m3`, размерность `1024` (подтверждено на шлюзе MAI)

### Postgres и pgvector

При синхронизации создаются таблицы `mai_artifacts` и `mai_artifact_versions`.
Для текущих версий считаются эмбеддинги через провайдера `infra.embeddingProvider`
(по умолчанию `mai`) и модель `bge-m3`. Если эмбеддинги недоступны, синхронизация
не падает: версии сохраняются, поиск переключается на полнотекстовый.

Векторный поиск — косинусное расстояние (`<=>`), полнотекстовый — `to_tsvector('simple')`.
Русский язык в `simple`-конфигурации не стеммится, поэтому морфология работает хуже,
чем у специализированного словаря. Это осознанный компромисс: не нужен дополнительный
словарь и миграции.

### Vault

KV v2 по пути `secret/data/mai-code`. Кнопка «Ключи → Vault» отправляет провайдеров,
«Ключи ← Vault» загружает их обратно и сохраняет в `settings.json`. Токен наружу
отдаётся как `***`; пустое поле при сохранении не стирает старый токен.

Vault в compose запущен в **dev-режиме**: данные в памяти, root-токен известен.
Для постоянного хранения нужен `vault server -config` с файловым бэкендом и нормальной
инициализацией — это не входит в текущую версию.

### SeaweedFS

Кнопка «Залить артефакты» кладёт текущие версии по пути
`/mai-code/<hash проекта>/<kind>/<slug>/<sha256>`. Это резервная копия, а не замена
локальному хранилищу: восстановление одной кнопкой пока не реализовано, есть только
`infra:download` для точечного чтения.

### Автосинхронизация

Флажок «Автосинхронизация» во вкладке «Инфраструктура» (выключен по умолчанию,
включает admin): каждая новая версия артефакта ставит проект в фоновую очередь;
через 5 с после последней правки артефакты уходят в Postgres и SeaweedFS (те, что
заданы). Ошибка — повтор через 30 с, 2 мин и 10 мин. Под флажком видно состояние,
число правок в очереди, последнюю успешную синхронизацию и ошибку; «Синхронизировать
сейчас» запускает прогон сразу. Ключи в Vault уходят только по кнопке (ADR 0087).

## Ограничения

- Автосинхронизация (ADR 0087) заливает все артефакты проекта на каждую волну
  правок; очередь в памяти — после перезапуска догонит при следующей правке.
- Нет сборки мусора (GC) для блобов: удалённый артефакт оставляет блобы на диске.
- `index.json` рассчитан на одного писателя; параллельная запись из двух окон может
  перетереть изменения. Доски сохраняют только свои секции, но общий файл один.
- Postgres хранит версии, но не является источником истины. Конфликты разрешаются
  в пользу локального файла.
- Vault dev-режим и SeaweedFS без аутентификации годятся только для локальной машины.
- Импорт OpenSpec читает `<проект>/openspec/**/*.md`; другие layout'ы не поддержаны.
- Векторный поиск использует `bge-m3`; смена модели требует пересоздания колонки
  `embedding` (размерность фиксируется при создании таблицы).
