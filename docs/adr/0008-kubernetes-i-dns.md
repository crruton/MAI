# 0008. Kubernetes и DNS как отдельный слой

- **Статус:** accepted
- **Дата:** 2026-11-04

## Контекст

Нужно развернуть сервис локально и иметь путь переезда в облако. DNS и домен
нужны и для сайта, и для Keycloak, и для Multica.

## Решение

Инфраструктура описывается отдельно от десктопного приложения:

- `infra/k8s/` — namespace, Postgres, Keycloak, Multica, ingress, PVC, secrets
  (шаблоны, без реальных значений);
- локальный запуск — k3d или kind;
- бесплатное облако — Oracle Cloud Always Free (4 OCPU / 24 ГБ ARM) с k3s;
  альтернативы: Civo (пробный период), Google GKE Autopilot (пробный кредит).
- `docs/DNS.md` — hosts для локального домена, A/CNAME для облака, TLS.

Приложение остаётся десктопным. В Kubernetes живут серверные сервисы:
Keycloak, Postgres, Multica и, при необходимости, будущий web-клиент.

## Альтернативы

| Вариант | Плюсы | Минусы |
|---|---|---|
| Docker Compose | Просто | Нет переезда в облако |
| Kubernetes | Единый манифест | Сложнее локально |
| Managed PaaS | Меньше ops | Не бесплатно, vendor lock |

## Последствия

- Локально нужен Docker и k3d/kind.
- Секреты не коммитятся: `infra/k8s/secrets.example.yaml` — шаблон.
- Домен и TLS требуют внешней настройки; в репозитории только инструкция.
- Ограничение: манифесты проверены синтаксически, не на живом кластере.
