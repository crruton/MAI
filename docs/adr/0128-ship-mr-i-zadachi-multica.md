# 0128. MAI Ship: MR и задачи Multica MAI

- **Статус:** accepted
- **Дата:** 2026-11-27
- **Контекст:** [бэклог командной работы](../BACKLOG-TEAM.md) E3.C4; ADR 0089 (статусы Multica → OpenSpec), 0112 (цель Multica), 0125 (статус MR в MAI)

## Контекст

`/ship` пишет ключ задачи в заголовок MR (`[MAI-42] …`), но задача в Multica MAI не знала о
MR: после слияния её закрывали руками или забывали. Критерий бэклога — «merge закрывает issue».

## Решение

- **Ключ задачи** — `[MAI-42]` или `MAI-42:` в начале заголовка MR (префикс `Draft:` GitLab
  пропускается), иначе — ветка `mai-42-кратко` или `ship/mai-42`. `[NO-KEY]` — MR без задачи.
  Ключ в середине заголовка не берётся: «как в MAI-3» — не связь.
- **Статус** — слитый MR → `done`, открытый → `in_review`. Закрытый без слияния MR задачу не
  меняет: это не значит, что работа отменена.
- **Только вперёд** (`backlog → todo → in_progress → in_review → done`). `done` не откатывается;
  `blocked` и `cancelled` ставит и снимает только человек. Несколько MR на задачу — побеждает
  самый дальний статус (слитый закрывает, даже если открыт ещё один).
- **Где работает** — в MAI на рабочем месте: MR проекта за 14 дней через `glab api` (вход
  пользователя, ADR 0125), задачи — из Multica цели проекта (ADR 0112), смена — `multica issue
  status <id> <status>`. Кнопка «Задачи Multica» на доске «Доставка»; автоматически при каждом
  опросе MR — если в настройках `"multica": { "mrSync": "auto" }`. IPC `ship:syncIssues`
  (developer: пишет в Multica).
- Модули: `ship/mr-issue.js` (`issueKeyFromMr`, `statusForMr`, `planIssueSync`),
  `multica.syncMrIssues`, `multica-target.issueStatusArgs`, `mr-status.collectRecentMrs`.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Джоба в GitLab CI после merge | без MAI на рабочем месте | Multica MAI не видна из CI, нужен её токен в CI | позже, когда у Multica будет стабильный API |
| Вебхук GitLab → Multica | мгновенно | у Multica нет приёмника вебхуков GitLab | — |
| Закрывать задачу и при закрытом MR | проще | теряем задачи, когда MR пересоздают | только слияние = готово |

## Последствия

- Проще: слияние MR закрывает задачу в Multica MAI, открытый MR показывает задачу на ревью.
- Сложнее: связь работает, пока кто-то из команды открыл MAI с доской «Доставка» (или нажал кнопку).
- Проверено: `test-ship-mr-issue` (19), UI-тест кнопки. Против живой Multica MAI не проверено:
  в этой сессии у агента нет доступа к её CLI.
