# 0005. Keycloak на Postgres

- **Статус:** accepted
- **Дата:** 2026-11-04

## Контекст

Keycloak в dev-режиме использовал встроенную H2. Пользователи и роли терялись
при пересоздании контейнера. Нужно хранение пользователей в Postgres и
возможность добавлять их без пересборки realm.

## Решение

`infra/keycloak/docker-compose.yml` поднимает два сервиса:

- `postgres:16-alpine` с томом `keycloak-db`;
- `keycloak:26` с `KC_DB=postgres`, `KC_DB_URL`, `KC_DB_USERNAME`,
  `KC_DB_PASSWORD` и `start --import-realm`.

Realm `mai-code` импортируется один раз. Пользователь `letun82@mail.ru`
создаётся в realm с временным паролем и ролью `admin`. Пароль хранится в
`infra/keycloak/README.md`, а не в git-истории приложения.

## Альтернативы

| Вариант | Плюсы | Минусы |
|---|---|---|
| H2 (dev) | Просто | Данные теряются |
| Postgres | Данные сохраняются | Ещё один контейнер |
| Внешний managed Postgres | Бэкапы | Нужна инфраструктура |

## Последствия

- `docker compose down` без `-v` сохраняет пользователей.
- Realm-файл — начальная конфигурация, а не источник истины после первого старта.
- Пароль первого пользователя нужно сменить при первом входе.
- Для production: TLS, внешний Postgres, бэкап и ротация секретов.
