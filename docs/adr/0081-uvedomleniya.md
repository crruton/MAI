# 0081. Уведомления на рабочем столе и в мессенджер

- **Статус:** accepted
- **Дата:** 2026-11-23
- **Контекст:** бэклог CW5.4; продолжение ADR 0050 (плановые задачи), 0075 (фоновые субагенты)

## Контекст

Агент работает долго, а пользователь переключается на другие окна. Уведомления
были только у плановых задач и фоновых субагентов, каждое своим кодом; о том,
что агент закончил, ждёт подтверждения или упал, пользователь узнавал, только
вернувшись в окно. Cowork присылает уведомления на рабочий стол, а в планах —
в мессенджер.

## Решение

`electron/lib/notify.js` — один вход для всех событий:
`createNotifier({ Notification, getSettings, isFocused, onClick, fetch })` →
`notify(kind, { title, body, sessionId })`. Виды: `done` (агент закончил),
`approval` (нужно подтверждение), `question` (агент спрашивает), `error`,
`background` (фоновый субагент), `scheduled` (плановая задача).

- **Рабочий стол** — только когда ни одно окно приложения не в фокусе. Клик
  поднимает окно и открывает чат.
- **Webhook мессенджера** — `settings.notifications.webhookUrl` (только
  `https://`): POST `{ text, content }` — понимают Slack, Mattermost, Teams
  (`text`) и Discord (`content`). Уходит только заголовок и первые строки
  ответа или причины, без файлов. Адрес хранится зашифрованным (это по сути
  токен канала), окно видит «***»; задать или сменить — только admin. Ошибка
  доставки — в журнал ошибок, без падения.
- Одно и то же (вид, заголовок, чат) не повторяется чаще раза в 10 с.
- Настройки: «Уведомления» — выключатель и виды для рабочего стола, адрес
  webhook и виды для него (по умолчанию: готово, ошибка, плановая задача),
  «Проверить уведомление» (IPC `notify:test`).
- В main: прогон чата (готово/ошибка), `makeApprover`, `makeAsker`, фоновые
  субагенты и `notifyScheduled` идут через `notify`.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Бот Telegram/Slack с двусторонней связью | Ответить с телефона | Сервер, токены бота, приём команд — это CW5.5 и N8 | Позже |
| Push на телефон через сервис | Без мессенджера | Внешний сервис и аккаунт | Webhook уже есть у мессенджеров |
| Уведомлять всегда, даже в фокусе | Проще | Шум | Только вне фокуса |

## Последствия

- Ответить на подтверждение из мессенджера нельзя — только вернуться в окно.
- Проверки: `scripts/test-notify.mjs` (настройки по умолчанию, http без s,
  выключатель, тело webhook, фокус и рабочий стол, виды для webhook, клик,
  повтор за 10 с, ошибка webhook); `test-ui` [44] — сохранение настроек;
  `smoke-scheduler` и `test-secrets-electron` — без регрессий.
