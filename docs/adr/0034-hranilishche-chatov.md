# 0034. Чаты: файл на сессию, индекс, поиск

- **Статус:** accepted
- **Дата:** 2026-11-20
- **Контекст:** бэклог A3.7, CC6.3, CC6.4, CC6.6, CC6.7

## Контекст

Все чаты лежали в одном `sessions.json`. После ADR 0027 история сохраняется
после каждого шага агента — и каждый шаг переписывал файл со всеми чатами.
Сбой записи грозил всем чатам сразу; список чатов не фильтровался по проекту,
поиска не было.

## Решение

- `electron/lib/session-store.js`: `<данные>/sessions/<id>.json` — сессия,
  `<данные>/sessions/index.json` — список (заголовок, проект, модель, даты,
  число запросов). Запись атомарная. Сохранение шага трогает только файл этой
  сессии и индекс.
- Перенос: при первом чтении `sessions.json` разбирается на файлы и
  переименовывается в `sessions.json.migrated` — данные не удаляются.
- `sessions:list({ projectDir, query })`: чаты текущей папки (по умолчанию в
  окне) или всех; поиск по заголовку и тексту сообщений с фрагментом совпадения.
- `/resume [поиск]` — найти и продолжить чат из любого проекта.
- ✎ у своего сообщения: текст — в поле ввода; при отправке диалог
  откатывается к сообщению (`checkpoints:rewind`, режим `conversation`, файлы
  не трогаются), затем уходит новый текст.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| SQLite | Запросы, индексы | Нативный модуль в Electron, сборка под платформы | Файлов достаточно |
| Оставить один файл, писать реже | Мало правок | Теряются шаги при сбое (A3.2) | Противоречит сохранению по шагам |

## Последствия

- Поиск по тексту читает файлы сессий — на тысячах чатов будет медленнее; при
  необходимости — индекс текста отдельно.
- Проверки: `scripts/test-sessions.mjs`, раздел [22] `test-ui`.
