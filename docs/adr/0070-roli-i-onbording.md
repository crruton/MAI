# 0070. Наборы по ролям и онбординг

- **Статус:** accepted
- **Дата:** 2026-11-22
- **Контекст:** бэклог CW6.1, CW6.2; продолжение ADR 0037 (пакеты), 0052 (коннекторы)

## Контекст

Новый пользователь видит пустое окно и не знает, что агент умеет в его работе.
Cowork начинает с выбора роли и сразу даёт подходящие плагины, подключения и
примеры задач. В MAI всё нужное для этого уже есть: пакеты (навыки и команды),
каталог коннекторов, поле ввода.

## Решение

**Наборы (CW6.1).** Папка `roles/` в приложении (попадает в сборку):
пакеты `role-developer`, `role-analyst`, `role-lawyer`, `role-sales`,
`role-finance`. В `mai-package.json` — поле `role`: `id`, `title`, `icon`,
`summary`, `connectors` (id из каталога ADR 0052), `examples` (2–5 задач).
Содержимое — только Markdown: навык и команда роли (например, «Сверка» и
`/budget` у финансов, «Проверка договора» и `/compare` у юристов).

`electron/lib/roles.js`:
- `listRoles(rolesDir)` — роли с проверенным манифестом, по фиксированному порядку;
- `installRole({ id, rolesDir, dataDir })` — копия в `<данные>/packages/<имя>`
  через readdir/readFile (папка внутри asar, `fs.cpSync` её не читает), во
  временную папку и затем переименованием — повторная установка заменяет набор
  целиком. Копируются только `commands`, `skills`, `agents`, манифест и
  README: `plugins`, `hooks.json`, `mcp.json` в наборе роли не ставятся, даже
  если окажутся в папке.

IPC: `roles:list` (любая роль; роли, отметка «установлен», состояние
онбординга), `roles:install(id)` (только admin: ставит, включает пакет,
запоминает роль, пишет в аудит).

**Онбординг (CW6.2).** Мастер из трёх шагов (`openOnboarding` в renderer):
1. карточки ролей → установка набора;
2. что установлено (навыки, команды) и подходящие коннекторы — кнопка
   открывает каталог коннекторов, отфильтрованный по роли;
3. примеры задач — выбранный пример попадает в поле ввода.

Открывается сам при первом запуске: admin, ещё нет чатов, мастер не пройден
(`settings.onboarding.done`). Закрытие на любом шаге (и «Пропустить»)
запоминает «пройден» — мастер больше не навязывается. Вернуться — `/onboarding`.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Наборы в каталоге на git (ADR 0042) | Обновляются без релиза | Первый запуск без сети не работает | Встроенные надёжнее; каталог остаётся для расширения |
| Роль как режим промпта | Без пакетов | Нельзя посмотреть, выключить, дополнить | Пакет — уже знакомая единица |
| Ставить коннекторы сразу | Меньше шагов | Нужен вход в каждый сервис, не всем нужен | Предлагаем, а не ставим |

## Последствия

- Наборы обновляются с приложением; установленная версия обновится при
  повторном выборе роли (`/onboarding`).
- Гость мастер не видит: установка и настройки — права admin.
- Проверки: `scripts/test-roles.mjs` (пять ролей, frontmatter навыков и команд,
  нет исполняемого, установка, видимость команды, замена при повторе,
  отбрасывание plugins/hooks/mcp, кривой манифест); `test-ui` [41] — карточки,
  установка, коннекторы роли, «пройден» и роль, пример в поле ввода.
