# 0127. PlantUML (C4-PlantUML) вместо Mermaid на досках

- **Статус:** accepted
- **Дата:** 2026-11-27
- **Контекст:** решение владельца («mermaid точно нужно заменить на plantuml»); подход — как в arcspace команды

## Контекст

Доска «Архитектура» рисовала C1–C4, sequence, ER и deployment через Mermaid в окне, а PlantUML
только генерировала и отдавала файлом. Две нотации одной модели расходились, Mermaid не знает
C4-нотацию, экспорт PNG шёл через растеризацию SVG в скрытом окне. Пакет `mermaid` с зависимостями —
115 пакетов (~170 МБ в `node_modules`), он раздувал приложение и образ MAI Ship (ADR 0126). Архитекторы
команды (arcspace) работают в PlantUML с C4-PlantUML.

## Решение

- **Одна нотация — PlantUML.** Генераторы Mermaid удалены. C1 — `C4_Context`, C2 — `C4_Container`
  (`ContainerDb` / `ContainerQueue` по технологии), C3 — `C4_Component`, deployment —
  `C4_Deployment` из встроенной библиотеки PlantUML (`!include <C4/...>`); C4 — диаграмма классов,
  sequence и ER — родные диаграммы PlantUML. Связи компонентов на C2 поднимаются до контейнеров.
- **Рендер — в main** (`electron/lib/plantuml.js`), как в arcspace: локальная Java +
  `plantuml.jar`, `-pipe` (текст в stdin, SVG или PNG из stdout, без временных файлов), таймаут
  30 с, кэш последних 128 схем и слияние одинаковых запросов (каждый вызов — запуск JVM, ~1 с).
- **Где искать.** Java — `plantuml.java` в настройках, `JAVA_HOME`, `PATH`, типичные папки Windows
  (JRE из Archi, Adoptium). Jar — `plantuml.jar` в настройках, `PLANTUML_JAR`,
  `<данные MAI>/plantuml/*.jar` (самая новая версия). Jar в репозиторий не кладётся (~30 МБ).
- **Без Java** — сервер PlantUML команды (`plantuml.server`, self-hosted `plantuml-server`). Публичный
  сервер по умолчанию не используется: схема архитектуры ушла бы наружу. Ничего нет — доска
  показывает исходник и подсказку, как настроить.
- **Безопасность.** `PLANTUML_SECURITY_PROFILE=SANDBOX`: `!include` файлов и адресов запрещён,
  встроенная библиотека доступна (модель может прийти из чужого репозитория). SVG перед вставкой в
  окно очищается от скриптов, обработчиков, `javascript:` и `foreignObject`.
- **Экспорт SVG и PNG** рисует main из PlantUML — без растеризации окна. JSON представления хранит
  `puml` и модель. Агент схем и калибратор получают PlantUML.
- IPC `boards:renderDiagram` и `boards:plantumlStatus` (any). Пакет `mermaid` удалён из зависимостей.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Оставить Mermaid, PlantUML — экспорт | без Java | две нотации, нет C4, +170 МБ | решение владельца |
| Только сервер PlantUML | без Java на машине | нужен сервер; без него схем нет | оставлен запасным вариантом |
| PlantUML в WebAssembly / CheerpJ в окне | без Java | десятки МБ JS, медленный старт, не проверено | Java уже есть у архитекторов (Archi) |
| Публичный plantuml.com | ничего ставить не надо | архитектура уходит наружу | только явный адрес своего сервера |

## Последствия

- Проще: одна нотация, C4 как у архитекторов команды, экспорт PNG без окна, приложение и образ легче.
- Сложнее: для схем нужна Java и `plantuml.jar` (или сервер команды). Первая отрисовка ~1 с.
- Хеши представлений теперь считаются от PlantUML: после обновления baseline архитектуры один раз
  покажет расхождение по всем представлениям — зафиксируйте baseline заново.
- Проверено: `test-plantuml` (16 без Java, 24 с Java и jar: все 7 представлений рисуются, `!include`
  файла заблокирован), UI-тест схемы, эталон кодирования для сервера из документации PlantUML.
  Сервер PlantUML вживую не проверен.
