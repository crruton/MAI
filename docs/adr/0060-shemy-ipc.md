# 0060. Проверка данных IPC

- **Статус:** accepted
- **Дата:** 2026-11-21
- **Контекст:** бэклог Q7; продолжение ADR 0028 (матрица прав IPC)

## Контекст

Матрица прав (ADR 0028) решает, кому можно вызвать канал, но не что в нём
пришло. Обработчики доверяли форме данных: `{ ...payload }` с ключом
`__proto__`, число вместо пути, массив вместо объекта настроек доходили до
кода, который пишет файлы и меняет права.

## Решение

`electron/lib/ipc-schemas.js`, проверка в `guardIpc` до обработчика и до
проверки роли:

- **Для всех 191 канала** — общая проверка: глубина ≤ 12, строка ≤ 10 МБ,
  массив ≤ 50 000, всего ≤ 50 МБ, циклы, ключи `__proto__`, `constructor`,
  `prototype` — отказ.
- **Типы аргументов** для каналов, которые меняют права, файлы и настройки
  или запускают код: 65 из 73 каналов admin/self (остальные без аргументов) и
  ключевые any-каналы (`chat:start`, `chat:approval`, `results:*`,
  `app:open*`, `checkpoints:*` …). Тип — `string | number | boolean | object
  | array | any`, «?» — необязательный; лишние поля разрешены.
- Нарушение — `{ ok: false, invalid: true, error: "Неверные данные для
  канал: аргумент 1.поле: ожидался string, пришло number" }`, обработчик не
  вызывается.
- Тест сверяет схемы с вызовами в `preload.cjs`: обязательное поле схемы,
  которого нет в вызове, — провал.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| zod / JSON Schema | Мощно, типы для TS | Зависимость; проект на JS | Свой валидатор на 150 строк |
| Проверки в каждом обработчике | Точно по месту | 191 место, легко забыть | Одна точка в `guardIpc` |

## Последствия

- Новый канал без схемы получает только общую проверку; для каналов с
  правами схема ожидается — подсказка в тесте (число каналов со схемой).
- Проверки: `scripts/test-ipc-schemas.mjs` (16), `test-ipc-permissions`
  (неверный тип и `__proto__` через `guardIpc`).
