# 0024. Версии памяти в хранилище артефактов

- **Статус:** accepted
- **Дата:** 2026-11-15
- **Контекст:** бэклог №4 «версии памяти и откат»; продолжение ADR 0016
  (вложения через файлы проекта) и хранилища артефактов

## Контекст

Память проекта — обычный Markdown-файл `<проект>/.mai-code/memory.md`, глобальная
память — `%APPDATA%\mai-code\memory.md`. Оба файла подмешиваются в системный
промпт, поэтому ошибка в них меняет поведение агента во всех следующих запросах.

Панель «Память» перезаписывала файл целиком. Отсюда три проблемы:

1. Случайная правка необратима: предыдущий текст нигде не сохранялся.
2. Правку агента нельзя отличить от правки человека: обе выглядят как новый файл.
3. `git` проекта помогает только для проектной памяти. Глобальная память лежит
   вне репозитория и не версионируется вовсе.

Хранилище артефактов (`electron/lib/artifacts.js`) уже умеет версии, blobs по
SHA-256, историю и откат. Оно используется для навыков, `AGENTS.md`, OpenSpec,
ADR и плагинов.

## Решение

Хранить версии памяти в существующем хранилище артефактов, добавив тип `memory`.

| Что | Значение |
|---|---|
| Тип артефакта | `memory` (добавлен в `KINDS`) |
| Идентификатор проектной памяти | `memory:project` |
| Идентификатор глобальной памяти | `memory:global` |
| Файл остаётся | `<проект>/.mai-code/memory.md`, `%APPDATA%\mai-code\memory.md` |
| Сравнение версий | SHA-256 содержимого |

Файл памяти остаётся источником истины для промпта: агент и человек читают
обычный Markdown. Хранилище — вторичное, оно хранит историю.

Новый модуль `electron/lib/memory.js` связывает файл и артефакт:

- `readMemoryState(projectDir)` — оба файла плюс история версий каждого уровня;
- `saveMemory(projectDir, { scope, content, note })` — пишет файл и версию;
- `memoryVersion(projectDir, scope, version)` — текст версии без записи;
- `restoreMemory(projectDir, scope, version)` — откат как новая версия;
- `saveMemoryFile(projectDir, file, content)` — совместимость со старым каналом.

Повторное сохранение того же текста версию не создаёт: `writeArtifact` сравнивает
хеш и возвращает `changed: false`. Откат не удаляет историю, а добавляет версию с
пометкой «восстановлена версия N», поэтому откат обратим.

IPC-каналы: `memory:read`, `memory:write`, `memory:save`, `memory:version`,
`memory:restore`. Запись и откат проверяют `requireAdmin()` в main-процессе.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Только `git` проекта | нет нового кода | глобальная память вне репозитория; нет отката из интерфейса | не решает проблему 3 |
| Отдельная папка `.mai-code/memory-history/` | просто | второй механизм версий рядом с существующим | дублирование `artifacts.js` |
| Postgres/SeaweedFS | общая история для команды | требует инфраструктуры, приложение должно работать офлайн | нарушает офлайн-режим |
| Хранилище артефактов, тип `memory` | один механизм, офлайн, откат уже есть | история растёт вместе с `.mai-code` | выбран |

## Последствия

- Проще: откат правки памяти из интерфейса; история видна рядом с полем ввода;
  один механизм версий для навыков, `AGENTS.md` и памяти.
- Сложнее: `.mai-code/artifacts/` растёт; при больших файлах памяти blobs
  занимают место. Ограничение размера памяти (6000/12000 символов) сдерживает рост.
- Проверено: `scripts/smoke-electron.mjs`, блок `[7]` — 9 проверок (создание
  версии, отсутствие версии при повторе, чтение версии, откат, история, уровень
  по пути). Прогон: 40 OK, 0 FAIL.
- Не проверено: поведение при одновременной правке файла человеком и агентом.
  Гонок нет только потому, что запись идёт из одного main-процесса.
- Риск: правка файла вручную (редактор, `git checkout`) версию не создаёт.
  Снижение: следующее сохранение в панели фиксирует расхождение как новую версию.
