# 0022. Тёмная полоса заголовка вместо системной

- **Статус:** accepted
- **Дата:** 2026-11-13
- **Контекст:** жалоба «светлая полоса окна спорит с тёмным интерфейсом»

## Контекст

MAI Code — тёмное приложение: фон `#0f1117`, текст `#e8eaf2`. Windows рисует
системную полосу заголовка по оформлению системы. На проверочной машине
системное оформление светлое, поэтому над тёмным интерфейсом видна светлая
полоса с кнопками «свернуть/развернуть/закрыть». Выглядит как чужая рамка.

Ограничения:

1. Кнопки окна нужны. Свои кнопки рисовать не хотим: тогда надо повторять
   поведение Windows (прилипание к краю, двойной клик, меню по правой кнопке,
   сочетания клавиш, масштабирование при высоком DPI).
2. Перетаскивание окна за верхнюю панель должно работать. Без него окно
   двигается только за узкую системную рамку.
3. Панель инструментов уже занимает верхнюю строку. Отдельная полоса высотой
   36 px отняла бы место у сообщений.

## Решение

Полосу заголовка рисует Chromium, кнопки окна — Windows поверх страницы.

1. `titleBarStyle: 'hidden'` убирает системную полосу, `titleBarOverlay`
   задаёт её цвет (`#0f1117`), цвет символов (`#e8eaf2`) и высоту 36 px.
   Настройка живёт в `titleBarOptions()` в `electron/main.js` и применяется к
   главному окну и к окнам досок.
2. Перетаскивание — drag-регионы в CSS: `-webkit-app-region: drag` на
   `.topbar` и `.board-topbar`, `no-drag` на кнопках, списках и полях внутри
   них. Иначе клик по кнопке начал бы двигать окно.
3. Место под кнопки окна резервируется через `env(titlebar-area-width)` и
   `env(titlebar-area-x)`: правый отступ панели считается от фактической
   ширины области кнопок. Значения по умолчанию (140 px) работают, если
   переменные не поддержаны.
4. macOS получает `hiddenInset`: там кнопки слева, а `titleBarOverlay` не
   поддерживается.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Оставить системную полосу | нет кода | светлая полоса на тёмном окне | это и есть проблема |
| `frame: false` и свои кнопки | полный контроль | повторять поведение Windows, ломается при DPI и прилипании | дорого и хрупко |
| Тёмное оформление Windows целиком | нет кода | меняет систему пользователя | приложение не должно менять систему |
| `titleBarOverlay` без drag-регионов | меньше CSS | окно не двигается за панель | неприемлемо |
| Отдельная полоса 36 px | просто | минус 36 px у сообщений | панель уже есть |

## Последствия

- Проще: окно выглядит цельным, кнопки окна остаются нативные.
- Сложнее: drag-регионы надо поддерживать. Новый элемент в верхней панели
  без `no-drag` начнёт двигать окно вместо нажатия.
- Сложнее: правый отступ панели зависит от `env(titlebar-area-*)`. При
  изменении высоты полосы в `titleBarOptions()` надо менять и CSS.
- Риск: на Linux `titleBarOverlay` не поддержан, окно останется без кнопок.
  Снижение: Linux не целевая платформа, сборка только под Windows.
- Проверить: перетаскивание за панель, двойной клик по панели
  (развернуть/восстановить), отсутствие наложения кнопок окна на кнопки
  панели при ширине 980 px и при масштабе 150 %.
- Не проверено: macOS и Linux.
