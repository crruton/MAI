# 0121. MAI Ship: журнал решений в MR и согласие approver ↔ человек

- **Статус:** accepted
- **Дата:** 2026-11-27
- **Контекст:** [бэклог командной работы](../BACKLOG-TEAM.md) E3.F6, E3.G2, E3.B6; ADR 0109, 0119

## Контекст

Пилот MAI Ship начинается в `mode: observe`. Переводить классы в `enforce` можно, только когда
решения approver'а совпадают с решениями людей (ADR 0109: согласие ≥ 95%). Мерить было нечем:
решения жили только в тексте комментариев.

## Решение

- **Журнал — сами MR.** В комментарии approver'а — запись
  `<!-- mai-ship:decision {"v":1,"project","iid","sha","decision","action","rule","mode","at"} -->`.
  Отдельного хранилища нет: история решений там же, где история MR. Для артефакта CI — тот же
  JSON строкой в `ship-journal.jsonl` (`approve --journal`).
- **Исход человека по тому же SHA:** влит — «approve»; влит после новых коммитов, закрыт без
  слияния или в открытом MR новые коммиты — «не approve»; открыт без новых коммитов — не решён.
- **Согласие по правилу:** доля совпадений; отдельно «approve без слияния» (опасная ошибка) и
  «лишний вызов человека» (безопасная).
- **Кандидаты в enforce:** правило, где approver говорил approve, не меньше 20 решённых MR,
  согласие ≥ 95% и ни одного approve без слияния. Перевод — отдельным MR с апрувом человека.
- **Команда:** `node scripts/mai-ship.mjs report [--days 30] [--json]`; джоба `ship:report` по
  расписанию (`MAI_SHIP_REPORT=true`).
- **Шаблоны политик (E3.B6)** — навык каталога `ship-setup`: docs, library, service, infra и
  `ship.yaml`; все стартуют в observe и проверяются тестом.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Журнал в БД или OTel | быстрые запросы | ещё один сервис и хранение | MR уже хранят всё нужное |
| Только JSONL-артефакт | просто | артефакты истекают, разбросаны по pipeline | артефакт — копия, источник — MR |
| Исход по апруву человека, а не по слиянию | точнее на Premium | на Free апрув необязателен | слияние того же SHA есть везде |

## Последствия

- Проще: решение о переходе в enforce — по числу, а не по ощущению.
- Сложнее: отчёт читает комментарии каждого MR за период — медленно на больших проектах
  (сотни запросов); период по умолчанию 30 дней.
- Revert после слияния пока не учитывается (метрика E3.G1).
- Проверено тестами (`test-ship-report`, 18; `test-ship-templates`, 24); на живом GitLab — в E3.H0.
