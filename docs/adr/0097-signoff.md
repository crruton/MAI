# 0097. /signoff — статус коммита «тесты проходят у меня»

- **Статус:** accepted
- **Дата:** 2026-11-23
- **Контекст:** бэклог N1, источник — [basecamp/gh-signoff](https://github.com/basecamp/gh-signoff); решение гриллинга «только статусы»

## Контекст

Маленьким командам и одиночкам облачный CI часто не нужен или медленный: тесты
и так гоняются локально. gh-signoff превращает это в проверяемый факт —
статус коммита в GitHub, который видно в PR и который можно требовать
правилом ветки. В MAI Code тесты агент запускает, но следа в GitHub не было.

## Решение

- `/signoff [контекст]` — HEAD проверяется (git-репозиторий, удалённый — GitHub,
  коммит есть в удалённой ветке, нет незакоммиченных правок отслеживаемых
  файлов), затем тесты проекта: `signoff.testCommand` или `npm test`, если в
  `package.json` есть `scripts.test` (заглушка `npm init` не считается).
  Прошли → статус `success` с контекстом `signoff` или `signoff/<контекст>` и
  описанием «Тесты прошли локально: npm test (42 с)». Упали → статус не
  ставится, окно показывает конец вывода.
- `/signoff fail [контекст]` — статус `failure` без тестов («отклонено вручную»).
- Статус ставит `gh api POST repos/{owner}/{repo}/statuses/{sha}` — нужен
  GitHub CLI с входом. Ссылка Details — шаблон `signoff.detailsUrl`
  (`{sha}`, `{owner}`, `{repo}`, `{context}`, только http/https).
- Тесты — в оболочке из настроек (ADR 0096), `CI=1`, таймаут
  `signoff.timeoutMin` (20 мин), остановка всего дерева процессов.
- IPC `signoff:run` (admin), запись в журнале аудита.
- Правила ветки (required status) MAI не меняет — это решение владельца
  репозитория (гриллинг).

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Через агента (промпт «прогони тесты и поставь статус») | Гибко | Недетерминированно, модель может «поставить» без тестов | Действие в main |
| Ставить и ruleset ветки | Один шаг до «обязательно» | Меняет настройки чужого репозитория | Только статусы |
| Проверять, что рабочая копия совсем чистая (и неотслеживаемые) | Строже | Мешают артефакты сборки | Только отслеживаемые файлы |

## Последствия

- Статус подтверждает тесты на машине автора, а не в изолированной среде — это
  договорённость команды, как у gh-signoff.
- Проверки: `test-signoff` — разбор, команда тестов, настоящий git-репозиторий:
  нет remote, не запушен, правки, упавшие тесты, успех с контекстом и Details,
  fail, отказ GitHub, не репозиторий; `test-ui` [56] — окно с выводом тестов и
  `/signoff fail lint`.
