# 0115. Наборы навыков каталога по ролям

- **Статус:** accepted
- **Дата:** 2026-11-26
- **Контекст:** [бэклог командной работы](../BACKLOG-TEAM.md) E1.7, наборы ролей и онбординг (ADR 0070), каталог (ADR 0111)

## Контекст

В каталоге 27 навыков. Новому участнику не нужны все: аналитику — PRD, PBC и OpenSpec,
разработчику — ревью, TDD и публикация MR. Наборы ролей MAI (ADR 0070) лежат в папке
`roles/` приложения и обновляются только с приложением, а навыки команды живут в каталоге.

## Решение

- **Поле `roles`** в `mai-marketplace.json`: `{ "<роль>": ["навык", …] }`. Роли каталога:
  developer, analyst, pm, qa, lead. Окно пакетов поле не использует (ADR 0042 читает только
  `packages`), старые версии MAI его пропускают.
- **Проверка каталога:** имя роли — латиница, список непустой, каждый навык есть в каталоге,
  без повторов.
- **Мастер первого запуска.** Выбор роли ставит набор роли из `roles/` (как раньше) и навыки
  этой роли из каталога команды: подключённого в `/packages`, у которого есть `roles`, или из
  корня MAI при запуске из исходников. Уже стоящий навык той же версии пропускается, более
  старый обновляется. Роль, которой нет в каталоге (например, lawyer), навыков не получает.
  Установка пишется в журнал решений, ошибки показываются уведомлением.
- **Скрипты:** `--role <роль>` у `npm.cmd run skills:export` и `npm.cmd run multica:skills`;
  с именами навыков — объединение. `--prune` с ролью не удаляет ничего.
- **Модуль** `electron/lib/catalog-roles.js` без Electron.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Пакет-набор на роль (зависимости между пакетами) | средствами ADR 0037 | у пакетов нет зависимостей; дублирование навыков в нескольких пакетах | одна копия навыка, роль — список имён |
| Роли в `roles/` приложения | уже есть онбординг | обновляются только с релизом MAI, команда не управляет | роли каталога — у команды |
| Отдельный файл `catalog/roles.json` | индекс не меняется | второй источник, проверка в двух местах | одно поле в индексе |

## Последствия

- Проще: «я аналитик» — один выбор, и в MAI, Claude Code или Multica приходят нужные навыки.
- Сложнее: при переименовании навыка нужно поправить роли. Проверка каталога ловит
  ссылку на несуществующий навык.
- Не проверено: установка навыков роли из каталога, подключённого по git-адресу; проверены
  локальный каталог и логика выбора каталога.
