# 0011. Guardrails встроенного агента

- **Статус:** accepted; guardrails — первый шаг PolicyEngine (ADR 0027), хуки не могут их обойти (ADR 0035)
- **Дата:** 2026-11-06

## Контекст

Встроенный агент выполняет shell-команды и меняет файлы с правами пользователя.
Одна разрушительная команда (`rm -rf /`, `del /f /s /q C:\`, pipe-to-shell) или
чтение `.env` может привести к потере данных или утечке секретов. Docker-песочница
закрывает процессы и сеть, но папка проекта остаётся смонтированной, а внешние
рантаймы вообще не проходят проверки приложения.

## Решение

Добавить слой guardrails в main-процессе:

- статический список разрушительных команд (Unix и Windows/PowerShell);
- защита секретных файлов (`.env`, ключи, `.ssh`, `.npmrc`, `.aws/credentials`,
  `.docker/config.json`);
- лимит длины команды;
- пользовательские регулярные запреты;
- маскирование токенов перед записью в журнал и телеметрию.

Проверка выполняется до подтверждения пользователем и до запуска. Guardrails
применяются к shell, файловым инструментам и стадиям деплоя.

Guardrails не объявляются песочницей и не применяются к внешним рантаймам.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Только подтверждение пользователем | Просто | Пользователь устаёт и подтверждает всё подряд | Нет защиты от ошибки |
| Только Docker | Сильная изоляция | Не покрывает host-рантаймы и смонтированную папку | Недостаточно |
| Guardrails + Docker | Два уровня | Нужно поддерживать список правил | Выбран |

## Последствия

- Типовые разрушительные команды блокируются без диалога.
- Список правил неполон: обход возможен, это не антивирус.
- Секреты по умолчанию недоступны агенту; `allowSecrets` снимает запрет.
- Нужно документировать разницу между guardrails и песочницей.
