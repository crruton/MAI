# 0020. Сервис озвучки MAV и подбор голоса вместо клонирования

- **Статус:** accepted
- **Дата:** 2026-11-08
- **Контекст:** запрос на сервис озвучки и клонирования голоса по образцу
  VoiceStudio, размещаемый в `crruton/MAV`

## Контекст

Требовался сервис озвучки и клонирования голоса на моделях, доступных по
ключу MAI. Проверка шлюза `api-ai.mai.ru` дала следующие факты.

| Проверка | Результат |
|---|---|
| Аудио-модели в `/models` | `silero-tts`, `silero-tts-accented` |
| Голоса `silero-tts` | `aidar`, `baya`, `kseniya`, `eugene`, `xenia` |
| Голос вне списка | HTTP 400 |
| Параметр референса или эмбеддинга голоса | в API отсутствует |
| `qwen3-tts` | в `/models` есть, для ключа недоступна (400) |
| Текст длиннее ~900 символов | HTTP 500 |
| Латиница | отбрасывается |
| Распознавание речи | `whisper-large-v3`, `gigaam-ru`, `stt-diarize-*` работают |
| GPU на машине | отсутствует (`nvidia-smi` не найден) |
| Docker | 29.9.3, 2 CPU, 3 ГБ памяти |

Вывод: **клонирование голоса на моделях MAI невозможно**. Шлюз не принимает
референсную запись и не отдаёт эмбеддинги. Локальное клонирование (XTTS,
F5-TTS) требует GPU, которого на машине нет.

## Решение

Создан самостоятельный сервис `services/mav` без внешних зависимостей.
Он делает четыре вещи: синтез речи, озвучку книг по главам, дубляж и
**подбор голоса** по референсу.

Подбор голоса — это измерение F0 и темпа референсной записи и выбор
ближайшего из пяти доступных голосов. Функция названа подбором, а не
клонированием, в интерфейсе, API и документации. Поле `cloning: false`
возвращается в `/api/health`, чтобы клиент не строил ложных ожиданий.

Эталонные значения F0 получены замером на реальном синтезе, а не из
документации: документации по F0 у Silero нет. Замер повторяем скриптом
`test/measure-voices.mjs`.

Движки вынесены за интерфейс `synthesize()`. Движок `mai` работает по сети,
движок `piper` — локальный офлайн. Это оставляет путь к настоящему
клонированию без переделки сервиса: достаточно добавить движок с моделью
клонирования.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Клонирование на моделях MAI | соответствует исходному запросу | API не принимает референс, 400 | технически невозможно |
| Локальный XTTS/F5-TTS | настоящее клонирование | нужен GPU, на машине его нет | не работает на текущем железе |
| Подбор голоса из пяти | работает на CPU, без GPU | это не клон | выбран как честный компромисс |
| Внешний сервис клонирования | полная функция | чужие данные, зависимость, оплата | противоречит работе по своему ключу |
| Electron-приложение вместо сервиса | единый интерфейс с MAI Code | тяжелее, не переиспользуется | сервис нужен и вне приложения |

## Последствия

- Проще: сервис запускается одной командой, зависимостей нет, работает на CPU.
- Проще: движки за интерфейсом, добавление локального клонирования не ломает API.
- Сложнее: ожидания пользователей. Слово «клонирование» в запросе не
  выполнено, и это надо повторять в интерфейсе и документации.
- Проверить: локальный движок Piper на машине с моделями `ru_RU-*`.
- Проверить: подгонку длительности сегментов при дубляже (нужен ffmpeg).
- Риск: эталоны F0 устареют при обновлении модели. Снижение — скрипт
  пересъёмки и живой тест подбора голоса.
- Риск: длинный текст тратит квоту шлюза. Снижение — нарезка по 800 символов
  и предупреждение в интерфейсе.
