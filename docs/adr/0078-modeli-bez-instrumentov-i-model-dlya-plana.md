# 0078. Модели без tool calling и отдельная модель для «Плана»

- **Статус:** accepted
- **Дата:** 2026-11-23
- **Контекст:** бэклог CC13.4, CC13.5; продолжение ADR 0057 (запасная модель), 0058 (возможности модели)

## Контекст

Модель с флагом `tools: false` (ADR 0058) могла только отвечать текстом, а
шлюз, который отвергал поле `tools`, ронял ход ошибкой. Многие локальные и
открытые модели вызывать функции в формате OpenAI не умеют, но следуют
текстовому протоколу. Отдельно: в Claude Code есть режим «одна модель
планирует, другая выполняет» (opusplan) — дорогая модель думает над планом,
дешёвая и быстрая делает работу.

## Решение

**Текстовый протокол (CC13.4)** — `electron/lib/text-tools.js`:
- `textToolsPrompt(schemas)` — инструменты (имя, описание, JSON Schema) и
  правило: вызов — блок `<tool_call>{"name": …, "arguments": {…}}</tool_call>`,
  после блоков ждать результата;
- `parseTextToolCalls(content)` — вызовы из ответа (в т.ч. внутри ```json,
  синонимы `tool`/`args`), текст вне блоков, нераспознанное — в `errors`
  (уведомлением);
- `toTextProtocol(messages)` — история для такой модели: вызовы ассистента —
  блоками в тексте, результаты — сообщением пользователя `<tool_result>`
  (подряд идущие — одним);
- `isToolsUnsupported(err)` — отказ шлюза «does not support tools» и похожие.

В `runAgent`: при `caps.tools === false` (или после такого отказа — тот же
шаг повторяется без поля `tools`, с уведомлением) запрос идёт без `tools`, с
протоколом в системном промпте; разобранные вызовы становятся обычными
`tool_calls`. История сессии не меняется: лента, откат, политика, хуки и смена
модели работают одинаково. Выключить — `settings.textToolProtocol: false`
(тогда, как раньше, только текст).

**Модель для «Плана» (CC13.5)** — `settings.planModel` (`провайдер/модель`,
«Настройки» → «Модель для «Плана»»). main передаёт `planner` в `runAgent`;
на каждой итерации в режиме «План» запросы уходят модели планирования, после
выхода из плана (режим сменился) — основной. Переключения видны уведомлениями
(«План составляет …», «План утверждён — выполняет …»), у сообщений — своя
модель. Запасная модель (ADR 0057) важнее: после перехода на неё планировщик
не включается.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Пометка «без инструментов» и только текст | Просто | Агент бесполезен для работы | Оставлено как выключатель |
| Протокол в формате ReAct (Thought/Action) | Знаком моделям | Хрупкий разбор свободного текста | JSON в теге разбирается надёжно |
| Модель плана — отдельным субагентом | Изоляция | Потеря контекста между планом и работой | Тот же диалог, другая модель |

## Последствия

- В ленте во время ответа модели без инструментов на миг видны блоки
  `<tool_call>` — после хода текст очищается и показывается карточка вызова.
- Модели, плохо следующие инструкциям, могут не соблюдать протокол —
  нераспознанное сообщается уведомлением.
- Проверки: `scripts/test-text-tools.mjs` (отказы шлюза, разбор, синонимы и
  ошибки, история без роли tool, промпт); `test-agent-loop` [32] — модель с
  `tools: false` вызывает `read_file` текстом, история и второй запрос; отказ
  шлюза → протокол с уведомлением; протокол выключен — только текст; [33] — в
  «Плане» модель планирования, после — основная, уведомления; `test-ui` [44] —
  поле настроек.
