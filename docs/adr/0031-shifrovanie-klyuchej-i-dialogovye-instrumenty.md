# 0031. Шифрование ключей и диалоговые инструменты ask_user, exit_plan

- **Статус:** accepted
- **Дата:** 2026-11-19
- **Контекст:** бэклог CC13.7, CC1.7, CC1.8

## Контекст

- Ключи провайдеров, токены Vault и MAS лежали в `settings.json` открытым
  текстом. После выноса плагинов в отдельный процесс (ADR 0030) это стало
  главным путём утечки: плагин читает файлы с правами пользователя.
- Агент мог спросить пользователя только текстом; ответ — свободный ввод,
  рекомендованный вариант не выделялся. Режим «План» заканчивался просьбой
  «переключите режим», переключение — вручную.

## Решение

**Ключи** (`electron/lib/secrets.js`). Секреты по путям `providers.*.apiKey`,
`infra.vaultToken`, `mas.token` пишутся как `enc:v1:<base64>`, шифр —
Electron `safeStorage` (DPAPI, Keychain, libsecret/kwallet). В памяти main —
открытые значения, в окно — `***`. Старые открытые ключи шифруются при
старте (`migrateSecrets`). Если хранилище ОС недоступно, ключи остаются
открытыми и это видно в «Настройках» (`secretsProtection: none`); слабый
шифр Linux без keyring (`basic_text`) приложение не включает. Если ключ не
расшифровался (сменился пользователь ОС), при сохранении на диске остаётся
прежнее зашифрованное значение, а не пустая строка.

**Диалог** (`electron/lib/tools/interactive.js`):

- `ask_user` — 1–4 вопроса по 2–4 варианта; один вариант с
  `recommended: true` ставится первым, подсвечивается, выбран заранее и
  отправляется по Enter; есть поле «Другое…» и мультивыбор;
- `exit_plan` — только в режиме «План»: план, до 4 альтернатив с риском,
  номер рекомендованной. Карточка предлагает «Выполнить: принимать правки»
  (рекомендуется), «Выполнить: вручную», «Без вопросов» (admin, доверенная
  папка) и «Доработать план». Одобрение меняет режим сессии в main, и
  следующая итерация агента получает инструменты записи.

Оба инструмента — класс `read`: сами ничего не меняют. Карточки — в ленте, а
не модальным окном. В режиме «Только разрешённое» `ask_user` скрыт.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Ключи в отдельном файле с правами 600 | Просто | Плагин работает от того же пользователя | Не защищает |
| Мастер-пароль приложения | Не зависит от ОС | Ввод при каждом запуске | Позже, как опция для общих машин |
| Вопрос пользователю обычным сообщением | Ничего не делать | Нет вариантов, рекомендации, клавиш | Ровно то, что чиним |

## Последствия

- `settings.json` с зашифрованными ключами не переносится на другую машину —
  ключи нужно ввести заново (видно в «Настройках»).
- В контейнерах и CI без keyring ключи остаются открытыми — это показывается.
- Проверки: `scripts/test-secrets.mjs`, `scripts/test-secrets-electron.mjs`,
  `scripts/test-interactive.mjs`, раздел [11] `test-agent-loop`, раздел [17] `test-ui`.
