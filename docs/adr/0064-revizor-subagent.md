# 0064. Ревизор знает режим и проверяет файлы сам

- **Статус:** accepted
- **Дата:** 2026-11-22
- **Контекст:** бэклог F5; A3.4 (роль `review`) сделано раньше

## Контекст

Ревизор (вторая модель) получал только задачу и текст ответа. В «Плане» он
требовал правок кода, которые там запрещены, — цикл крутился до `maxRounds`.
Проверить, что правки действительно сделаны, он не мог: верил тексту ответа.
Для gpt-5 он слал `temperature: 0`, которую модель не принимает.

## Решение

- Режим и вид чата — в промпт ревизора (`reviewContext`): «План» — оценивать
  план, не требовать правок кода; «Только разрешённое» — отклонённые правилами
  действия не ошибка агента; «Задача» — оценивать документы, а не код.
- Если агент изменил файлы в прогоне (`write`/`delete`), ревизор — субагент
  (ADR 0036) на модели ревизора: инструменты только чтения (`read_file`,
  `read_document`, `list_files`, `glob`, `grep`), режим «План», без подтверждений;
  в задании — задача, ответ и список изменённых файлов. Итог — тот же JSON
  `approve`/`revise`; не JSON — «принято». Без изменений файлов — как раньше,
  одним запросом.
- `temperature` ревизору — только если модель её принимает (ADR 0058).
- Настройка «ревизор сам читает изменённые файлы» (`reviewer.verify`, по
  умолчанию включено) — «Настройки» → «Ревизор».

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Ревизор всегда субагент | Единообразно | Лишние шаги, когда проверять нечего | Только при изменённых файлах |
| Ревизору разрешить запуск тестов | Сильнее проверка | Команды — риск, нужен режим и подтверждения | Только чтение; тесты — через хук Stop (ADR 0035) |

## Последствия

- Проверка с чтением файлов дороже на несколько запросов к модели ревизора.
- Проверки: раздел [27] `test-agent-loop` (ревизор читает изменённый файл,
  без инструментов записи, список файлов в задании, revise → approve, в
  «Плане» — контекст режима, gpt-5 без temperature).
