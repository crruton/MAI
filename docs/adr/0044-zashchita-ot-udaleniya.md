# 0044. Защита от удаления и корзина

- **Статус:** accepted
- **Дата:** 2026-11-21
- **Контекст:** бэклог CW1.4 (P0 для Cowork)

## Контекст

У агента не было инструмента удаления: файлы удалялись командой `rm`/`del`
через `run_shell`. Такую команду в «Авто» спрашивала только оценка риска, а
в «Без вопросов» удалённое терялось насовсем: чекпоинты (ADR 0033) команды не
видят. Для работы с документами пользователя (Cowork) удаление без возврата
недопустимо.

## Решение

- Инструмент `delete_file(path)` и новый класс действия `delete` в PolicyEngine
  (ADR 0027). Режимы: «Вручную», «Принимать правки», «Авто» — спросить;
  «План» и «Только разрешённое» — запрет (если нет правила `allow`); «Без
  вопросов» — разрешено. Правила `write_file`/`edit_file` удаление не
  покрывают: нужно отдельное `delete_file(маска)`, кнопка «Да, и не спрашивать»
  предлагает его только на конкретную папку.
- Удаление — перенос в корзину приложения `<данные>/trash/<id>/` с
  `meta.json` (исходный путь, размер, число файлов, время). Файл ещё и
  попадает в чекпоинт: откат к сообщению вернёт его.
- Нельзя: всю папку проекта, вне проекта, секретные файлы (guardrails); без
  корзины инструмент не работает.
- `/trash` — список, «Восстановить» (если на месте уже есть файл — с
  подтверждением замены, замена только admin), «Удалить навсегда» (admin).
  Записи старше 30 дней удаляются при следующем удалении.
- Описание инструмента просит модель удалять только им, а не `rm` через
  `run_shell`; `rm`/`del` остаются в оценке высокого риска (ADR 0039).

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Корзина ОС (`shell.trashItem`) | Привычно | Только в main-процессе Electron; на Linux без DE не работает; в тестах не проверить | Своя корзина, одинаковая на всех ОС |
| Запретить удаление агенту совсем | Проще | Агент начнёт удалять через `rm` | Отдельный инструмент с корзиной и вопросом |
| Подтверждение и на перезапись файла | Строже | Перезапись покрыта чекпоинтами и diff в запросе; в «Принимать правки» спрашивал бы каждый `write_file` | Перезапись — через чекпоинты; удаление — через корзину |

## Последствия

- `rm` через `run_shell` по-прежнему возможен там, где команда разрешена: это
  граница режима и правил, а не корзины. Для Cowork-задач полезна песочница
  команд (ADR 0040).
- Проверки: `scripts/test-trash.mjs` (29: корзина, восстановление с заменой,
  очистка, решения во всех режимах, правила, отказ, чекпоинт, запреты), раздел
  [30] `test-ui`.
