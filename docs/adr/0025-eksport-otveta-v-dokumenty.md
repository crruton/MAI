# 0025. Экспорт ответа в MD, TXT, DOCX и XLSX без внешних библиотек

- **Статус:** accepted
- **Дата:** 2026-11-16
- **Контекст:** бэклог №6, `docs/BACKLOG.md`

## Контекст

Ответы агента нужно отдавать наружу: в документ, отчёт или таблицу. Сейчас
скопировать текст можно только через буфер обмена. Пункт 6 бэклога требует
меню «Скачать» с четырьмя форматами: Markdown, TXT, DOCX, XLSX.

Бэклог предлагал библиотеки `docx` и `exceljs`. Проверка `node_modules`
показала: ни одной из них нет. Обе тянут транзитивные зависимости и увеличивают
офлайн-архив. Приложение уже поставляет 205 МБ офлайн-дистрибутива, и каждая
новая зависимость усложняет проверку целостности.

## Решение

Генерировать DOCX и XLSX самостоятельно: это ZIP-архив с XML внутри. Node
содержит `zlib`, поэтому ZIP собирается без зависимостей.

| Формат | Как собирается | Зависимости |
|---|---|---|
| MD | текст как есть | нет |
| TXT | Markdown → простой текст | нет |
| DOCX | ZIP + WordprocessingML | нет |
| XLSX | ZIP + SpreadsheetML | нет |

Детали:

1. **ZIP-писатель** (`electron/lib/export/zip.js`). Хранилище без сжатия
   (`method 0`) для простоты и предсказуемости. Размер файла растёт, но DOCX
   ответа — единицы килобайт. CRC-32 считается по таблице.
2. **Разбор Markdown** (`electron/lib/export/markdown.js`). Один проход по
   строкам: заголовки, списки, таблицы, блоки кода, цитаты, горизонтальные
   линии. Инлайн-разметка упрощается до текста: `**жирный**` → `жирный`.
3. **DOCX** (`electron/lib/export/docx.js`). Минимальный набор частей:
   `[Content_Types].xml`, `_rels/.rels`, `word/document.xml`,
   `word/styles.xml`. Код — моношрифтом `Consolas`, таблицы — `w:tbl`.
4. **XLSX** (`electron/lib/export/xlsx.js`). Каждая таблица Markdown — лист.
   Если таблиц нет, лист один и содержит текст построчно. Строки экранируются
   от XML-инъекций.
5. **Имя файла** (`electron/lib/export/index.js`). `<дата>-<тема>.<ext>`,
   запрещённые в Windows символы заменяются на `-`, длина ограничена 80
   символами.
6. **IPC** `export:message` и `export:chat`. Диалог сохранения —
   `dialog.showSaveDialog`, как у `artifacts:export`.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| `docx` + `exceljs` | готовый API, меньше кода | +2 зависимости, +несколько МБ в офлайн-архиве, нужна проверка целостности | офлайн-дистрибутив и так большой |
| Только MD и TXT | ноль кода | не закрывает критерии приёмки бэклога | задача требует четыре формата |
| HTML с расширением `.doc` | просто | Word показывает предупреждение о формате | критерий: «без предупреждений» |
| CSV вместо XLSX | просто | нет листов, нет типов | критерий: «таблицы отдельными колонками» |

## Последствия

- Проще: нет новых зависимостей, офлайн-архив не растёт, экспорт работает
  без сети.
- Сложнее: свой ZIP-писатель и разбор Markdown нужно поддерживать. Покрытие
  Markdown неполное — вложенные списки и сноски упрощаются.
- Проверить: открытие файлов в Word, Excel и LibreOffice; кириллицу и эмодзи;
  таблицы с пустыми ячейками; ответы с кодом.
- Риски: ZIP без сжатия даёт файл больше ожидаемого на очень длинных ответах.
  Снижение: при ответе длиннее 1 МБ включается `deflate` через `zlib`.
- Ограничение: формулы Excel не генерируются, диаграммы не переносятся.
