# 0033. Чекпоинты правок и откат к сообщению

- **Статус:** accepted
- **Дата:** 2026-11-20
- **Контекст:** бэклог CC6.1

## Контекст

Отменить правки агента можно было только через git. Вернуть чат к прошлому
сообщению и переспросить по-другому — никак.

## Решение

`electron/lib/checkpoints.js`. Перед записью `write_file` и `edit_file`
вызывают `ctx.beforeWrite(file)`; цикл агента привязывает правку к последнему
сообщению пользователя в истории (ход — его индекс) и сохраняет исходное
содержимое файла один раз за ход. Хранилище — `<данные>/checkpoints/blobs/<sha256>`
(одинаковое содержимое хранится один раз) и индекс `<данные>/checkpoints/<сессия>.json`.
Файл, которого не было, помечается `absent` — откат его удалит; файлы больше
5 МБ не сохраняются и помечаются `skip`.

Откат к ходу N: для каждого файла берётся самое раннее состояние среди ходов
≥ N. Режимы: «Код и диалог» (рекомендуется, если были правки), «Только диалог»
(сообщение и всё после него уходят из чата, текст возвращается в поле ввода),
«Только код». Перед откатом окно показывает файлы и что с ними будет. Откат
недоступен, пока агент работает, и берёт блокировку проекта.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| git stash / коммит на каждый ход | Знакомо | Трогает историю git пользователя, нужен git | Чекпоинты не зависят от git |
| Снимок всей папки проекта | Ловит и run_shell | Дорого на больших проектах | Только файлы, которые правил агент |

## Последствия

- Изменения, сделанные командами `run_shell`, откат не возвращает — окно
  отката пишет это прямо.
- Чекпоинты удаляются вместе с чатом.
- Проверки: `scripts/test-checkpoints.mjs`, раздел [14] `test-agent-loop`,
  раздел [21] `test-ui`.
