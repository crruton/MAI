# 0106. Хук post-commit не блокирует коммит

- **Статус:** accepted
- **Дата:** 2026-11-24
- **Контекст:** зависание `git commit` на 58–180 с после установки хука repowise

## Контекст

`repowise hook install` ставит `.git/hooks/post-commit`, который после каждого
коммита обновляет индекс и документацию. Хук запускает `repowise update` в
подоболочке с `&`, то есть формально в фоне. На практике `git commit` ждал
окончания индексации.

Замеры на этом репозитории:

| Что измерялось | Время |
|---|---|
| `sh .git/hooks/post-commit` напрямую | 0.8 с |
| `git commit --allow-empty` с хуком | 58.7 с |
| `repowise update` по логу `.repowise/.update.log` | 5 мин 11 с |

Причина: подоболочка наследует дескрипторы git (stdout/stderr пайпа), а
`repowise` — её потомок. Git читает вывод хука до EOF и получает EOF только
после выхода внука. Фоновый `&` снимает ожидание самого `sh`, но не закрывает
унаследованный канал.

## Решение

Хук запускает `repowise update` через `nohup` с перенаправлением всех
дескрипторов: `nohup "$RW" update >> "$LOG" 2>&1 </dev/null &`. Процесс
отвязывается от git, коммит возвращает управление сразу, индексация идёт
параллельно и пишет в `.repowise/.update.log`.

Правка живёт в `.git/hooks/post-commit` и **перезаписывается** командой
`repowise hook install`. После переустановки хука правку нужно повторить;
признак возврата дефекта — коммит дольше нескольких секунд.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Оставить как есть | Ничего не делать | Коммит ждёт 1–5 минут | Дефект блокирует работу |
| Удалить хук (`repowise hook uninstall`) | Коммит быстрый | Индекс и документация устаревают | Теряется польза repowise |
| `setsid` / `disown` | Отвязка от сессии | На Windows в Git Bash `setsid` нет | Непереносимо |
| `nohup` + `/dev/null` на всех дескрипторах | Работает в Git Bash на Windows | Правка не переживает переустановку хука | Выбран: минимальная и проверенная |

## Последствия

- Коммит возвращает управление за ~0.8 с вместо 58.7 с.
- Индексация repowise продолжается в фоне; её результат виден в
  `.repowise/.update.log`.
- После `repowise hook install` правку нужно повторить.
- Проверка: `git commit --allow-empty` и замер времени; ожидается меньше 2 с.
