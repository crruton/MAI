# 0051. Длинные задачи и прогресс

- **Статус:** accepted
- **Дата:** 2026-11-21
- **Контекст:** бэклог CW5.2, CW5.3

## Контекст

История чата сохраняется после каждого шага агента (ADR 0034), но если
приложение закрыли посреди работы, по чату это не было видно: последнее
сообщение — вызов инструмента, а продолжить можно было только написав
агенту самому, что произошло.

## Решение

- У чата — состояние прогона `session.run`: `running` при старте, по окончании
  `done`, `error` или `stopped` (и у плановых задач, ADR 0050). Поле защищено
  от перезаписи прогоном (как режим) и есть в индексе чатов.
- При запуске приложения все `running` — это прогоны, которые не пережили
  закрытие: они помечаются `interrupted` (`markInterrupted`).
- В списке чатов у такого чата — «⏸», в самом чате — плашка «Работа
  прервалась… сделано N из M задач» с кнопками «Продолжить» и «Скрыть».
  «Продолжить» отправляет агенту просьбу продолжить с места и сначала
  проверить сделанное (список задач, файлы, результаты команд), не повторяя
  шаги. Состояние берётся из истории: список задач восстанавливается из
  последнего `todo_write`, файлы — на диске, чекпоинты — как обычно.
- Прогресс (CW5.3) — список задач агента (CC1.5) с текущим шагом в заголовке
  (виден и в свёрнутом виде), «📄 Результаты» (ADR 0047), вопросы карточками
  (ADR 0031).

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Продолжать автоматически при запуске | Без клика | Агент начнёт менять файлы, пока пользователь не смотрит; в режимах с вопросами — сразу вопрос | Явная кнопка |
| Отдельный файл состояния задачи (план, шаг) | Точнее | Дублирует историю и список задач | История + todo_write уже есть |

## Последствия

- Если приложение упало, а не закрылось, — то же поведение: `running` без
  процесса.
- Проверки: `test-sessions` (защита поля, индекс, `markInterrupted`), раздел
  [36] `test-ui` (плашка, «Продолжить», текущий шаг), `smoke-scheduler`
  (настоящее приложение отмечает прерванный прогон).
