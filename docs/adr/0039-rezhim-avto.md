# 0039. Режим «Авто» с классификатором

- **Статус:** accepted
- **Дата:** 2026-11-20
- **Контекст:** бэклог CC2.2, A1.5; решение D2

## Контекст

По ADR 0027 прежний «Авто» (разрешить всё) стал «Без вопросов». Между
«Принимать правки» (каждая команда — вопрос) и «Без вопросов» (вопросов нет)
не было середины: агент, который гоняет тесты и сборку, спрашивает на каждом
шаге, а «Без вопросов» запускает и `git push`, и `curl | sh`.

## Решение

Режим `smart`, в интерфейсе — «Авто». Id новый: сохранённое `auto` по-прежнему
читается как `bypass`, чтобы поведение не менялось молча.

Порядок проверки PolicyEngine прежний: guardrails → `deny` → `ask` → чтение →
`allow`. Вызов, который правила не решили, отдаётся `classifyAuto()`
(`electron/lib/policy.js`) — детерминированному классификатору без модели:

| Молча | С вопросом |
|---|---|
| правки файлов проекта (откатываются, ADR 0033) | файл вне проекта, `.git/` |
| запись в память (версии) | — |
| команды без высокого риска в папке проекта: `npm test`, `npm run build && npm test`, `git status > out.txt` | удаление, сеть, установка пакетов, `git push`/`reset --hard`/`clean` (тот же список, что у оценки риска); подстановка `$(…)`; встроенный код `node -e`, `python -c`, `bash -c`, `pwsh -Command`; пути вне проекта (`/…`, `~`, `C:\`, `\\server`, `..`, в т. ч. в `--opt=/путь`) |
| — | MCP, плагины, сеть |

- Причина вопроса классификатора — в карточке: «Авто спрашивает: …».
  В журнале решений — `source_of_decision: classifier`.
- Режим доступен гостю: он строже «Без вопросов» и не снимает ни одной защиты.
- Внешние CLI наш классификатор не исполняют: для них «Авто» = «Принимать
  правки» (флаги из `permissionArgs`), в docker — проект на запись.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Классификатор на LLM (как auto mode в Claude Code) | Понимает намерение | Задержка и цена на каждый вызов, недетерминирован, сам может быть обманут промпт-инъекцией | Детерминированные правила проверяемы тестами; LLM-оценку можно добавить вторым шагом для «спросить» |
| Белый список команд | Предсказуемо | Длинный список, постоянно неполный | Чёрный список риска уже есть (оценка риска), плюс правило «только внутри проекта» |
| Переиспользовать id `auto` | Короче | Пользователи с сохранённым `auto` молча получили бы другой режим | Новый id |

## Последствия

- `run_shell` в «Авто» может менять файлы проекта командой — такие правки
  чекпоинты не откатывают. Для недоверенного кода — «Вручную» или docker (CC2.8).
- Классификатор не видит, что делает скрипт (`npm test` запускает что угодно из
  `package.json`); это та же граница доверия, что и доверие к папке (ADR 0028).
- Проверки: раздел [Авто] `test-policy` (30), карточка в `test-ui` [14].
