# 0006. Ревизор: вторая модель проверяет ответ

- **Статус:** accepted; замечание хранится ролью `review` (ADR 0027), к субагентам ревизор не применяется (ADR 0036)
- **Дата:** 2026-11-04

## Контекст

Из Delamain нужна механика, где одна модель проверяет вывод другой и либо
апрувит, либо отправляет на доработку. Сейчас агент завершает работу, как только
перестаёт вызывать инструменты.

## Решение

Добавлен опциональный ревизор в `electron/lib/reviewer.js`:

- после финального ответа агента запускается вторая модель;
- ревизор получает задачу пользователя, финальный ответ и краткий diff;
- ответ строго JSON: `{ "verdict": "approve" | "revise", "reason": "...", "instructions": "..." }`;
- при `revise` причина и инструкции добавляются в историю как сообщение
  пользователя, цикл агента продолжается;
- не больше `reviewer.maxRounds` раундов (по умолчанию 2);
- события `review:start`, `review:result` показываются в чате.

По умолчанию ревизор выключен: это дополнительный расход токенов. Включение —
`settings.reviewer.enabled = true`, модель — `provider/model` или пусто
(тогда используется модель основного агента).

## Альтернативы

| Вариант | Плюсы | Минусы |
|---|---|---|
| Без ревизора | Дешево | Ошибки остаются |
| Тот же агент проверяет себя | Просто | Нет второго взгляда |
| Вторая модель | Независимая проверка | Токены и задержка |

## Последствия

- Нужен валидный JSON; при ошибке разбора ревизор считается `approve`, чтобы
  не блокировать пользователя.
- Ревизор не вызывает инструменты и не меняет файлы.
- Ограничение: качество зависит от модели; это советник, а не формальный гейт.
