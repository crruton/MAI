# 0077. Безголовый режим: `mai -p` и поток событий

- **Статус:** accepted
- **Дата:** 2026-11-22
- **Контекст:** бэклог CC12.1, CC12.2; продолжение ADR 0050 (плановые задачи без окна)

## Контекст

Агента можно было запустить только из окна (или по расписанию). Claude Code
работает и из скриптов: `claude -p "…" --output-format json|stream-json`. Для
CI, cron и цепочек команд нужен такой же запуск MAI — с теми же провайдерами,
ключами, правилами и хуками, что и в приложении.

## Решение

- `electron/lib/cli.js`: `isCliInvocation(argv)` (`--cli`, `-p`, `--print`),
  `parseCliArgs` (флаги `-p/--print` или `-p -` для stdin, `--mode`,
  `--output text|json|stream-json`, `--model`, `--kind`, `--cwd`,
  `--max-turns`, `--allow` повторяемый; флаги Chromium и путь приложения
  пропускаются; ошибка — код 2 и справка), `resultObject`, `streamLine`.
  Модуль не зависит от Electron.
- `main.js`: при CLI окно, планировщик и установка навыков не запускаются;
  `runCli` повторяет путь плановой задачи — `runAgent` с политикой
  (`policyFor` + режим из флага), хуками, чекпоинтами, плагинами и MCP
  проекта (если папка доверена), сессией «CLI: …» (видна потом в окне),
  блокировкой папки. Спросить некого: `approve` всегда отказывает с подсказкой
  «разрешите правилом --allow»; `ask_user` недоступен; браузер агента
  выключен. Режим по умолчанию — `dontAsk` (только по правилам);
  `bypass` — только где разрешён в окне (доверенная папка, admin, без запрета
  организации), иначе `dontAsk` с предупреждением в stderr.
- Вывод: `text` — только ответ в stdout, ошибки в stderr; `json` — один объект
  `{ type: 'result', ok, result, session_id, model, mode, duration_ms, usage?,
  denied?, error? }`; `stream-json` — каждое событие агента (те же, что
  получает окно: `delta`, `tool_call`, `tool_result`, `notice`…) строкой JSON с
  `session_id`, последней — итог. Код выхода: 0 — готово, 1 — ошибка, 2 —
  неверные флаги. Ctrl+C останавливает прогон.
- Перезапуск с `--use-system-ca` (корпоративные сертификаты) в CLI наследует
  stdio и код выхода дочернего процесса.
- `bin/mai.mjs` (`"bin": { "mai": … }`) — запуск из терминала через Electron из
  `node_modules`; на Linux без дисплея добавляет `--ozone-platform=headless`.
  Флаги Chromium ставятся после пути приложения, иначе перезапуск их теряет.
  `-p -` (задача из stdin) читает лаунчер и передаёт файлом
  (`MAI_CLI_PROMPT_FILE`): главный процесс Electron на Windows stdin не
  получает. Найдено падением smoke-cli на Windows CI.
  Установленное приложение: `"MAI Code.exe" --cli -p "…"`.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Отдельный Node-пакет без Electron | Лёгкий запуск | Нет `safeStorage` (ключи), дублирование main | Тот же main — те же ключи и правила |
| HTTP-сервер приложения для скриптов | Без нового процесса | Открытый порт, нужно запущенное окно | Процесс на задачу проще и безопаснее |

## Последствия

- На Windows упакованное приложение — GUI-программа: вывод виден при
  перенаправлении (`> out.json`) или через `mai` из Node.
- CLI занимает папку проекта так же, как чат: параллельный прогон в окне той
  же папки получит «папка занята».
- Проверки: `scripts/test-cli.mjs` (определение запуска, все флаги, значения
  по умолчанию, `--флаг=значение`, stdin, ошибки, итог и строки событий);
  `scripts/smoke-cli.mjs` на настоящем приложении с поддельной моделью —
  stream-json с событиями и итогом, запись по `--allow`, отказ без правила,
  режим по умолчанию, сохранённый чат, json со stdin и `--mode plan --kind
  task`, text, неверный флаг (2), `--help`, нет модели (1). В CI на Linux и
  Windows. Лаунчер без дисплея проверен вручную.
