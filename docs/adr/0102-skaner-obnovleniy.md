# 0102. Проактивный сканер обновлений и обновление на ветке с тестами

- **Статус:** accepted
- **Дата:** 2026-11-23
- **Контекст:** бэклог N6 (запрос пользователя); worktree (ADR 0075), signoff (ADR 0097)

## Контекст

Устаревшие зависимости, уязвимости и конфликты версий обнаруживались случайно —
когда что-то ломалось. Встроенные навыки, CLI (repowise, gh) и само приложение
обновлялись, только если о новой версии кто-то вспоминал. А обновить «как есть»
в рабочей папке — значит рискнуть проектом: мажорная версия может сломать сборку.

## Решение

- `update-scan.js` (без Electron): `scanUpdates` собирает
  - `npm outdated --json --long` → обновления: мажорная версия — высокий риск,
    минорная — средний, патч — низкий, не установлен — сведения;
  - `npm audit --json` → уязвимости: critical/high — высокий, moderate — средний;
    есть ли исправление и мажорное ли оно;
  - `npm ls --json --all` → конфликты (invalid, peer, missing — высокий);
  - встроенные навыки, версия которых новее установленной;
  - repowise (PyPI), gh (релизы cli/cli) и MAI Code (последний релиз
    `updateScan.releasesRepo`, по умолчанию `crruton/MAI`).
  Сеть недоступна — пункт в `errors`, скан не падает.
- npm проверяется только в доверенном проекте с `package.json` (ADR 0028).
- Расписание: через 90 с после запуска, не чаще `updateScan.intervalHours`
  (24 ч); отчёт — `<данные>/update-scan.json`; находки высокого риска —
  уведомлением. `updateScan.enabled: false` выключает.
- `/updates`: отчёт по риску, «Проверить сейчас», отметить обновления npm и
  «Обновить на ветке и прогнать тесты» (admin): рабочая копия
  `mai/update-deps-<время>` (git worktree), `npm install имя@версия` только для
  проверенных имён и версий, тесты проекта (как у `/signoff`). Проект не меняется:
  слить ветку — вручную через `/worktree`, когда тесты зелёные.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Dependabot / Renovate | Готово | Только GitHub, без навыков, CLI и локальных тестов | Локально и для всего |
| Автообновление в проекте | Быстро | Ломает рабочую папку без проверки | Ветка + тесты |
| Скан на каждый запуск | Свежее | Сеть и npm на каждом старте | Раз в сутки |

## Последствия

- Обновление самого MAI Code — новый установщик (автообновления нет); сканер
  только сообщает о релизе.
- Первый же прогон на репозитории MAI показал Electron 38 → 45 и openai 6 → 7
  (мажорные) и 10 уязвимостей среднего риска в зависимостях сборки.
- Проверки: `test-update-scan` — прыжки версий, разбор outdated/audit/ls,
  навыки, CLI и приложение, полный скан с ошибкой сети, без package.json,
  расписание, безопасные аргументы установки; `test-ui` [59] — окно `/updates`,
  выбор и «Обновить на ветке».
