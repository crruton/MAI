# 0076. `/pr`, `/security-review` и чат в рабочей копии `/worktree`

- **Статус:** accepted
- **Дата:** 2026-11-22
- **Контекст:** бэклог CC11.2, CC11.4, CC11.5; продолжение ADR 0059 (`/commit`, `/review`, защита веток), 0075 (worktree для субагента)

## Контекст

После `/commit` и `/review` в git-потоке не хватало трёх шагов из Claude Code:
открыть pull request по шаблону репозитория, сделать ревью с фокусом на
безопасности и вести параллельную задачу в отдельной рабочей копии, не трогая
основную папку.

## Решение

**`/pr [уточнение]` (CC11.2)** — шаблон запроса `prPrompt`, как `/commit`:
агент смотрит состояние (незакоммиченное — спросить), на основной/защищённой
ветке создаёт новую, ищет шаблон описания (`.github/pull_request_template.md`,
`.github/PULL_REQUEST_TEMPLATE/*`, `docs/…`, GitLab
`.gitlab/merge_request_templates/*`) и заполняет его разделы, пропуская
пункты про секреты и внутренние адреса; push — `git push -u origin <ветка>`,
PR — `gh pr create --body-file` или `glab mr create`; без CLI — ссылка из
вывода push и готовый текст. Не мерджит и не меняет историю. Подпись — из
`gitAttribution`. Все команды идут обычными `run_shell` с разрешениями и
защитой веток (ADR 0059).

**`/security-review [PR]` (CC11.4)** — `securityReviewPrompt`: как `/review`
(только чтение, diff или `gh pr diff`), но категории уязвимостей, важность
критично/высокий/средний/низкий, уверенность, `файл:строка`, путь атаки и
исправление; без теоретических находок без пути атаки.

Обе команды, как `/commit` и `/review`, `overridable`: своя команда проекта или
пакета с тем же именем сильнее.

**`/worktree [имя]` (CC11.5)** — чат в отдельной рабочей копии.
- `worktree.js`: `createWorktree({ branchPrefix })` (для чатов — `mai/wt-<имя>`),
  `listWorktrees(repo)` (`git worktree list --porcelain`), `worktreeId(имя)`.
- IPC `worktree:list` (любая роль), `worktree:create`, `worktree:open`,
  `worktree:remove` (admin). Копии — в `<данные>/worktrees/<репозиторий>/<имя>`,
  вне папки проекта. Копия доверенного репозитория получает то же доверие.
  Открытие — смена папки проекта и новый чат в ней; подпапка проекта внутри
  репозитория сохраняется.
- «Убрать»: несохранённое коммитится в ветку копии, папка удаляется, ветка
  остаётся; основную папку убрать нельзя.
- `/worktree` без имени — окно со списком (основная папка и копии, «Открыть»,
  «Убрать») и полем «Новая копия».

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| PR через GitHub API из main | Без gh | Токен в приложении, только GitHub | Агент и gh/glab: видно каждую команду |
| Копии внутри проекта (`.mai-code/worktrees`) | Рядом с кодом | Вложенные рабочие копии путают инструменты и поиск | Папка данных приложения |
| Отдельное окно на каждую копию | Параллельно на экране | Сложнее; окно уже умеет переключать папку | Переключение папки + новый чат |

## Последствия

- Слияние копии в основную ветку — обычным git или `/pr` из копии.
- Проверки: `scripts/test-worktree.mjs` [4] — имя копии, список с основной
  папкой, повторное создание, удаление с веткой; `test-ui` [46] — тексты
  `/security-review` и `/pr`, окно `/worktree` (строки, «Убрать» только у
  копий, создание).
