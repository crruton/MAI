# 0056. web_fetch и web_search

- **Статус:** accepted
- **Дата:** 2026-11-21
- **Контекст:** бэклог CC1.6, A1.7

## Контекст

Агент не умел читать документацию и искать в интернете — только через
`curl` в `run_shell` (высокий риск, сырой HTML) или MCP-сервер.

## Решение

`electron/lib/web.js`, `tools/web.js`:

- **`web_fetch({ url, max_chars? })`** — класс `network` (ADR 0027): без
  правила спрашивается во всех режимах, кроме «Без вопросов». Только http/https,
  до 5 МБ, 20 с, до 5 перенаправлений. HTML → текст (заголовки `#`, абзацы,
  списки, ссылки абсолютными `[текст](url)`; скрипты, стили, `nav`/`footer`
  выкинуты); картинки и архивы — «не текст».
- **SSRF.** Адреса локальной сети (loopback, 10/8, 172.16/12, 192.168/16,
  169.254/16 — метаданные облака, 100.64/10, IPv6 ULA и link-local, `localhost`,
  `.local`, `.internal`) запрещены; имя резолвится и проверяется, каждое
  перенаправление — заново. Разрешить — «Настройки» → «Поиск в интернете» →
  «адреса локальной сети» (admin).
- **`web_search({ query, limit? })`** — тоже `network`. Поисковик —
  `settings.webSearch`: DuckDuckGo (HTML, без ключа, по умолчанию), свой
  SearXNG (`url`) или Brave Search (`apiKey`, шифруется хранилищем ОС, в окно —
  `***`). Меняет admin.
- Правила: предмет `web_fetch` — домен (`web_fetch(docs.python.org)`,
  `web_fetch(*.python.org)`), кнопка «Да, и не спрашивать» предлагает домен;
  `web_search` — запрос, предлагается `web_search`.
- Результат — данные: рамка `<данные>` и детектор внушённых указаний
  (ADR 0053); длинный текст — в файл (ADR 0054).
- `settings.webTools: false` убирает оба инструмента.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Только MCP-сервер fetch | Ничего своего | Нет проверки SSRF и домена в правилах; ставить отдельно | Встроенный с правилами по домену |
| Поиск только с ключом (Brave, Bing) | Стабильно | Без ключа поиска нет вовсе | DuckDuckGo по умолчанию, ключевые — по выбору |
| Загрузка через Chromium (`net.fetch`) | Системный прокси | Другие правила перенаправлений, сложнее проверять SSRF | Node fetch; прокси — ограничение ниже |

## Последствия

- Системный прокси не используется (Node fetch). За корпоративным прокси
  нужен SearXNG внутри сети или MCP-сервер — следующий шаг.
- HTML DuckDuckGo может поменяться или отвечать капчей — тогда помогает
  SearXNG/Brave.
- Проверки: `scripts/test-web.mjs` (30: адреса, SSRF через имя и
  перенаправление, HTML → текст, перенаправление, 5 МБ, не текст, разбор
  DuckDuckGo, SearXNG, Brave, политика и правила по домену, инструменты);
  в CI на Linux — живая загрузка example.com.
