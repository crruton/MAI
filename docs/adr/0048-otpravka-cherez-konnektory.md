# 0048. Отправка через коннекторы

- **Статус:** accepted
- **Дата:** 2026-11-21
- **Контекст:** бэклог CW3.2 (P0 для коннекторов, CW3.1)

## Контекст

MCP-инструмент без `readOnlyHint` был классом `external` и в «Без вопросов»
выполнялся молча. Для коннекторов почты, мессенджеров и календаря это значит,
что агент может отправить письмо или сообщение от имени пользователя без его
ведома. Такое действие не откатить: ни чекпоинты, ни корзина не помогут.

## Решение

- Новый класс действия `send` (ADR 0027). MCP-инструмент попадает в него, если
  в имени есть глагол отправки — `send`, `reply`, `forward`, `post`,
  `publish`, `notify`, `invite`, `share`, `comment`, `create_event`,
  `schedule_meeting`, `dm` (camelCase разбирается: `sendMessage`,
  `chat_postMessage`). `readOnlyHint: true` сильнее имени. Плагин может
  объявить `kind: 'send'`.
- Решение: guardrails → `deny` → «План» (запрет) → `ask` → `allow` (явное
  правило — без вопроса) → **спросить в любом режиме, включая «Без вопросов»**;
  «Только разрешённое» — запрет.
- Риск высокий, рекомендованный ответ — «Нет». «Да, и не спрашивать» не
  предлагается: правило можно добавить только вручную (`/permissions` или
  `settings.json`).
- Карточка запроса показывает, что уйдёт, раскрытым блоком «Будет
  отправлено:» по полям (`to`, `subject`, `body`…), а не под спойлером.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Только по аннотациям MCP (`openWorldHint`, `destructiveHint`) | Без эвристик | Большинство серверов аннотации не ставят | Имя + `readOnlyHint` |
| Список известных инструментов | Точно | Устаревает, не покрывает свои серверы | Глаголы в имени |
| Разрешить в «Без вопросов» | Последовательно с другими классами | Необратимое действие от имени пользователя | Исключение из «Без вопросов», как guardrails |

## Последствия

- Эвристика по имени может ошибиться: `create_issue` — не отправка
  (`external`, в «Без вопросов» без вопроса), `share_link` — отправка. Точнее —
  правила `ask`/`deny` на конкретные инструменты.
- Проверки: раздел [Отправка] `test-policy` (12), раздел [34] `test-ui`.
