# 0075. Изоляция субагента в git worktree и фоновые субагенты

- **Статус:** accepted
- **Дата:** 2026-11-22
- **Контекст:** бэклог CC8.5, CC8.6; продолжение ADR 0036 (субагенты), CC6.1 (чекпоинты)

## Контекст

Субагент `general` правил файлы проекта напрямую: попытку «другого подхода»
нельзя было ни сравнить, ни отбросить целиком. В Claude Code субагент может
работать в своём `git worktree`, а долгие подзадачи — идти в фоне, пока
основной агент продолжает работу.

## Решение

**Изоляция (CC8.5).** Параметр инструмента `agent` `isolation: "worktree"` или
`isolation: worktree` в frontmatter своего типа (`.mai-code/agents/*.md`).
Действует только для пишущих субагентов. `electron/lib/worktree.js`:
- `repoRoot(dir)` — корень репозитория с коммитами, иначе отказ с подсказкой
  (правок в проекте при этом нет);
- `createWorktree` — копия на ветке `mai/agent-<id>` от HEAD в
  `settings.worktreeDir` (по умолчанию временная папка); субагент работает в
  ней (`projectDir` — тот же подпуть внутри копии), чекпоинты и доп. папки
  отключены;
- `worktreeChanges` — `git add -A` и список A/M/D без распознавания
  переименований, статистика, патч (предел 2 МБ);
- после работы — запрос «Слить в проект изменения субагента…» (`agent_merge`,
  класс write, со списком файлов и статистикой) в любом режиме;
- «да» → `applyChanges`: по каждому файлу трёхсторонне относительно базы
  копии (`git merge-file`), поэтому незакоммиченные правки пользователя
  сохраняются; конфликт хоть в одном файле — ошибка, проект не меняется.
  Перед наложением файлы пишутся в чекпоинт хода родителя — откат CC6.1 вернёт
  и их. Копия и ветка удаляются;
- «нет», конфликт или ошибка → изменения коммитятся в ветку `mai/agent-<id>`,
  копия удаляется, ветка остаётся для ручного разбора.

**Фон (CC8.6).** `background: true` у `agent` — только для субагентов для
чтения или с изоляцией (в фоне не должно быть вопросов о правках проекта, на
которые некому ответить). main ведёт реестр по чату (`backgroundFor`):
задача получает id `bg-…` и свой AbortController, родитель сразу получает
ответ «запущен в фоне». По завершении итог дописывается в историю чата
(сообщение с `background: id` — агент увидит его следующим ходом), окну
уходит событие `agent:background`, а если окно не в фокусе — системное
уведомление. Инструмент `agent_result` (класс read) — состояние и итог по id
или всех. Фоновые субагенты останавливаются при выходе из приложения.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| `git apply --3way` для слияния | Одна команда | Требует, чтобы индекс совпадал с файлами — ломается на незакоммиченных правках | Слияние по файлам через `merge-file` |
| Копия папки без git | Работает везде | Нет базы для трёхстороннего слияния, медленно на больших проектах | Только git-репозитории |
| Фон для любых субагентов | Гибко | Вопросы о правках без родителя повисают | Фон — только чтение или копия |

## Последствия

- Копия стартует от последнего коммита: незакоммиченных правок пользователя
  субагент в копии не видит (агенту это сказано в описании параметра).
- Ветки `mai/agent-*` после отказов копятся в репозитории — их удаляет
  пользователь (или чистильщик N7).
- Проверки: `scripts/test-worktree.mjs` (настоящий git: корень, копия на
  ветке, A/M/D, слияние с правкой пользователя, чистый индекс, отказ с
  веткой, конфликт без изменений проекта, неверный id); `test-agent-loop`
  [30] — правка в копии, вопрос о слиянии, чекпоинт, «нет» — ветка, не git —
  отказ; [31] — фон для чтения, запрет фона для пишущего без изоляции,
  `agent_result`, итог.
