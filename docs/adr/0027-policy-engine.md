# 0027. PolicyEngine: одна точка решения о вызове инструмента

- **Статус:** accepted
- **Дата:** 2026-11-18
- **Контекст:** `openspec/changes/policy-engine/`, бэклог `docs/BACKLOG-NEXT.md`, раздел A1
- **Заменяет частично:** ADR 0017 (таблица режимов и функция `decide`)

## Контекст

Режим разрешений (ADR 0017) работал только там, где инструмент сам вызывал
`approve`: `write_file`, `edit_file`, `run_shell`, `memory_append`. Аудит кода
показал, что этого недостаточно:

- MCP-инструменты вызывались напрямую (`agent.js`, `mcp.call`), без проверки.
  В режиме «План» и «Вручную» MCP-сервер файловой системы мог записать файл
  без вопроса.
- Плагин сам решал, вызывать ли `approve`.
- В `chat.completions` MCP-схемы уходили как `undefined`: `mcp.toolSchemas()`
  отдавал схему без обёртки `{ schema }`.
- `run_shell` с параметром `cwd` выходил за пределы проекта.
- Режим «Авто» разрешал всё, без правил и без журнала.
- Ответ пользователя был только «да/нет»: каждый `git status` — вопрос.

## Решение

Решение о вызове принимает **PolicyEngine** (`electron/lib/policy.js`), а
применяет **`runToolCall`** (`electron/lib/tool-runner.js`) в цикле агента.
Инструменты больше не вызывают `approve`.

**Классы действий.** Встроенные инструменты — по таблице; MCP — `read` только
при `annotations.readOnlyHint === true`, иначе `external`; плагин — по полю
`kind`, без него `external`. Плагин не может занять имя встроенного инструмента.

**Порядок проверки:**

1. guardrails (для команд);
2. правила `deny`;
3. режим «План» — всё, кроме `read`, запрещено;
4. правила `ask`;
5. класс `read` — разрешено;
6. правила `allow` (для составной команды правило должно покрыть каждую часть,
   подстановка `$(…)` правилом не покрывается);
7. режим.

| Режим | read | write | memory | exec | external |
|---|---|---|---|---|---|
| `manual` (Вручную) | да | спросить | спросить | спросить | спросить |
| `acceptEdits` (Принимать правки) | да | да | спросить | спросить | спросить |
| `plan` (План) | да | запрет | запрет | запрет | запрет |
| `dontAsk` (Только разрешённое) | да | запрет | запрет | запрет | запрет |
| `bypass` (Без вопросов) | да | да | да | да | да |

Правила `allow` / `ask` / `deny` меняют ячейку таблицы. Синтаксис:
`инструмент` или `инструмент(маска)`, например `run_shell(npm test*)`,
`write_file(src/**)`, `mcp__github__*`. Источники: `settings.permissions`
(глобально, меняет только admin) и `session.permissionRules` (чат).

**Режим «Без вопросов».** Прежний `auto` переименован в `bypass`: сохранённое
значение `auto` читается как `bypass`, поведение пользователя молча не
меняется. Режим помечен предупреждением и недоступен роли `guest`: main
понижает его до `manual` (решение D2, предварительное). Новый «Авто» с
классификатором — отдельная задача (бэклог CC2.2), с новым id.

**Ответ пользователя.** Запрос содержит класс, риск, причину риска,
рекомендацию (`deny` для высокого риска) и подсказку правила. Ответы:
«Да», «Да, и не спрашивать: <правило>» (чат или всегда), «Нет» с пояснением,
которое уходит модели в результате инструмента.

**Журнал.** Каждое решение пишется в `%APPDATA%/mai-code/audit.jsonl`
(ротация на 5 МБ, секреты маскируются). IPC `permissions:audit` — только admin.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Оставить `approve` в инструментах, добавить его в MCP и плагины | Мало кода | Новый источник снова можно забыть; правила пришлось бы повторять в каждом | Не устраняет причину |
| Проверка в IPC-слое main | Близко к границе процесса | Цикл агента и инструменты живут в main, IPC их не видит | Не та граница |
| Классификатор моделью для каждого вызова | Гибко | Задержка и стоимость на каждом шаге, недетерминизм | Пойдёт в новый «Авто» поверх правил, не вместо |

## Последствия

- Любой новый инструмент автоматически проходит проверку; класс `external`
  по умолчанию безопасен.
- MCP с аннотацией `readOnlyHint` работает в «Плане» и без вопросов.
- Плагины старого формата работают: их вызов `ctx.approve` получает `true`,
  потому что разрешение уже выдано. Плагину с действиями без `kind` теперь
  задаётся вопрос.
- `edit_file` получил `precheck`: если фрагмента нет, пользователя не спрашивают.
- Правила проекта (`.mai-code/settings.json`) пока не читаются: их можно
  подложить в чужой репозиторий. Появятся вместе с доверием к папке (бэклог A2.3).
- Внешние рантаймы (CLI) PolicyEngine пока не проходят — бэклог A4.1.
- Проверки: `scripts/test-policy.mjs`, `scripts/test-permissions-integration.mjs`
  (матрица «режим × источник» с проверкой файла на диске),
  `scripts/test-agent-loop.mjs`, раздел [14] `scripts/test-ui.mjs`.
