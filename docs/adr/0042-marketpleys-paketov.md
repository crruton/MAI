# 0042. Маркетплейс пакетов

- **Статус:** accepted
- **Дата:** 2026-11-21
- **Контекст:** бэклог CC10.2, CW6.1

## Контекст

Пакеты (ADR 0037) ставились по одному из папки или git-URL. Команде нужен
общий список «что у нас есть»: какие пакеты, какой версии, что вышло новое.
Узнать об обновлении можно было, только переустановив пакет вручную.

## Решение

`electron/lib/marketplace.js`. Каталог — git-репозиторий или папка с
`mai-marketplace.json`:

```json
{
  "name": "team",
  "description": "Пакеты команды",
  "packages": [
    { "name": "review-kit", "version": "1.3.0", "description": "Ревью кода", "source": "packages/review-kit" },
    { "name": "git-kit", "version": "0.4.0", "source": "https://git.example.com/git-kit.git", "ref": "v0.4.0" }
  ]
}
```

- `source` — папка внутри каталога (выход через `..` отбрасывается) или git-URL;
  `ref` — тег или ветка (`git clone --depth 1 --branch`), без опций git.
- Каталоги — `settings.marketplaces: [{ name, url }]`. Каталог из git
  кешируется клоном в `<данные>/marketplaces/<имя>/`; «Обновить каталоги»
  клонирует заново во временную папку и заменяет кеш только при успехе.
- Окно `/packages` → «Каталоги»: пакеты каталога, установленная версия,
  «Установить» / «Обновить» (версия каталога новее установленной; сравнение
  semver, предрелиз меньше релиза).
- Установка — `installPackage` (ADR 0037) с проверкой: имя и версия в
  `mai-package.json` источника должны совпасть с записью каталога, иначе отказ.
  Источник пакета записывается в `settings.packages.<имя>.origin`.
- Добавить и убрать каталог, обновить, установить — только admin; добавление
  каталога и установка пишутся в журнал решений.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Центральный сервер-реестр | Поиск, статистика | Нужен сервер и его поддержка | Git уже есть у каждой команды; приватный каталог — приватный репозиторий |
| npm как реестр | Версии, зависимости | `postinstall`, нужен npm, публикация | Как в ADR 0037: копирование без скриптов установки |
| Автообновление пакетов | Всегда свежие | Новая версия кода исполняется без ведома пользователя | Обновление — кнопкой, с видимой версией |

## Последствия

- Подписи пакетов нет: доверие — к репозиторию каталога и источникам пакетов.
  Совпадение имени и версии защищает от ошибок каталога, а не от владельца
  источника.
- Зависимостей между пакетами нет.
- Наборы по ролям (CW6.1) публикуются как каталог.
- Проверки: `scripts/test-marketplace.mjs` (31: локальный и git-каталоги,
  обновление кеша, версии, подмена имени и версии, выход из каталога, `ref`),
  раздел [29] `test-ui`.
