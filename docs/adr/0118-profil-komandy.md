# 0118. Профиль команды: каталоги, MCP, AGENTS.md и workspace из одного репозитория

- **Статус:** accepted
- **Дата:** 2026-11-26
- **Контекст:** [бэклог командной работы](../BACKLOG-TEAM.md) E2.2, уровни настроек (ADR 0038), каталоги (ADR 0042, 0111), workspace Multica (ADR 0112), роли (ADR 0117)

## Контекст

Новый участник команды настраивает MAI руками: подключает каталоги, MCP-серверы, пишет
глобальный `AGENTS.md`, ищет workspace Multica. У каждого получается своя конфигурация, и
агенты работают по-разному. Настройки организации (`managed-settings.json`) задают правила и
вход, но не содержимое для работы.

## Решение

- **Профиль** — git-репозиторий или папка с `mai-team.json`: `name`, `marketplaces`,
  `mcpServers`, `agents` (путь к `AGENTS.md` команды), `multica.workspaceId`. Формат — в
  [TEAM.md](../TEAM.md).
- **Адрес** — `teamProfile` в настройках организации; без них — в настройках MAI (их меняет
  только admin). Организация сильнее.
- **Слой, а не перезапись.** Профиль не пишется в `settings.json`. Каталоги подмешиваются к
  личным (личный с тем же именем сильнее), MCP — слой ниже глобального, `AGENTS.md` команды —
  раздел системного промпта перед личным глобальным, workspace — значение по умолчанию ниже
  личного и проектного (ADR 0112). Окно «Добавить/убрать каталог» работает только с личными.
- **Без секретов.** Заголовки и `env` MCP — только `${ПЕРЕМЕННАЯ}`; сканер каталога (ADR 0111)
  проверяет профиль и `AGENTS.md` команды. Любая ошибка — профиль не применяется целиком.
- **Обновление:** при запуске (кэш сразу, git в фоне), после входа через Keycloak, IPC
  `team:refresh` (developer). Клон — во временную папку, кэш заменяется только при успехе.
  Применение пишется в журнал решений.
- **Модуль** `electron/lib/team-profile.js` без Electron; IPC `team:status` (ANY),
  `team:refresh` (DEVELOPER); строка о профиле в окне «Доступ».

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Всё в `managed-settings.json` | один файл | файл кладёт администратор машины, команда его не правит через MR | профиль — репозиторий команды с ревью |
| Писать профиль в `settings.json` пользователя | просто | личные правки теряются при обновлении, не понять, что откуда | слой с явным источником |
| Профиль как пакет (ADR 0037) | готовая установка | пакет не задаёт каталоги, workspace и глобальные инструкции | отдельный формат с узким набором полей |

## Последствия

- Проще: участник входит через Keycloak и получает каталоги, MCP, правила и workspace команды.
- Сложнее: изменения профиля приходят всем при следующем обновлении; ревью профиля — через MR
  в его репозиторий.
- Проверено: формат, отказ при секретах, git-клон и сохранение кэша при ошибке, слияние
  каталогов, строка в окне «Доступ». Не проверено: приватный репозиторий профиля и живой вход.
