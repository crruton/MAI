# 0041. OAuth для удалённых MCP-серверов

- **Статус:** accepted
- **Дата:** 2026-11-20
- **Контекст:** бэклог CC9.2, CW3.1

## Контекст

Удалённые MCP-серверы (HTTP) подключались только с заголовками из
`settings.json`: токен нужно было получить где-то ещё и вставить руками, и он
лежал рядом с настройками. Большинство публичных MCP-серверов (почта,
трекеры, вики) требуют OAuth 2.1 со входом в браузере. Без этого каталог
коннекторов (CW3.1) невозможен.

## Решение

`electron/lib/mcp-oauth.js` и `McpManager` (`electron/lib/mcp.js`) на базе
`OAuthClientProvider` из `@modelcontextprotocol/sdk`:

- Сервер ответил 401 — статус **«нужен вход»**. Браузер сам не открывается
  (ни при запуске, ни при фоновой синхронизации): вход начинается только кнопкой
  «Войти» в окне «MCP».
- «Войти»: приложение поднимает приём кода на `http://127.0.0.1:33418/callback`
  (только loopback; порт — `oauth.callbackPort`), SDK находит сервер
  авторизации (RFC 9728/8414), регистрирует клиента (DCR, публичный клиент без
  секрета), открывает страницу входа в системном браузере с PKCE S256 и
  случайным `state`. Возврат с чужим `state` отклоняется. Код обменивается на
  токены, сервер подключается заново. Ожидание — до 5 минут.
- Страница входа принимается только по HTTPS (или loopback для разработки).
- Токены, регистрация клиента и PKCE verifier — в `<данные>/mcp-oauth.json`,
  каждая запись зашифрована хранилищем ОС (secretBox, ADR 0031), файл `0600`.
  Обновление токена по refresh_token делает SDK.
- Токены привязаны к адресу сервера: сменился `url` — старые не отправляются.
- «Выйти» удаляет токены и регистрацию. `"oauth": false` в настройках сервера
  выключает OAuth (тогда 401 — ошибка с подсказкой про `headers`).
- Вход и выход — только admin; вход пишется в журнал решений.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Окно Electron для входа | Не нужен браузер | Пароли вводятся в окне приложения; SSO и менеджеры паролей не работают; против рекомендаций RFC 8252 | Системный браузер |
| Случайный порт для возврата | Нет конфликта портов | При DCR адрес возврата регистрируется; новый порт — новая регистрация каждый раз | Постоянный порт, настраиваемый; при смене — перерегистрация |
| Токены в `settings.json` (`headers`) | Уже работает | Не обновляются, видны в настройках | Отдельный зашифрованный файл; `headers` остаются для серверов без OAuth |
| Открывать вход автоматически при 401 | Меньше кликов | Браузер выпрыгивает при запуске из-за любого сервера в настройках | Явная кнопка |

## Последствия

- Каталог коннекторов (CW3.1) может опираться на этот вход.
- Предварительно зарегистрированные клиенты (без DCR, с `client_id` от
  администратора) пока не поддержаны — следующий шаг.
- Проверки: `scripts/test-mcp-oauth.mjs` (24: полный вход против локального
  MCP-сервера с DCR, PKCE и проверкой `state`, повторное подключение после
  перезапуска, смена адреса, выход), раздел [28] `test-ui`.
