# 0067. PDF из Markdown через Chromium

- **Статус:** accepted
- **Дата:** 2026-11-22
- **Контекст:** бэклог CW2.4; продолжение ADR 0049 и 0066

## Контекст

Агент создавал DOCX, XLSX и PPTX, но не PDF — самый частый формат «на отправку»
(«сделай из заметок PDF для клиента»). Читать PDF он умел (вложения, ADR 0030).
Собственный писатель PDF с кириллицей требует встраивания шрифтов и разметки
текста — это большой объём кода. В Electron уже есть Chromium, который печатает
HTML в PDF с нормальной вёрсткой, переносами и любыми шрифтами системы.

## Решение

- `electron/lib/export/html.js` — `markdownToHtml(markdown, { title })`: тот же
  разбор Markdown (`export/markdown.js`), экранирование текста, встроенный CSS
  для A4 (поля, таблицы с рамками, код моношрифтом, разрыв страниц не режет
  строки таблиц), `<meta>` CSP `default-src 'none'; style-src 'unsafe-inline'`.
- `electron/lib/pdf-render.js` — `renderPdf(BrowserWindow, html)`: скрытое окно
  без JavaScript, в песочнице и в отдельной сессии `mai-pdf-render`; CSP
  вставляется в любую страницу (`withCsp`), сетевые и файловые запросы сессии
  отменяются (фильтр без `data:` — перехват самой страницы ломает загрузку),
  переходы запрещены. Страница грузится как `data:`-URL, затем `printToPDF`
  (A4, фон печатается). Таймауты на загрузку и печать; окно закрывается штатно,
  `destroy` — запасной путь. Модуль не импортирует Electron: `BrowserWindow`
  передаёт main.
- `create_document` с `.pdf` — из `markdown`; `renderPdf` приходит в контекст
  инструмента из настроек агента (`agentSettings.renderPdf` в main). Без него
  (тесты на чистом Node, внешний запуск) — понятный отказ «PDF создаётся только
  в приложении». В запросе разрешения — текст будущего документа.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Свой писатель PDF | Работает и вне Electron | Шрифты с кириллицей, переносы, таблицы — много кода | Chromium уже в приложении |
| pdfkit / pdf-lib | Готовые | Зависимость, шрифты всё равно встраивать | ADR 0049 — без библиотек |
| DOCX → PDF через LibreOffice | Единый путь | LibreOffice есть не у всех | Нельзя рассчитывать |

## Последствия

- Объединение PDF и заполнение форм не поддержаны (часть CW2.4 — дальше).
- Картинки в PDF не попадают: внешние ресурсы закрыты намеренно.
- Electron завершает приложение, когда закрыто последнее окно: если главное
  окно уже закрыто, после печати приложение выйдет — как и без PDF.
- Проверки: `scripts/test-pdf.mjs` (Electron): HTML и CSP; PDF с кириллицей и
  таблицей (текст сверяется `pdftotext`, если он есть); страница с внешними
  картинкой и стилем не делает ни одного запроса к локальному серверу;
  `create_document` с `.pdf` и отказ без Chromium.
