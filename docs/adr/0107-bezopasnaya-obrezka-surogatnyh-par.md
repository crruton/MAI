# 0107. Безопасная обрезка текста: границы суррогатных пар

- **Статус:** accepted
- **Дата:** 2026-11-24
- **Контекст:** сессия `923a2ccc` перестала отвечать после `400 Invalid JSON payload: no low surrogate in string`

## Контекст

Сессия MAI Code перестала работать: каждый запрос к модели возвращал
`400 Invalid JSON payload received. Unexpected end of string ... no low surrogate
in string`. Ошибка повторялась на любом сообщении, включая «привет», и не
проходила после перезапуска приложения.

Причина — в файле сессии. В `messages[749]` лежал одиночный high surrogate
`U+D83C`: начало эмодзи, у которого потерялась вторая половина. `JSON.stringify`
кодирует такой символ как `\ud83c` — формально валидный JSON, но невалидный
UTF-8. Шлюз на protobuf отвергает всю строку, а история отправляется целиком,
поэтому один обрывок ломал все следующие запросы.

Откуда обрывок: `String.prototype.slice` режет по кодовым единицам UTF-16.
Любая обрезка «до N символов» может попасть между половинами суррогатной пары.
В коде таких мест много: лимит вывода инструмента (`spillOutput`), снимок
страницы браузера, память в промпте, результаты, OCR, документы.

## Решение

Модуль `electron/lib/text-safe.js` (без Electron):

- `safeSlice(text, limit)` и `safeTail(text, limit)` — обрезка по границе
  символа: если граница попала внутрь пары, она сдвигается на одну единицу.
- `sanitizeText(text)` — одиночные суррогаты заменяются на `U+FFFD`; целые пары
  сохраняются.
- `hasLoneSurrogate(text)` — проверка для тестов и диагностики.
- `sanitizeMessages(messages)` — санитайз сообщений API: `content` (строка и
  части), `name`, аргументы `tool_calls`. Вход не меняется.

Применение:

- `agent.js::buildRequest` — `sanitizeMessages` после маскирования секретов и
  перед отправкой. Это последний рубеж: даже если обрывок попал в историю с
  диска (старая версия, импорт чата, плагин), запрос уйдёт.
- `tool-runner.js::spillOutput` — `safeSlice`/`safeTail` вместо `slice`.
- `browser-agent.js` — функция `cut` внутри скриптов снимка страницы.

### Дополнение: санитайз на уровне клиента и при загрузке сессии

Первый заход закрыл только цикл агента. Повторный разбор показал две дыры:

1. Мимо `buildRequest` идут побочные вызовы модели: компакция
   (`completeOnce`), ревизор, калибратор, диаграмма, заголовок и урок. Каждый
   режет текст своим `.slice` и отправляет запрос напрямую.
2. История читается с диска как есть. Сессия, записанная старой версией,
   приносит обрывок обратно — и он снова ломает все запросы.

Поэтому санитайз опущен на два уровня ниже:

- `electron/lib/safe-client.js::withTextSafety(client)` — обёртка клиента
  провайдера. Через `Proxy` перехватывает `chat.completions.create` и
  `responses.create` и чистит тело запроса: `messages`, `instructions`, `input`
  (строка и части), `tools`, имена и аргументы вызовов. Остальные свойства
  клиента (`models`, `files` и прочие) проходят как есть. Обёрнуты все места
  создания клиента: `agent.js` (основной, плановый, запасной, ревизор,
  компакция, заголовок, урок), `calibrator.js`, `diagram-agent.js`.
- `session-store.js::getSession` — `sanitizeMessages` при чтении сессии. Файл на
  диске не переписывается, но в приложение история попадает уже чистой.

Плюс закрыты оставшиеся точки обрезки, которые питают запрос: `context.js`
(компакция), `reviewer.js`, `calibrator.js::buildContext`, `diagram-agent.js`,
`memory-limits.js`, `mcp.js` (ресурсы), `ocr.js`, `attachments.js`,
`tool-runner.js` (превью аргументов, `PostToolUse`), `agent.js` (заголовок,
урок, субагент, хук Stop, проверка ответа).

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Чинить только файл сессии | Быстро | Дефект остаётся, повторится на следующем эмодзи | Лечит симптом |
| Заменить все `slice` на `Array.from` | Просто читается | Массив кодовых точек на 30 000 символов — лишняя память и копирование | Точечные хелперы дешевле |
| Санитайз только при записи сессии | История на диске чистая | Запросы из уже испорченных сессий и из импорта всё равно падают | Нужен рубеж перед отправкой |
| Убрать эмодзи из текста целиком | Гарантия | Теряется смысл текста пользователя | Замена на U+FFFD достаточно |

## Последствия

- Обрезка может вернуть на один символ меньше лимита — это допустимо.
- Одиночный суррогат в тексте пользователя превращается в `�`; целые эмодзи
  не страдают.
- Старые испорченные сессии чинятся сами при следующей отправке; файл на диске
  остаётся как был (история не переписывается).
- Проверки: `node scripts/test-text-safe.mjs` (36 проверок: границы, хвост,
  санитайз, JSON-escape, сообщения API, `spillOutput`, обёртка клиента для
  `chat.completions` и `responses`); `node scripts/test-sessions.mjs` (24
  проверки, включая загрузку сессии с обрывком с диска); оба входят в `npm test`.
