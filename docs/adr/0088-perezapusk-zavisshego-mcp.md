# 0088. Перезапуск зависшего MCP-сервера Repowise

- **Статус:** accepted
- **Дата:** 2026-11-23
- **Контекст:** бэклог F13; [REPOWISE](../REPOWISE.md), MCP (ADR 0071)

## Контекст

`repowise serve --no-ui` (0.60) иногда перестаёт отвечать: вызов инструмента
висел 120 с и падал, а сервер так и оставался «подключён» — каждый следующий
запрос агента тоже ждал до таймаута. В окне не было видно, что сервер завис.

## Решение

- `McpManager` помнит конфигурацию сервера. Вызов инструмента ждёт
  `callTimeoutMs` (по умолчанию 120 с). Таймаут у stdio-сервера — перезапуск
  процесса (`restart`): закрыть и подключиться заново той же конфигурацией.
- Повтор вызова после перезапуска — один раз и только для инструментов «только
  чтение» (`readOnlyHint`) или при `retryOnTimeout: true`; иначе ошибка
  «…сервер перезапущен — повторите запрос», чтобы запись не выполнилась дважды.
  `restartOnTimeout: false` отключает перезапуск.
- `checkHealth(name)` — `ping` с таймаутом 10 с; нет ответа — перезапуск.
- `status()` — `restarts`, `lastRestartAt`, `lastTimeout` (время и причина).
- Repowise: `mcpConfig` — `callTimeoutMs: 60000`, `restartOnTimeout`,
  `retryOnTimeout` (инструменты индекса только читают). Конфиг, сохранённый
  раньше, дополняется при проверке состояния.
- Окно «Хранилище» → Repowise: карточка «MCP-сервер» — отвечает / не запущен /
  ошибка, число перезапусков, последний и его причина, кнопка «Перезапустить»
  (IPC `repowise:restartMcp`, admin). «Проверить» шлёт ping (`repowise:status`).

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Фоновый ping по таймеру | Видно до запроса | Процессы и шум ради редкого сбоя | Проверка при запросе и по «Проверить» |
| Повторять любые инструменты | Проще | Повтор записи у сторонних серверов | Только чтение или явный флаг |
| Только для repowise | Узко | Зависнуть может любой stdio-сервер | Общий механизм, у repowise короче таймаут |

## Последствия

- Зависание стоит одного ожидания (60 с для repowise) вместо таймаута на каждый запрос.
- Сервер, который зависает всегда, перезапускается один раз на вызов, без цикла.
- Проверки: `test-mcp-restart` (тестовый stdio-сервер `mcp-hang-server.mjs`) —
  повтор чтения, отказ повтора записи, `retryOnTimeout`, `restartOnTimeout: false`,
  «всегда зависает», ping занятого процесса, ручной перезапуск, конфиг repowise;
  `test-ui` [50] — карточка MCP и «Перезапустить».
