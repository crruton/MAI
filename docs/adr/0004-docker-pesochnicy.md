# 0004. Docker-песочницы с публикацией портов

- **Статус:** accepted
- **Дата:** 2026-11-04

## Контекст

Песочница-папка изолирует файлы проекта, но не процессы и сеть. Агенту нужна
возможность запускать сервис и открывать порт, не давая доступа ко всей машине.

## Решение

Добавлен режим Docker-песочницы (`electron/lib/container.js`):

- папка проекта монтируется в `/workspace`;
- контейнер запускается от непривилегированного пользователя;
- порты публикуются только явно указанные пользователем (`127.0.0.1:host:container`);
- сеть по умолчанию `bridge`, опция `none` для полной изоляции;
- лимиты CPU/памяти и `--read-only` для корневой ФС (кроме `/workspace` и `/tmp`);
- имя контейнера: `mai-code-<slug>`, метки для поиска и остановки.

Песочница-папка остаётся режимом по умолчанию: Docker требует установленного
Docker Desktop/Engine и прав на запуск контейнеров.

## Альтернативы

| Вариант | Плюсы | Минусы |
|---|---|---|
| Только папка | Ноль зависимостей | Нет изоляции процессов |
| Docker | Изоляция и порты | Нужен Docker, медленный старт |
| VM | Сильнее изоляция | Тяжело, отдельный гипервизор |

## Последствия

- На Windows нужен Docker Desktop с WSL2.
- Порт публикуется на `127.0.0.1`, а не на все интерфейсы — меньше риска.
- Образ выбирает пользователь; по умолчанию `node:22-alpine`.
- Ограничение: Docker-сокет не пробрасывается внутрь контейнера.
