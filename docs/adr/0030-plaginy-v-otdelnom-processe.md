# 0030. Плагины в отдельном процессе, песочница окон и CSP

- **Статус:** accepted
- **Дата:** 2026-11-19
- **Контекст:** бэклог A2.4, A2.5

## Контекст

- Плагины импортировались в main-процесс. Доверенный плагин видел память main
  (расшифрованные ключи провайдеров и токены), Electron API, IPC окон и всё
  окружение процесса. Зависший плагин вешал приложение, упавший — ронял его.
- Окна работали с `sandbox: false` и без CSP. В окне досок значения из
  `boards.json` и индекса артефактов проекта (приоритет задачи, статус стадии,
  номер версии) вставлялись в HTML без экранирования: файл из чужого
  репозитория мог внедрить разметку в окно с полным IPC.

## Решение

**Плагины.** `electron/plugin-host/worker.mjs` запускается через
`utilityProcess.fork`, `electron/lib/plugin-host.js` управляет им:

- main получает манифест (схемы, `kind`, наличие хука), код плагина в main не
  исполняется;
- вызов инструмента и `transformMessages` — сообщения с таймаутом
  (загрузка 15 с, вызов 120 с, хук 10 с); по таймауту хост убивается;
- окружение хоста — без переменных с `KEY`, `TOKEN`, `SECRET`, `PASSW`, `AUTH`,
  `CREDENTIAL`, `COOKIE`, `SESSION`, `PRIVATE`;
- хост переиспользуется, пока не изменились файлы плагинов.

`transformMessages` стал асинхронным для цикла агента; плагины старого формата
работают без изменений, их вызов `ctx.approve` получает `true` (ADR 0027).

**Окна.** `sandbox: true` у главного окна и окон досок; CSP
`default-src 'self'; script-src 'self'; object-src 'none'; base-uri 'none'`,
стили inline разрешены для Mermaid. Модуля `clipboard` в песочнице нет —
запись через IPC `app:clipboard`. Неэкранированные подстановки в `board.js`
исправлены.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Модель разрешений Node (`--permission`) для хоста | Ограничила бы файлы и процессы | В `utilityProcess` Electron 38 не включается (проверено) | Недоступно |
| Плагины в Docker | Настоящая изоляция | Docker обязателен, задержка на каждый вызов | Позже, как режим для недоверенных плагинов |
| Worker thread в main | Просто | Тот же процесс и память | Не изолирует |

## Последствия

- Утечка ключей из памяти main через плагин закрыта; ключи из
  `settings.json` на диске плагин прочитать по-прежнему может — поэтому
  шифрование ключей (бэклог CC13.7) поднимается в приоритете.
- Ошибки плагина — сообщения об ошибке, а не падение приложения.
- Внедрённая в данные проекта разметка не выполняется дважды: экранирование
  и CSP.
- Проверки: `scripts/test-plugin-host.mjs` (25 проверок: другой процесс,
  отсутствие ключей и Electron API, зависание, падение, перезапуск),
  раздел [16] `scripts/test-ui.mjs` (CSP, песочница, задача с
  `<img onerror>` в `boards.json`).
