# 0013. Внешние рантаймы в отдельных контейнерах

- **Статус:** accepted
- **Дата:** 2026-11-06

## Контекст

Пользователь спросил, запускаются ли DeepSeek Harness и Hermes в отдельных
контейнерах. Раньше все внешние CLI запускались как host-процессы: это просто,
но не даёт изоляции и лимитов. Готовых образов с этими CLI нет.

## Решение

Добавить рантайму режим `mode: host | docker`:

- `host` — текущее поведение, CLI на машине;
- `docker` — `docker run` с указанным пользователем образом, папка проекта в
  `/workspace`, сеть `bridge`, лимиты памяти/CPU, `cap-drop ALL`,
  `no-new-privileges`, `tmpfs /tmp`.

Образ обязателен. MAI Code не собирает образы автоматически и не поставляет
образы для `dsh`/Hermes. Пока образа нет, пресеты работают в host-режиме.

Добавлена проверка `runtimes:probe`: для host — `where`/`which`, для docker —
`docker image inspect`. Добавлен параллельный запуск `runtimes:runMany`.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Только host | Просто | Нет изоляции | Не отвечает на запрос |
| Собирать образы в MAI Code | Удобно | Сложно, нужен Dockerfile на каждый CLI | Слишком много поддержки |
| Пользовательский образ | Гибко | Пользователь готовит образ | Выбран |

## Последствия

- Пользователь может запускать любой CLI в контейнере, если есть образ.
- Папка проекта всё равно смонтирована: файлы не изолированы.
- Guardrails встроенного агента не действуют внутри контейнера.
- Нужно документировать, что docker-режим — не «песочница из коробки».
