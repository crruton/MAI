# 0083. PDF: объединение, выборка страниц и формы (pdf-lib)

- **Статус:** accepted
- **Дата:** 2026-11-23
- **Контекст:** бэклог CW2.4 (остаток); продолжение ADR 0067 (PDF из Markdown); исключение из ADR 0049

## Контекст

Агент создавал PDF из Markdown и читал текст PDF, но не мог собрать договор из
нескольких файлов, вырезать нужные страницы или заполнить анкету — частые
задачи Cowork. Это правка структуры PDF: перекрёстные ссылки, потоки объектов,
поля AcroForm, внешний вид полей. Своим кодом это долго и рискованно.

## Решение

Библиотека **pdf-lib 1.17.1** (MIT, чистый JS, без нативных частей, работает
офлайн) — осознанное исключение из правила ADR 0049 «документы без
библиотек». Решение пользователя от 23.11.2026. В сборку идёт только `cjs/`
(браузерные сборки, исходники и типы исключены в `electron-builder.yml`).

`electron/lib/tools/pdf.js`:
- **`pdf_merge({ inputs: [{ path, pages }], output })`** (write) — страницы
  входных файлов по порядку в новый PDF; `pages` — «1-3,5,8-» (пусто — все),
  так же вырезаются страницы из одного файла. Итог не может совпадать с
  входным файлом, исходники не меняются. Зашифрованный PDF — понятный отказ.
- **`pdf_fields({ path })`** (read) — поля формы: имя, тип (текст, флажок,
  список, переключатель), текущее значение, варианты.
- **`pdf_form({ path, values, output, flatten })`** (write) — заполнение:
  текст, флажок (`true/да/yes/1`), вариант списка без учёта регистра (нет
  варианта — ошибка с перечнем). По умолчанию итог — «<имя> (заполнено).pdf»
  рядом, исходник не меняется. Отсутствующие поля названы в ответе.
  `flatten` — поля становятся обычным текстом.
- **Кириллица в полях**: стандартные шрифты PDF (WinAnsi) её не рисуют. Такое
  значение пишется в поле напрямую, ставится `NeedAppearances`, а внешний вид
  при сохранении не пересчитывается — текст рисует просмотрщик своим шрифтом
  (Acrobat, браузеры, Foxit). `flatten` в этом случае не выполняется (в ответе
  сказано).
- Политика: предмет правила — итоговый файл (`pdf_merge(папка/**)`), в запросе
  разрешения — какие файлы и страницы, сколько полей. Промпт «Задачи» знает
  про `pdf_merge`, `pdf_fields`, `pdf_form`.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Свой разбор PDF | Без зависимостей | Потоки объектов, шифрование, AcroForm — долго и хрупко | Риск порчи документов |
| qpdf / pdfunite / pdftk | Зрелые | Нет у большинства пользователей, особенно на Windows | Не везде работает |
| pdf-lib + fontkit и свой шрифт | Кириллица «вплавлена» | Ещё зависимость и шрифт в сборке | NeedAppearances хватает просмотрщикам |

## Последствия

- Зависимость ~3.4 МБ в сборке (`cjs/`); `npm audit` отслеживает её вместе с
  остальными.
- Кириллица в полях не вплавляется при `flatten`; печатные формы без полей
  (сканы) заполнять нельзя — только создать новый PDF.
- Проверки: `scripts/test-pdf-tools.mjs` — разбор страниц и ошибки,
  объединение A(1,3)+B, вырезка страницы, отказ при совпадении итога и
  входа, нет файла; поля и PDF без формы; заполнение латиницей (текст, флажок,
  вариант), кириллицей (значение, `NeedAppearances`, названное отсутствующее
  поле), нет варианта, flatten, без values; классы, предмет правила, подсказка
  правила, текст запроса.
