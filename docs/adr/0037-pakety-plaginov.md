# 0037. Пакеты плагинов

- **Статус:** accepted
- **Дата:** 2026-11-20
- **Контекст:** бэклог CC10.1

## Контекст

Свои команды, типы субагентов, навыки, плагины, хуки и MCP-серверы лежали
каждый в своей папке. Поделиться набором («ревью кода»: команда `/review`,
агент-ревьюер, хук с линтером) можно было только инструкцией «скопируйте шесть
файлов в шесть мест», а выключить такой набор — только удалением файлов.

## Решение

`electron/lib/packages.js`. Пакет — папка с манифестом `mai-package.json`
(`name`, `version`, `description`) и частями по соглашению: `commands/`,
`agents/`, `skills/`, `plugins/`, `hooks.json`, `mcp.json`.

- Где: `<данные>/packages/<имя>/` (глобальные) и `<проект>/.mai-code/packages/<имя>/`
  (только для доверенной папки, ADR 0028). Пакет проекта сильнее глобального
  с тем же именем.
- Приоритет внутри видов: проект → пакеты → глобальные. Встроенные команды и
  типы агентов не переопределяются; источник — `package:<имя>`.
- Плагины пакета — в том же отдельном процессе (ADR 0030); хуки — в общем
  исполнителе (ADR 0035); MCP-серверы — с рабочей папкой пакета по умолчанию.
- Установка из папки или git-URL (`git clone --depth 1`) копирует пакет без
  `.git` и `node_modules`; существующий — заменяется только явно. Выключение —
  `settings.packages.<имя>.enabled = false`, без удаления файлов. Установка,
  удаление и включение — только admin; установка пишется в журнал решений.
- `/packages` — список с содержимым и источником, флажок включения, удаление,
  установка.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| npm-пакеты | Версии, зависимости | Нужен npm, `postinstall` исполняет код при установке | Копирование папки проще и без скриптов установки |
| Один JS-модуль, который регистрирует всё | Гибко | Код при загрузке; команды и агенты — не Markdown | Части пакета — те же файлы, что и без пакета |

## Последствия

- Маркетплейс (каталог из git-репозитория, обновления) — следующий шаг (CC10.2).
- Пакет с плагинами, хуками или MCP — исполняемый код с правами пользователя;
  окно помечает такие пакеты.
- Проверки: `scripts/test-packages.mjs` (26, включая установку из git),
  раздел [18] `test-agent-loop`, раздел [25] `test-ui`.
