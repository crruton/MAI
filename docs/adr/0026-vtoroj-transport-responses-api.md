# 0026. Второй транспорт к шлюзу: OpenAI Responses API

- **Статус:** accepted; изображения — `input_image`, учёт токенов из `response.completed` (CHANGELOG 0.2.0)
- **Дата:** 2026-11-16
- **Контекст:** модели AgentRouter (`gpt-5.6-sol`, `gpt-6.1-sol`) недоступны агенту

## Контекст

Агент говорил со шлюзом единственным способом — `POST /v1/chat/completions`
через OpenAI SDK (`client.chat.completions.create`). Проверка живых каталогов
дала три факта, которые этот способ ломает:

1. `agentrouter.org` отдаёт `401 unauthorized client detected` всем клиентам,
   кроме тех, чей `User-Agent` похож на клиент Claude Code. С ним же — `200`.
   Шлюз MAI на `User-Agent` не реагирует вообще.
2. Обе живые модели AgentRouter отвечают `400` на `/v1/chat/completions` с
   явным указанием использовать `/v1/responses` (OpenAI Responses API).
3. Те же модели отвергают `temperature`: `400 Unsupported parameter`.

Дополнительно: статические списки моделей в настройках разошлись с реальными
каталогами. В `settings.json` у MAI числилась `Qwen3.5-122B-A10B`, которой в
шлюзе уже нет; у AgentRouter — три модели (`claude-opus-5-5`, `claude-sonnet-5-5`,
`deepseek-v4-flash`), которых в каталоге под этим ключом нет вовсе. Дропдаун
показывал недоступное и не показывал доступное.

## Решение

Транспорт выбирается по факту, а не по конфигурации. Цикл агента остаётся
единым и работает с внутренней chat-формой сообщений; для моделей, которым
нужен Responses API, ход оборачивается в `/v1/responses`.

- `electron/lib/responses.js` — транспорт: `instructions` вместо системного
  сообщения, `input[]` вместо `messages`, плоские `tools` без обёртки
  `function`, `function_call` / `function_call_output` вместо `tool_calls` и
  `role: "tool"`. Стриминг читает дельты (`response.output_text.delta`,
  `response.function_call_arguments.delta`), а если шлюз дельт не дал —
  разбирает готовый объект ответа из `response.completed`.
- `agent.js` при первой же ошибке вида «используйте /v1/responses» повторяет
  тот же шаг новым транспортом и запоминает выбор на всю сессию, чтобы не
  платить 400 на каждой итерации.
- `temperature` не отправляется для `gpt-5+` — по имени модели
  (`supportsTemperature()`), без повторных запросов на отказ параметра.
- `providerUserAgent()` в `config.js`: User-Agent провайдера из настроек,
  иначе по id провайдера, иначе по хосту `baseURL`. Применяется и к SDK
  (`defaultHeaders`), и к прямым `fetch` в `models.js` и `main.js`.
  Заголовки собираются отдельно на каждый клиент — User-Agent основного
  провайдера не перетекает в клиент ревизора.
- Статические списки моделей приведены к реальному каталогу шлюзов.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Только chat/completions, AgentRouter не поддерживать | ничего не менять | модели пользователя недоступны | противоречит задаче |
| Отдельный режим провайдера в настройках («транспорт: responses») | явно | пользователь должен угадать транспорт до первого запроса; модели внутри одного шлюза различаются | выбор по ошибке дешевле и не требует настроек |
| Ретрай «выкинуть неподдерживаемый параметр» по тексту ошибки | ловит любые параметры | лишние запросы и разбор текста ошибки | `temperature` известен заранее — дешевле по имени модели |
| Полный переход на Responses API | один транспорт | MAI и DeepSeek/Qwen работают через chat; Responses у них не покрыт tool calling так же надёжно | ломает то, что уже работает |

## Последствия

- Стало возможным работать с моделями, у которых только Responses API.
- Появился второй путь обращения к шлюзу: его нужно держать в согласии с
  первым при любых изменениях формата сообщений (вложения, reasoning,
  подтверждения). Конвертация сосредоточена в одном модуле именно для этого.
- Детектор транспорта опирается на текст ошибки шлюза. Если формулировка
  изменится, фолбэк не сработает и пользователь увидит исходную 400 —
  это заметно, а не тихо. Проверка: `scripts/test-responses.mjs`, блок [5].
- `supportsTemperature()` — список по префиксу имени; новые поколения GPT
  потребуют дополнить регулярное выражение.
- `agent.js` теперь импортирует `config.js` (а через него `electron`), поэтому
  тесты транспорта держатся на `responses.js` — он без внешних зависимостей.
- `gpt-6-astra` и `claude-haiku-5-5` остаются недоступны: шлюз отвечает
  `503 无可用渠道` — каналов для ключа нет. Это не наша сторона.
