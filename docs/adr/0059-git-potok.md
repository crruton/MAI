# 0059. Git-поток: защита веток, /commit, /review

- **Статус:** accepted
- **Дата:** 2026-11-21
- **Контекст:** бэклог CC11.1, CC11.3, CC11.6

## Контекст

Правило «в `main` — только через PR» держалось на хуке git и защите ветки на
GitHub; в приложении агент мог выполнить `git push origin main`, если команда
разрешена (режим «Без вопросов» или правило `run_shell(git push*)`). Коммит и
ревью агент делал только по свободной просьбе, каждый раз по-разному.

## Решение

- **Защищённые ветки** (`electron/lib/git-guard.js`): в цикле решений, после
  правил и до вопроса, `git push` в защищённую ветку — запрет в любом режиме и
  при любом `allow`, как guardrails. Ловится `origin main`, `HEAD:main`,
  `+main`, `refs/heads/main`, удаление (`--delete main`), `--all`/`--mirror`,
  `git push` без ветки, когда текущая ветка защищена; в составной команде —
  любая часть. Ветки — `settings.protectedBranches` («Настройки» →
  «Защищённые ветки», по умолчанию `main, master`; пусто — выключено; меняет
  admin). Хук-пример `no-push-main.mjs` (ADR 0035) остаётся для CLI и проектов.
- **`/commit [уточнение]`** — агент смотрит `git status`/`diff`/`log`,
  отбрасывает секреты и мусор, показывает сообщение и коммитит одной командой
  `run_shell` (подтверждение — как у любой команды); без push и без правки
  истории. Подпись — `settings.gitAttribution` («Подпись в коммитах»), по
  умолчанию без подписи.
- **`/review [номер PR]`** — ревью текущего `git diff HEAD` или PR (`gh pr diff`),
  только чтение; находки по убыванию важности с `файл:строка`, сценарием и
  исправлением; «серьёзного нет» — честно.
- `/commit` и `/review` можно заменить своей командой проекта или пакета с
  тем же именем (`overridable`) — например, `review-kit` со своим чек-листом.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Правило `deny` по умолчанию | Через общий механизм | Маска не понимает текущую ветку и `git push` без аргументов | Разбор команды |
| Инструмент `git_commit` | Сообщение под контролем | Ещё один инструмент; `run_shell` уже показывает команду целиком | Шаблон для агента |

## Последствия

- Обойти можно, только выключив защиту в настройках (admin) или командой, не
  похожей на `git push` (скрипт). Для полной гарантии остаётся защита ветки на
  сервере.
- Проверки: `scripts/test-git-guard.mjs` (15, в т. ч. запрет в «Без вопросов»
  и при `allow`), раздел [39] `test-ui`.
