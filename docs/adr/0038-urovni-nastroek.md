# 0038. Уровни настроек и панель «Разрешения»

- **Статус:** accepted
- **Дата:** 2026-11-20
- **Контекст:** бэклог CC2.4, CC2.9; решение D2

## Контекст

Правила разрешений было два уровня: глобальные (`settings.json`, только admin)
и правила чата. Команда не могла хранить общие правила проекта в git
(«`npm run lint` можно всегда»), пользователь — личные правила одного проекта,
а организация — запреты, которые пользователь не снимет. По решению D2 режим
«Без вопросов» остаётся, но организация должна уметь его выключить. Увидеть,
какие правила сейчас действуют и почему команда разрешена или запрещена,
было негде.

## Решение

`electron/lib/settings-levels.js`. Пять уровней, как в Claude Code:

| Уровень | Где | Кто меняет |
|---|---|---|
| managed (организация) | `%ProgramData%\mai-code\managed-settings.json`, `/Library/Application Support/mai-code/…`, `/etc/mai-code/…`; путь можно задать `MAI_MANAGED_SETTINGS` | администратор машины, не из приложения |
| user | `settings.json`, поле `permissions` | admin |
| project | `<проект>/.mai-code/settings.json`, в git | команда через git |
| local | `<проект>/.mai-code/settings.local.json`, в `.mai-code/.gitignore` | admin в приложении |
| session | правила чата | любой в своём чате |

- Правила всех уровней объединяются; порядок проверки PolicyEngine прежний
  (ADR 0027): `deny` с любого уровня сильнее любого `allow`, поэтому запрет
  организации не снимается ни правилом, ни режимом «Без вопросов».
- Уровни project и local читаются только для доверенной папки (ADR 0028).
- Файл организации может содержать `permissions`, `hooks` и
  `disableBypassMode: true`. Хуки организации идут первыми и не выключаются в
  приложении. Запрет «Без вопросов» действует везде, где выбирается режим:
  встроенный агент, внешние CLI (ADR 0029), вопросы `ask_user`, выбор режима.
- Файл читается при каждом решении — правка действует без перезапуска.
- В запросе разрешения «Да, и не спрашивать» можно запомнить: в этом чате,
  в этом проекте (только у меня — уровень local), всегда.
- `/permissions` — панель: правила по уровням с источником, удаление для
  уровней chat/local/user, проверка «что будет с этим вызовом» через
  `permissions:explain` (решение, правило, уровень).

### Дополнение 21.11.2026: области MCP-серверов (CC9.5)

MCP-серверы — те же уровни: глобальные (`settings.json`), из пакетов,
проекта (`.mai-code/mcp.json`, в git), «только у меня»
(`.mai-code/mcp.local.json`, строка в `.mai-code/.gitignore`). Позднее сильнее
при одинаковом имени. Проектные и локальные — только для доверенной папки.
В окне «MCP» у сервера видна область, при добавлении можно выбрать «в этом
проекте (только у меня)» (`mcp:saveLocal`, admin).

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Уровень организации через Keycloak (claims) | Централизованно | Нужен сервер и вход; не работает офлайн | Файл на машине раскладывается теми же средствами, что и приложение (GPO, MDM); Keycloak может дополнить позже |
| Приоритет уровней «последний побеждает» | Проще объяснить | Проект мог бы снять запрет организации | `deny` сильнее всего — то же правило, что внутри одного уровня |
| Писать «в этом проекте» в `.mai-code/settings.json` | Один файл | Личные разрешения уходят в git всей команде | Отдельный local-файл, как `settings.local.json` в Claude Code |

## Последствия

- Нельзя «разрешить локально» в недоверенной папке — сначала доверие.
- Правила проекта из git действуют у всех, кто доверил папку: при доверии
  стоит посмотреть `.mai-code/settings.json`.
- Проверки: `scripts/test-settings-levels.mjs` (34), раздел [26] и вариант
  «в этом проекте» в `test-ui`.
