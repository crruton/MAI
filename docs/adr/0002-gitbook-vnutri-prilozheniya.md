# 0002. GitBook-документация внутри приложения

- **Статус:** accepted
- **Дата:** 2026-11-04

## Контекст

Документация лежит в `docs/*.md`, но пользователь видит только README на GitHub.
Нужна обновляемая документация «на уровне приложения и в его стилистике»,
доступная офлайн.

## Решение

Добавлен режим чтения документации внутри приложения:

- main-процесс читает `docs/**/*.md` и `README.md` из `app.getAppPath()`
  (работает и внутри `app.asar`);
- IPC `docs:list`, `docs:read`, `docs:search`;
- окно с тремя колонками: разделы, текст, оглавление страницы;
- поиск по всем файлам с переходом к документу и номером строки;
- относительные пути проверяются: выход за пределы `docs/` запрещён.

GitBook Cloud не используется. `docs/SUMMARY.md` остаётся GitBook-совместимым
оглавлением, а встроенный просмотрщик — собственный рендер Markdown.

## Альтернативы

| Вариант | Плюсы | Минусы |
|---|---|---|
| GitBook Cloud | Готовый UI | Нужен интернет и аккаунт, нет офлайна |
| Открывать файлы в редакторе | Ноль кода | Нет навигации и поиска |
| Собственный просмотрщик | Офлайн, стиль приложения | Нет плагинов GitBook |

## Последствия

- Документация попадает в установщик (`electron-builder.yml`, `docs/**/*`).
- Рендер поддерживает заголовки, списки, код, цитаты, ссылки. Таблицы
  отображаются как обычный текст до отдельной доработки рендера.
- `docs:check` проверяет ссылки и наличие страниц в `SUMMARY.md`.
