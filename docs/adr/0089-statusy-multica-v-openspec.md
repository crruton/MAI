# 0089. Статусы Multica обратно в OpenSpec

- **Статус:** accepted
- **Дата:** 2026-11-23
- **Контекст:** бэклог F14; [MULTICA](../MULTICA.md), [OPENSPEC](../OPENSPEC.md)

## Контекст

Задачи из `openspec/changes/*/tasks.md` уходили в Multica с маркером
`<!-- openspec:<change>:<task> -->`, но закрытие задачи в Multica в `tasks.md` не
возвращалось: галочку приходилось ставить руками, и доска «Доставка» отставала.

## Решение

- `openspec.js`: `parseTaskMarker` (маркер из описания), `statusUpdatesFromIssues`
  (только задачи с маркером; `done`/`completed`/`closed`/`resolved` в любом регистре →
  `[x]`; отменённые — в отчёт без галочки; «в работе» и прочие — без изменений),
  `applyTaskStatuses(projectDir, updates, { dryRun })` — задача ищется по id из
  текста (номер строки мог сдвинуться), меняется только `[ ]` → `[x]` в её строке,
  переводы строк (CRLF) сохраняются, запись через временный файл. Отчёт:
  `marked`, `already`, `missing` (изменение или задача переименованы).
- `multica.pullStatuses(projectDir)` — `issue list` (до 200) → галочки; IPC
  `multica:pullStatuses` (admin). Панель Multica — кнопка «Статусы → tasks.md»,
  отчёт тостом, отменённые в Multica перечисляются отдельно.
- CLI: `node scripts/multica-sync.mjs [папка] --pull`.
- Галочка, поставленная локально, назад не снимается: задача, переоткрытая в
  Multica, остаётся `[x]` — локальная отметка важнее, а снятие стёрло бы работу.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Полная двусторонняя синхронизация (снимать [x]) | Симметрия | Переоткрытие в Multica стирает локальную отметку | Только «готово» → [x] |
| Статусы «в работе» в tasks.md (пометкой) | Больше информации | Формат OpenSpec — только чекбокс | Видно на доске Multica |
| Автоматически после каждого «Синхронизировать» | Меньше кликов | Пишет в репозиторий без явного действия | Отдельная кнопка |

## Последствия

- Задачи, закрытые в Multica, отмечаются одним нажатием; изменения в `tasks.md`
  видны в git и попадают в коммит как обычная правка.
- Проверки: `test-openspec-pull` — маркеры, статусы любого регистра, dryRun, нужная
  строка, CRLF и `*`, missing, повторный запуск; `test-ui` [51] — кнопка и отчёт.
