# 0029. Режим разрешений и передача запроса для внешних CLI

- **Статус:** accepted
- **Дата:** 2026-11-19
- **Контекст:** `openspec/changes/trust-and-runtimes/`, бэклог A4.1, A4.2

## Контекст

- Внешние рантаймы (OpenCode, Claude Code, Codex, Gemini и другие) запускались
  без учёта режима разрешений: режим «План» ничего не значил для CLI.
- Команда собиралась строкой и запускалась через `spawn(line, { shell: true })`.
  На Windows `cmd.exe` раскрывал `%VAR%` в запросе пользователя и обрезал его
  на переводе строки; кавычки экранировались не по правилам cmd.

## Решение

**Режим.** `permissionPlan(runtime, mode)` в `electron/lib/runtimes.js`:

- docker-режим: «План», «Вручную», «Только разрешённое» — проект монтируется
  `:ro`; «Принимать правки» и «Без вопросов» — rw;
- host: флаги из `permissionArgs` пресета (Claude Code `--permission-mode`,
  Codex `--sandbox`, Gemini `--approval-mode`), вставляются в позицию
  `permissionArgsAt`;
- нет флагов для режима — запуск отклоняется до записи сообщения в чат;
  исключение — «Без вопросов».

CLI нельзя спросить посреди работы, поэтому «Вручную» и «Только разрешённое»
для него значат «без действий, требующих подтверждения». Флаги пресета
применяются, только пока команда совпадает с командой пресета.

Группа рантаймов с правом записи в одну папку не запускается (до worktree,
бэклог A4.3).

**Передача запроса.** `spawnPlan(command, args)`:

- POSIX и `.exe` на Windows — `spawn` без shell, аргументы массивом;
- `.cmd`/`.bat` — `cmd.exe /d /s /c` с `windowsVerbatimArguments` и
  экранированием по алгоритму cross-spawn (двойное для `node_modules/.bin`).
  Перевод строки через cmd не передаётся: если пресет объявил `stdin`
  (Claude Code, Codex), запрос идёт через stdin, иначе — одной строкой с
  пометкой в выводе.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Зависимость cross-spawn | Проверенная библиотека | Новая зависимость ради 20 строк; не решает переводы строк | Алгоритм перенесён, тесты рядом |
| Всегда stdin | Нет проблем с cmd | Не все CLI читают запрос из stdin | Только где CLI это умеет |
| Запускать любой CLI в любом режиме с предупреждением | Совместимость | Режим снова «только в интерфейсе» | Ровно то, что чиним |

## Последствия

- OpenCode и другие CLI без флагов в режимах «План», «Вручную», «Принимать
  правки» на хосте больше не запускаются: нужен docker-режим, свои
  `permissionArgs` или «Без вопросов». Это изменение поведения по умолчанию.
- Флаги CLI взяты из их документации; на всех версиях не проверены —
  поле `permissionArgs` редактируется.
- Windows-путь проверен модульными тестами экранирования, а не на Windows.
- Проверки: `scripts/test-runtimes.mjs` (в том числе реальный процесс с
  многострочным запросом, `%PATH%`, `&`, кавычками через аргумент и stdin).
