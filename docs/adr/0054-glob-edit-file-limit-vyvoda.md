# 0054. glob, правка файлов и лимит вывода

- **Статус:** accepted
- **Дата:** 2026-11-21
- **Контекст:** бэклог CC1.1, CC1.2, CC1.3, CC1.13

## Контекст

- Найти файлы по маске агент мог только через `list_files` (дерево) или
  команду оболочки.
- `edit_file` делал одну замену; файл с переводами строк Windows (CRLF) не
  находил фрагмент с `\n` (урок записан в `memory.md`); агент мог править и
  перезаписывать файл, который не читал, — по памяти о его содержимом.
- Длинный вывод обрезался по-разному: у `run_shell` — 24 000 символов и
  «обрезано», у MCP и плагинов — никак.

## Решение

- **`glob(pattern, path?)`** — класс `read`: `**`, `*`, `?`, `{a,b}`; новые
  файлы первыми; `node_modules`, `.git`, сборки пропускаются, если не указаны в
  маске явно; до 500 результатов. Работает и в `@папках` (ADR 0045).
- **`edit_file`**: `replace_all`, массив `edits` (по порядку, атомарно — не
  применилась одна, файл не тронут), фрагмент с `\n` в файле с CRLF приводится
  к переводам строк файла, `old == new` — ошибка.
- **Чтение перед правкой.** В прогоне агента ведётся список прочитанных файлов
  с отметкой времени изменения: `edit_file` и перезапись `write_file`
  существующего файла без `read_file` — отказ «Сначала прочитай»; файл
  изменился после чтения — «прочитай заново». Свои правки отметку обновляют.
  Новые файлы и прямые вызовы инструментов (без прогона) — как раньше.
- **Единый лимит вывода** в `runToolCall` для любого инструмента: длиннее
  30 000 символов — целиком в `<данные>/tool-output/…`, модели — начало, конец
  и путь `@вывод/…`; эта папка подключена к прогону как рабочая, агент
  дочитывает её `read_file`/`grep`. Файлы старше 7 дней удаляются.

### Дополнение: `read_file` для картинок, PDF и двоичных файлов (CC1.3)

- Картинка (png, jpg, gif, webp, до 5 МБ): модель со зрением (ADR 0024, F1)
  получает её в запросе — сообщением с изображением сразу после результатов
  шага. В историю чата это сообщение не пишется (не ломает ходы, чекпоинты и
  откат), у результата инструмента хранится только путь. Модель без зрения
  получает подсказку про OCR.
- PDF — текст (тот же извлекатель, что у вложений) с номерами строк и
  `offset`/`limit`; скан без текста — подсказка про OCR.
- `.docx`/`.xlsx` — подсказка `read_document`; папка — `list_files`/`glob`;
  двоичный файл (нулевой байт в начале) — отказ вместо мусора.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| glob через `fast-glob` | Полный синтаксис | Зависимость ради 40 строк | Своё на нужное подмножество |
| Предупреждать, а не запрещать правку без чтения | Мягче | Модель игнорирует предупреждения | Запрет с понятной причиной: следующий шаг — read_file |
| Хранить длинный вывод в истории | Ничего не теряется | Контекст забивается сразу | Файл + путь |
