# 0113. Навыки каталога → Multica MAI

- **Статус:** accepted
- **Дата:** 2026-11-26
- **Контекст:** [бэклог командной работы](../BACKLOG-TEAM.md) E1.8, каталог (ADR 0111), workspace проекта (ADR 0112)

## Контекст

Каталог навыков (ADR 0111) ставится в MAI через `/packages`. Агенты Multica MAI его не
видят: у Multica своя библиотека навыков в workspace. Копировать навыки руками значит
снова получить расходящиеся копии.

## Решение

- **Команда.** Панель «Multica» → «Навыки → Multica» (сначала план, затем подтверждение) и
  `npm.cmd run multica:skills` (`--dry-run`, `--prune`, `--workspace`, имена навыков).
  Workspace — как у синхронизации задач (ADR 0112).
- **Метка.** Навык из каталога создаётся с `config = { managed_by: "mai-code", version,
  hash, source }`. `hash` — SHA-256 от `SKILL.md` и файлов навыка с путями.
- **План.** Нет в Multica — `create`. Есть, метка наша, версия или хэш другие — `update`.
  Совпадают — ничего. Навык с тем же именем без нашей метки — `conflict`: не меняется,
  попадает в отчёт. Свой навык, пропавший из каталога, — `delete`, только с `--prune` и
  только при отдаче всего каталога.
- **Концы строк.** Хэш и загружаемые файлы — с LF. Иначе checkout на Windows (CRLF) и
  Linux (LF) давал бы разный хэш, и отдача с разных машин гоняла бы навыки по кругу.
- **Загрузка.** Нормализованная копия навыка пишется во временную папку. CLI читает
  `--content-file` относительно неё, поэтому кириллица не идёт через stdin и аргументы.
  Двоичные файлы и файлы больше 512 КБ не отдаются.
- **Модуль** `electron/lib/multica-skills.js` без Electron: вызов CLI передаётся
  параметром. IPC `multica:pushSkills` (ADMIN).

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| `multica skill import --url` с GitHub | одна команда на навык | нет метки и версии, нельзя отличить свой навык от ручного, нет prune | идемпотентность нужна по версии и хэшу |
| Перезаписывать навык с тем же именем | проще | теряются ручные правки в Multica | ручное не трогаем, сообщаем |
| Отдавать через REST Multica | быстрее | REST не стабилен между версиями (ADR 0003) | CLI, как у задач |

## Последствия

- Проще: агенты Multica получают те же версии навыков, что и MAI. Повторный запуск ничего
  не меняет.
- Сложнее: файл, удалённый из навыка в каталоге, остаётся в Multica до удаления навыка;
  чистка файлов — отдельный шаг.
- Не проверено на живом сервере: формат JSON ответов `skill list` и `skill get`, поле
  `config` в `skill list`. Если `list` не отдаёт `config`, он читается через `skill get`;
  навык без `config` считается чужим — это безопасная сторона.
