# 0023. OCR через адаптеры движков, а не через один нативный API

- **Статус:** accepted
- **Дата:** 2026-11-14
- **Контекст:** задача «распознавание текста на изображениях-вложениях»;
  продолжение ADR 0016 (вложения через файлы проекта)

## Контекст

Приложение собирается для Windows, Linux и macOS: `.github/workflows/release.yml`
запускает `electron-builder` в матрице из трёх ОС, `electron-builder.yml` содержит
цели `nsis`/`portable`, `AppImage`/`tar.gz`, `dmg`. То есть дистрибутив для любой
из трёх платформ человек скачает.

При этом у каждой платформы свой движок распознавания текста:

| Платформа | Встроенный движок | Доступ из Node |
|---|---|---|
| Windows 10/11 | `Windows.Media.Ocr` (WinRT) | только через PowerShell-мост |
| macOS | Vision (`VNRecognizeTextRequest`) | только через Swift/ObjC |
| Linux | нет | нужен `tesseract` или ONNX-модель |

Первый прототип вызывал `Windows.Media.Ocr` напрямую. Это работало на Windows и
не работало больше нигде. Дистрибутив для macOS при этом собирался — то есть
интерфейс обещал функцию, которой в нём не было.

Отдельный риск: языковой пакет. На проверочной машине
`AvailableRecognizerLanguages` = `en-US, ru`. На чистой английской Windows
русского пакета нет, и движок молча переключился бы на `en-US`: кириллица
превратилась бы в мусор без единого сообщения.

## Решение

Ввести слой `electron/lib/ocr.js` с четырьмя движками за одним интерфейсом.
`attachments.js` не знает про WinRT, Vision и tesseract.

| Движок | Платформа | Сеть | Зависимость | Размер |
|---|---|---|---|---|
| `winrt` | Windows | нет | языковой пакет ОС | 0 |
| `vision` | macOS | нет | Xcode Command Line Tools | 0 |
| `tesseract` | любая | нет | бинарник в `PATH` | системный пакет |
| `mai` | любая | **да** | ключ шлюза, `hunyuan-ocr` | 0 |

Порядок в режиме `auto` — локальные движки первыми, сеть последней:

- `win32` → `winrt`, `tesseract`, `mai`
- `darwin` → `vision`, `tesseract`, `mai`
- `linux` → `tesseract`, `mai`

Наружу два вызова: `ocrStatus()` — какие движки живы, какие языки, что выбрано;
`ocrImage()` — распознать файл. Оба асинхронные.

Правила, которые следуют из ADR 0018 (таймауты) и ADR 0011 (guardrails):

1. У каждого движка таймаут. Прикрепление файла не «висит» вечно.
2. Движок не найден — понятная ошибка с причиной, вложение остаётся доступным.
3. Отсутствие языкового пакета — явная ошибка со списком доступных языков и
   инструкцией, а не тихое переключение на другой язык.
4. Сетевой движок отправляет изображение на сервер. Поэтому он последний и
   помечается в результате полем `note`.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Только `Windows.Media.Ocr` | 0 МБ, офлайн, уже проверено | не работает на Linux и macOS | дистрибутивы для них собираются — функция была бы обещанием без реализации |
| Только `hunyuan-ocr` через шлюз | один HTTP-вызов, одинаково везде, 0 зависимостей | нужна сеть, изображение уходит на сервер, расход токенов | приватность: скриншот с кодом или документом уходит наружу без явного согласия |
| `onnxruntime-node` + RapidOCR | офлайн, одинаково везде | десятки-сотни МБ на платформу, нативные бинарники в сборке | размер дистрибутива; **не проверено** — запрос к registry npm не выполнялся |
| Адаптеры движков (выбрано) | работает везде, локально где можно, сеть как запасной путь | четыре кодовых пути, три из них не проверены в этой среде | — |

## Последствия

- Проще: добавление нового движка — новый адаптер, а не правка `attachments.js`.
  Windows-путь работает офлайн и без зависимостей.
- Сложнее: четыре кодовых пути. `vision`, `tesseract` и `mai` **не проверены** в
  среде разработки — macOS и tesseract недоступны, живой вызов шлюза не делался.
- Проверять: `npm.cmd run test:ocr` (24 проверки, без сети). Живой прогон на
  macOS и Linux — отдельная задача.
- Риск: сетевой движок отправляет изображение на сервер. Снижение — он последний
  в порядке приоритета, отключается настройкой `ocr.engine`, а результат помечен
  полем `note`.
- Риск: `swift` в PATH на macOS есть только с Xcode Command Line Tools. Снижение —
  `ocrStatus()` сообщает об этом текстом, а `tesseract` и `mai` остаются.
- Документация: `docs/OCR.md`, раздел «Вложения» в `docs/ARCHITECTURE.md`.
