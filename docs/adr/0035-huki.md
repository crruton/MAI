# 0035. Хуки на события агента

- **Статус:** accepted
- **Дата:** 2026-11-20
- **Контекст:** бэклог CC3.1–CC3.3

## Контекст

Правила проекта («не трогать `.env.prod`», «после правки — линтер», «не
заканчивать без тестов») можно было записать только текстом в `AGENTS.md`;
модель могла их не выполнить. Нужна проверка, которую исполняет приложение.

## Решение

`electron/lib/hooks.js`. Формат — как в Claude Code: событие → группы с
`matcher` (регулярное выражение по имени инструмента целиком; пусто или `*` —
всё) → команды с `timeout` (1–600 с, по умолчанию 60). Источники:
`settings.hooks` и `.mai-code/hooks.json` проекта — только для доверенной папки.

Команда получает JSON на stdin (`hook_event_name`, `session_id`, `project_dir`
и данные события) и `MAI_PROJECT_DIR`. Код 0 — успех, stdout может содержать
`{ decision, reason, additionalContext }`; код 2 — блокировка, причина —
stderr; другой код или таймаут — ошибка хука, действие не блокируется. По
таймауту хук останавливается вместе с дочерними процессами. Из нескольких
решений побеждает самое строгое.

| Событие | Что может |
|---|---|
| `PreToolUse` | `deny` — вызов не выполняется; `ask` — спросить даже в «Без вопросов»; `allow` — не спрашивать. Не пробивает guardrails, `deny`-правила и «План» |
| `PostToolUse` | `additionalContext` — дописать к результату; `block` — замечание агенту |
| `UserPromptSubmit` | `block` — запрос не уходит; `additionalContext` — дополнить запрос |
| `Stop` | `block` — агент продолжает с замечанием (роль `hook` в истории), не больше 3 раз |
| `PreCompact` | `additionalContext` — что обязательно сохранить в сводке |
| `SessionStart` | `additionalContext` — к первому запросу нового чата |

Каждое срабатывание — в журнале решений (`audit.jsonl`, `tool: hook:<событие>`)
и событием `hook` в окне; `/hooks` показывает настроенные хуки.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Только JS-хуки плагинов | Без процессов | Привязка к нашему API; не переиспользовать скрипты Claude Code | Команды совместимы с экосистемой |
| Хук `allow` пробивает все проверки | Как у части агентов | Хук проекта отменил бы deny-правила пользователя | Безопасность важнее |

### Дополнение 21.11.2026: готовые хуки для правил проекта (CC3.4)

`examples/hooks/`: `no-push-main.mjs` (PreToolUse для `run_shell`: пуш в
защищённые ветки и `git push` с защищённой ветки — код 2) и

получает отказ с объяснением, а не нарушает правило. Репозиторий MAI
подключает их сам (`.mai-code/hooks.json`). Проверки —
`scripts/test-hook-examples.mjs` (20, настоящий git).

## Последствия

- Хук проекта — исполняемый код репозитория, поэтому только после доверия к папке.
- Хуки выполняются в main-процессе приложения как дочерние процессы с правами пользователя.
- Проверки: `scripts/test-hooks.mjs` (16, на настоящих командах), раздел [16]
  `test-agent-loop`, раздел [23] `test-ui`.
