# 0085. Рантаймы: версия CLI и перенос пресетов

- **Статус:** accepted
- **Дата:** 2026-11-23
- **Контекст:** бэклог F7; продолжение ADR 0029 (внешние рантаймы)

## Контекст

Проба рантайма (OpenCode, Claude Code, Codex, Gemini, herdr) говорила только
«CLI найден»: старая версия с другими флагами всплывала уже ошибкой запуска.
Настроенные рантаймы нельзя было перенести на другую машину или раздать
команде.

## Решение

- `probeRuntime` после поиска в PATH запускает `<команда> --version` (или
  свои `versionArgs`, до 10 с), `versionOf` достаёт номер («opencode 0.3.1»,
  «2.0.14 (Claude Code)», «v1.2-beta»). Поле рантайма `minVersion` — если
  версия старее (`compareVersions`), проба возвращает `outdated` и причину.
  В окне «Рантаймы»: «CLI найден · 0.3.1», устаревший — жёлтым.
- «Экспорт» (`runtimes:export`, любая роль) — `mai-runtimes.json` (формат
  `mai-runtimes` v1); значения `env` — секреты — не уходят, только имена.
- «Импорт» (`runtimes:import`, admin: рантайм — это запускаемая команда):
  `importRuntimes` проверяет id, `command` (без перевода строки) или `image`
  для docker, `args` — список строк; плохие — с причиной. Свои рантаймы с тем
  же id заменяются только по согласию; при замене свои значения `env`
  сохраняются. Запись в аудит.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Экспорт вместе с ключами env | Перенос «одной кнопкой» | Утечка ключей через файл | Ключи вводятся на месте |
| Обязательная minVersion для пресетов | Строже | Пресеты устаревают вместе с CLI | Поле по желанию |

## Последствия

- Проба на один рантайм дольше на время `--version`.
- Проверки: `test-runtimes` — разбор версий, сравнение, проба настоящего
  `node` (путь и версия), `minVersion`, экспорт без значений env, импорт
  (новое, своё оставлено, ошибки), замена с сохранением своего ключа, не тот
  файл.
