# 0016. Вложения через файлы проекта, а не через текст промпта

- **Статус:** accepted
- **Дата:** 2026-11-05
- **Контекст:** задача о вложениях в композере (документы, архивы, изображения)

## Контекст

До этого решения вложения читались в рендерере через `file.text()` и целиком
вставлялись в текст промпта. Отсюда три ограничения:

- предел 64 КБ на файл и 192 КБ на все вложения — иначе контекст модели
  переполняется;
- бинарные файлы отклонялись, поэтому PDF, DOCX, XLSX, PPTX и архивы
  прикрепить было нельзя;
- содержимое файла попадало в историю сессии и в каждый следующий запрос,
  то есть токены тратились повторно.

Агент уже умеет читать файлы инструментами `read_file` и `grep` внутри папки
проекта. Значит, файлу достаточно лежать на диске, а в контекст нужно передать
путь.

## Решение

Вложение — это файл в папке проекта плюс запись манифеста в промпте.

1. Файл копируется в `.mai-code/uploads/<sessionId>/` внутри папки проекта.
2. Модуль `electron/lib/attachments.js` определяет тип по расширению и
   сигнатуре, затем извлекает текст:
   - текст и код читаются как UTF-8;
   - DOCX, XLSX, PPTX разбираются как ZIP и XML без внешних библиотек;
   - PDF распаковывается `zlib` и разбирается по операторам `Tj`/`TJ`;
   - ZIP распаковывается встроенным парсером, 7-Zip и `tar` — запасной путь;
   - изображения отдаются как путь и data URL.
3. В промпт уходит манифест: имя, размер, тип, путь, путь к извлечённому
   тексту, число строк или страниц, примечание.
4. Агент читает файл инструментами. Размер файла больше не ограничен
   контекстом: предел 200 МБ на файл и 500 МБ на сессию.

Опасные операции проходят проверку в main-процессе: удаление и открытие
разрешены только внутри папки вложений, секретные имена отклоняются по
исходному имени до очистки.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Оставить текст в промпте | Просто, работает офлайн | Предел 64 КБ, нет бинарных файлов, токены тратятся повторно | Не решает задачу |
| Внешняя библиотека (`pdf-parse`, `mammoth`) | Меньше своего кода | Новая зависимость, вес сборки, лицензии | Правило проекта: минимум зависимостей |
| Отправлять файлы в API провайдера | Нативная поддержка у модели | Не все провайдеры, файлы уходят наружу | Модель угроз и приватность |
| Файлы на диске + манифест | Любой размер, офлайн, приватность | Нужен разбор форматов | **Выбран** |

## Последствия

- Проще: прикреплять большие файлы, архивы и документы; контекст не растёт от
  размера файла; вложения переживают перезапуск приложения.
- Сложнее: свой разбор PDF и Office. Разбор PDF эвристический: сжатые потоки
  без `FlateDecode`, шифрование и сканы без текстового слоя не поддерживаются.
- Проверить: `node scripts/test-attachments.mjs` — 35 проверок, все проходят.
  Проверено на синтетических ZIP, DOCX и PDF. Реальные файлы Word, Excel и
  PDF от пользователя не проверялись.
- Риск: копии файлов занимают место в проекте. Снижение — удаление папки
  сессии вместе с сессией и запись `.mai-code/uploads/` в `.gitignore`.
