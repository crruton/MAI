# 0040. Песочница для команд агента

- **Статус:** accepted
- **Дата:** 2026-11-20
- **Контекст:** бэклог CC2.8, F17, CW1.3

## Контекст

Docker-песочница проекта (`container.js`) была отдельной панелью: агент её не
использовал, и `run_shell` всегда выполнялся на хосте с правами пользователя.
Guardrails и правила ловят известные опасные команды, но `npm test` запускает
что угодно из `package.json`, а режимы «Авто» и «Без вопросов» выполняют
команды без вопроса.

## Решение

`electron/lib/shell-sandbox.js`, настройка `shellSandbox` (меняет только admin):

```json
{ "shellSandbox": { "mode": "docker", "image": "node:22-bookworm-slim", "network": "none", "hostCommands": ["git *"] } }
```

- `mode: docker` — `run_shell` выполняет команду в одноразовом контейнере:
  `docker run --rm`, проект смонтирован в `/workspace` (рабочая папка — та же
  относительно проекта), корневая ФС `--read-only`, `/tmp` в памяти,
  `--cap-drop ALL`, `no-new-privileges`, лимиты памяти, CPU и 512 процессов,
  сеть `none` (или `bridge` по выбору). На Linux — `--user` текущего
  пользователя, чтобы файлы проекта не становились root.
- Команда уходит в `sh -lc` внутри контейнера одним аргументом — оболочка
  хоста в цепочке не участвует. «Стоп» и таймаут — `docker kill`.
- `hostCommands` — маски команд, которым нужен хост (`git *` — ключи и
  конфигурация git). Составная команда идёт на хост, только если каждая часть
  совпала с маской; подстановки `$(…)` — никогда.
- Docker недоступен — команда **не** выполняется на хосте молча: агент получает
  ошибку с объяснением. Доступность проверяется не чаще раза в минуту.
- В итоге команды указано, где она выполнилась: `[код 0, 812 мс · Docker …]`.
- Решения PolicyEngine не меняются: песочница — второй рубеж, а не повод
  разрешать больше.
- Попутно: `allowOutsideProject` теперь меняет только admin.

По умолчанию песочница выключена: см. «Последствия».

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Включить по умолчанию | Безопаснее «из коробки» | На Windows у многих нет Docker; команда в контейнере — Linux `sh`, а агент и пользователи привыкли к `cmd.exe`; первый запуск тянет образ | Выключено по умолчанию; организация может включить политикой, режим «Без вопросов» в документации советует песочницу |
| Долгоживущий контейнер проекта (`docker exec`) | Быстрее, кеш зависимостей между командами | Состояние течёт между командами, процесс может пережить «Стоп» | Одноразовый контейнер проще и предсказуем; кеш — в `node_modules` проекта |
| Копировать проект внутрь контейнера | Хост-файлы не меняются вовсе | Правки агента не видны, нужно синхронизировать обратно | Агенту нужно менять проект; чекпоинты и git остаются способом отката |
| Песочница ОС (bubblewrap, Seatbelt, AppContainer) | Без Docker | Три разных механизма, на Windows — сложно | Можно добавить позже для Linux/macOS |

## Последствия

- Включённая песочница меняет оболочку команд на Linux `sh` и на Windows:
  `dir` не сработает, `ls` — сработает. Системный промпт описывает
  `run_shell` как оболочку проекта; модели это обычно не мешает.
- `npm install` в контейнере без сети не скачает пакеты — нужно `network: bridge`
  или маска на хост.
- Образ должен быть скачан (`docker pull`) — первый вызов может быть долгим.
- Следующий шаг: учитывать песочницу в классификаторе «Авто» (сеть выключена —
  сетевые команды безопасны), сделать её доступной в настройках организации
  (ADR 0038).
- Проверки: `scripts/test-shell-sandbox.mjs` (30, плюс 6 с настоящим Docker в CI
  на Linux, `MAI_DOCKER_TEST=1`).
