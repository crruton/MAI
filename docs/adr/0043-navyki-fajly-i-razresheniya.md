# 0043. Навыки: файлы и allowed-tools

- **Статус:** accepted
- **Дата:** 2026-11-21
- **Контекст:** бэклог CC10.4

## Контекст

Навык был одним `SKILL.md`: описание — в системном промпте, тело — по
`load_skill`, вызов — `/имя`. Справки, шаблоны и скрипты рядом с ним агент не
видел. Навык, который запускает свой скрипт, спрашивал разрешение на каждый
запуск даже в доверенном проекте.

## Решение

Три уровня загрузки, как в Claude Code:

1. Описание из frontmatter — в системном промпте (как раньше).
2. `load_skill(name)` — тело `SKILL.md`, путь папки навыка и список его файлов
   (до 200, без скрытых и `node_modules`).
3. `load_skill(name, file)` — файл навыка (до 100 КБ). Путь вне папки навыка —
   отказ. Скрипт агент запускает через `run_shell` по полному пути, как любую
   команду: решение принимает PolicyEngine.

`allowed-tools` во frontmatter (`allowed-tools: run_shell(python scripts/*), mcp__docs__search`) —
после загрузки навыка эти правила становятся `allow` **на текущий прогон**:

- не сохраняются ни в чат, ни в настройки; субагентам не передаются;
- `deny`, `ask`, guardrails и режим «План» по-прежнему сильнее;
- широкие правила не выдаются: команды и запись (`run_shell`, `write_file`,
  `edit_file`, `memory_append`) только с маской, маска `*` — нет;
- пользователь видит уведомление «Навык … разрешил на этот прогон: …», выдача
  пишется в журнал решений;
- плагинам эта возможность не передаётся (как `ask`, ADR 0030).

Навыки проекта по-прежнему доступны только в доверенной папке (ADR 0028), так
что `allowed-tools` из чужого репозитория без доверия не действуют.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Игнорировать `allowed-tools` | Безопаснее | Навыки со скриптами спрашивают на каждом шаге; несовместимо с навыками Claude Code | Узкие правила на прогон |
| Сохранять выданное в правила чата | Не спрашивать и в следующих сообщениях | Разрешение переживает задачу, ради которой выдано | Только на прогон |
| Отдельный инструмент `run_skill_script` | Явно | Ещё один класс действий, тот же риск, что у `run_shell` | `run_shell` с правилами |

## Последствия

- Навык из пакета или глобальный с `allowed-tools` — доверие к его автору;
  окно `/packages` помечает исполняемые пакеты, но не навыки с `allowed-tools`.
- Проверки: раздел [19] `test-agent-loop` (файлы, выход из папки, узкие и
  широкие правила, команда до и после загрузки, уведомление, журнал).
