# 0079. Ноутбуки, диагностика кода и отложенная загрузка инструментов

- **Статус:** accepted
- **Дата:** 2026-11-23
- **Контекст:** бэклог CC1.10, CC1.11, CC1.12

## Контекст

Три пробела в инструментах агента относительно Claude Code: ноутбуки Jupyter
читались сырым JSON и правились только целиком; агент не видел ошибок
компилятора и линтера, пока не запустит сборку сам; при десятках MCP-серверов
схемы всех инструментов уходили в каждый запрос и съедали контекст.

## Решение

**Ноутбуки (CC1.10)** — `tools/notebook.js`.
- `read_file` для `.ipynb` — `renderNotebook`: ячейки с номерами, типом, id,
  счётчиком выполнения, код в блоке языка ядра, вывод кратко (поток, текст
  результата, типы картинок, ошибка `ename: evalue`, до 2000 символов).
- `notebook_edit({ path, cell | cell_id, new_source, cell_type, edit_mode:
  replace|insert|delete })`, класс write: то же правило «сначала прочитай»
  (`readGuard`), превью — текст ячейки до и после. JSON пишется с прежним
  отступом; источник — строками с `\n`; у изменённой ячейки кода сбрасываются
  `outputs` и `execution_count`; вставленная получает `id` (nbformat ≥ 4.5).
  Правило «запомнить» — `notebook_edit(папка/**)`.

**Диагностика (CC1.11)** — `diagnostics.js` и инструмент `diagnostics(path?)`
(класс read, в «Коде» и у ревизора).
- Вместо постоянного языкового сервера — программы, уже стоящие в проекте:
  `tsc --noEmit -p tsconfig.json` (из `node_modules/.bin`), ESLint с конфигом,
  Ruff или Pyright; без них — синтаксис: `node --check`, `python -m
  py_compile`. Вывод каждой разбирается в `файл:строка:колонка`, важность,
  источник, сообщение; до 200 строк.
- Запуск программ проекта (конфиг ESLint — это его код) — только в доверенной
  папке, как хуки и плагины.
- `settings.autoDiagnostics` (по умолчанию выключено: проверка большого
  проекта бывает медленной): после успешной правки кода (`.js/.ts/.py…`)
  проверяется изменённый файл (до 60 с), ошибки дописываются к результату
  правки «[Диагностика после правки]». Промпт «Кода» просит проверять
  `diagnostics` перед «готово».

**Отложенные инструменты (CC1.12)** — `tool-search.js`.
- Если внешних инструментов (MCP и плагины) больше `settings.deferToolsOver`
  (по умолчанию 25; 0 — никогда), их схемы в запрос не идут: в системном
  промпте — «Инструменты по запросу» с именем и кратким описанием, а модель
  получает `tool_search({ query })` — слова из названия/описания или
  `select:имя1,имя2`, до 10 за раз. Найденные помечаются загруженными на
  прогон и со следующего шага уходят в запрос со схемами.
- Вызов неподгруженного инструмента всё равно выполняется (тот же
  `runToolCall`, политика и хуки) — схема нужна модели, а не приложению.

## Дополнение: выбор интерпретатора Python (2026-11-24)

Проверка синтаксиса молча не работала в Windows. `onPath('python3')` проверял
только наличие файла в PATH. В Windows `python3.exe` часто оказывается
заглушкой Microsoft Store: `where` её находит, но запуск возвращает код 9009 и
пустой вывод. `py_compile` запускался на заглушке, разбор получал пустую строку
и возвращал пустой список — файл с `SyntaxError` выглядел как «Ошибок нет».

Теперь `pythonOnPath()` проверяет кандидата запуском (`python -c pass`) и при
отказе берёт следующего: `python3`, затем `python`. Правило общее: программу
из PATH проверяют запуском, а не наличием файла.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Настоящий LSP (typescript-language-server, pyright --langserver) | Точно, быстро после старта | Процессы на проект, протокол, зависимости | CLI проекта даёт то же для «проверить после правки» |
| Ноутбук — edit_file по JSON | Без нового инструмента | Модель ломает экранирование и выводы | Правка ячеек — надёжнее |
| Отключать часть MCP вручную | Просто | Пользователь не знает, что нужно агенту | Поиск по запросу |

## Последствия

- Диагностика всего проекта TypeScript занимает столько, сколько `tsc`; для
  файла tsc всё равно проверяет проект, ошибки фильтруются по файлу.
- Отложенные инструменты стоят один лишний шаг модели (`tool_search`).
- Проверки: `scripts/test-notebook.mjs` (чтение по ячейкам и выводы, правка
  без чтения, замена со сбросом вывода, отступ, вставка по id и в конец,
  удаление, ошибки, превью); `scripts/test-diagnostics.mjs` (разбор tsc,
  eslint, ruff, pyright; node --check с ошибкой и без, py_compile, файл без
  проверок, формат); `test-agent-loop` [34] — 30 MCP: только tool_search и
  имена, загрузка по описанию, схема со следующего шага, вызов; мало MCP —
  как раньше; `autoDiagnostics` дописывает SyntaxError к правке.
- `py_compile` проверяется только при рабочем Python: заглушка Microsoft Store
  в PATH больше не выбирается (см. дополнение).
