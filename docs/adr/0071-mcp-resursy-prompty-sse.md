# 0071. MCP: ресурсы, промпты и SSE

- **Статус:** accepted
- **Дата:** 2026-11-22
- **Контекст:** бэклог CC9.3, CC9.4, CC9.6; продолжение ADR 0041, 0052

## Контекст

MAI использовал у MCP-серверов только инструменты. Claude Code умеет больше:
ресурсы сервера упоминаются в запросе как `@server:uri`, промпты сервера
вызываются как слэш-команды `/mcp__server__prompt`, а со старыми серверами
он работает по SSE. Многие серверы (базы данных, документация, CRM) отдают
главное именно ресурсами и промптами.

## Решение

**Подключение.** `McpManager.connect` после `initialize` смотрит возможности
сервера: `listTools` (если сервер их не объявил, но есть ресурсы или промпты —
пропускаем), `listResources`, `listPrompts`; сбой списка ресурсов или промптов
подключение не ломает. В статусе — число ресурсов и промптов, транспорт.

**Ресурсы (CC9.3).** `listResources()`, `readResource(server, uri)` — текст,
двоичное — пометкой с типом и размером, длиннее 50 000 символов — обрезка.
В поле ввода `@` подсказывает файлы проекта и ресурсы (`mcp:resources`) в
виде `@сервер:uri`. При отправке `resolveResourceMentions` находит только
известные ресурсы (до 5), их содержимое дописывается к запросу в рамке
`<данные>` (ADR 0053) — это данные, не указания; в чате виден запрос, как
его написали. Чтение ресурса, упомянутого пользователем, не спрашивается.

**Промпты (CC9.4).** `listPrompts()` → команды `mcp__<сервер>__<промпт>` с
подсказкой аргументов (`<обязательный> [необязательный]`) и меткой «MCP».
`commands:expand` → `promptArgs` (слова по порядку, `ключ=значение` — по
имени, лишние слова — в последний аргумент) → `getPrompt` → текст сообщений
сервера уходит агенту как обычный запрос. Нет обязательного аргумента —
понятная ошибка.

**SSE (CC9.6).** `transport: "sse"` или `type: "sse"` (как в `.mcp.json`
Claude Code) — сразу `SSEClientTransport`; `"http"`/`"streamable-http"` —
только streamable HTTP. Без указания — streamable HTTP, а если `initialize`
не прошёл не из-за входа — новая попытка по SSE (рекомендация спецификации
для обратной совместимости). OAuth работает на обоих.

## Альтернативы

| Вариант | Плюсы | Минусы | Почему не выбран |
|---|---|---|---|
| Ресурсы — инструментом `mcp_read_resource` для агента | Агент сам решает | Модель не знает, что есть; лишний шаг | Как в Claude Code: явное упоминание |
| Промпт подставлять текстом в поле ввода | Можно поправить | Аргументы теряют смысл | Сразу запрос; можно повторить |
| Только явный `transport` | Предсказуемо | Старые серверы «просто не работают» | Автопереход только при не-входе |

## Последствия

- Шаблоны ресурсов (`resourceTemplates`) и подписки на изменения не
  поддержаны; список ресурсов обновляется при переподключении.
- Ресурсы упоминаются только у подключённых серверов.
- Проверки: `scripts/test-mcp-extras.mjs` — настоящий сервер SDK по streamable
  HTTP (ресурсы текст/двоичный/обрезка, промпт с аргументами и без
  обязательного, инструменты) и сервер только с SSE (автопереход,
  `transport: "sse"`, `type: "sse"`, `transport: "http"` без перехода);
  разбор аргументов и упоминаний. `test-ui` [42] — подсказка `@db:uri`,
  вставка, промпт в списке команд.
