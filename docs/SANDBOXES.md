# Песочницы

В MAI Code два режима. Их не нужно путать: они дают разный уровень изоляции.

| Режим | Что изолирует | Что не изолирует | Зависимости |
|---|---|---|---|
| Проект в отдельной папке | файлы и `.mai-code` | процессы, сеть, права пользователя | нет |
| Docker-песочница | процессы, сеть, capabilities, ФС контейнера | смонтированную папку проекта | Docker |

## Проект в отдельной папке

Кнопка **＋ Новый проект** («Новый проект в отдельной папке») создаёт папку в
`%APPDATA%\mai-code\sandboxes\<slug>` (имя каталога осталось прежним ради
совместимости; раньше это называлось «песочницей проекта», ADR 0091):

- свой `.mai-code/memory.md`, `sandbox.json`, загрузки;
- шаблон `blank`, `service` или `agent-app`;
- локальный git и начальный коммит;
- опционально remote в GitHub/GitLab или инструкция для OpenScion.

Это удобно для разделения проектов, но **не является границей безопасности**:
агент работает с правами вашего пользователя.

## Docker-песочница

Кнопка **Docker** на панели — единственная настоящая изоляция: процессы, сеть,
capabilities.

Панель **Песочницы** запускает контейнер с папкой проекта в `/workspace`.

Что включено:

- `--read-only` для корневой ФС;
- `--tmpfs /tmp` с `noexec,nosuid`;
- `--cap-drop ALL` и `--security-opt no-new-privileges`;
- лимиты `--memory` и `--cpus`;
- `--pids-limit 256`;
- сеть `bridge` или `none`;
- порты только явные, по умолчанию на `127.0.0.1`.

Пример формы:

| Поле | Значение |
|---|---|
| Образ | `node:22-alpine` |
| Порты | `3000:3000, 127.0.0.1:8080:8080` |
| Сеть | `bridge` |
| Память | `2g` |
| CPU | `2` |
| Команда | `npm run dev` (необязательно) |

Без команды контейнер работает в режиме ожидания: `while true; do sleep 3600; done`.
Затем можно выполнить команду через `sandbox:exec` (API) или зайти в контейнер:

```powershell
docker exec -it mai-code-<slug> sh
```

## Порты

Формат: `[host:]hostPort:containerPort[/tcp|udp]`.

- `3000:3000` → `127.0.0.1:3000` (безопасный вариант);
- `0.0.0.0:3000:3000` → все интерфейсы (осознанный риск);
- `8080:80/udp` → UDP.

Порт, занятый на хосте, даст ошибку `docker run`. Выберите другой host-порт.

## Docker-режим внешнего рантайма

Отдельно от окна «Docker» («Подключения ▾») у каждого рантайма есть режим `docker`
(панель **Рантаймы** → **Изменить**). Он запускает CLI агента в отдельном
контейнере:

- `--rm --init`, сеть `bridge`, память `2g`, CPU `2`;
- `--cap-drop ALL`, `no-new-privileges`, `--pids-limit 512`;
- `tmpfs /tmp` 256 МБ;
- папка проекта монтируется в `/workspace`.

Это не отдельный образ для DeepSeek Harness или Hermes: образ должен содержать
нужный CLI. Без такого образа рантайм работает как host-процесс.

## Очистка старых образов

Повторные сборки оставляют теги, dangling-образы и остановленные контейнеры.
Скрипт `scripts/docker-gc.mjs` удаляет лишнее и сохраняет N последних тегов:

```powershell
npm.cmd run docker:gc:dry     # показать, что будет удалено
npm.cmd run docker:gc         # удалить, keep=2, плюс build cache старше 72h
node scripts/docker-gc.mjs --keep 3 --all --build-cache
```

Флаги: `--dry-run`, `--keep N`, `--all`, `--no-dangling`, `--build-cache`,
`--no-containers`, `--json`.

Скрипт не удаляет образ, который используется контейнером: такой образ
попадает в «пропущено (используются)». Это защищает работающие песочницы.

## Ограничения

- Docker Desktop на Windows требует WSL2.
- Папка проекта смонтирована: контейнер может менять файлы проекта. Для полной
  изоляции файлов копируйте проект внутрь контейнера — это отдельный режим.
- Docker-сокет не пробрасывается: вложенный Docker недоступен.
- Образы не проверяются и не подписываются приложением.
- На macOS/Linux поведение то же, но пути монтируются иначе.
- Панель не устанавливает Docker. Если `docker info` не отвечает, показывается ошибка.
- Guardrails встроенного агента не применяются к процессам внутри контейнера
  рантайма.

## Проверка

Проверено на Docker 29.9.2: запуск контейнера, публикация `127.0.0.1:18080→80`,
список контейнеров, логи и остановка. Для проверки использовался образ
`postgres:17.11-alpine3.24` и команда `sleep 60`.

```powershell
docker ps --filter label=mai-code.sandbox=1
docker logs --tail 100 mai-code-<slug>
docker stop mai-code-<slug>; docker rm mai-code-<slug>
```
