## 1. Целевая архитектура

```
UI (лента, композер, панели)          ← только отображение и ввод
  │ IPC (типизированный, проверка схемы)
main
  ├─ SessionStore    (сессия = файл, история шагов, чекпоинты)
  ├─ AgentLoop       (итерации, субагенты, очередь сообщений, компакция)
  ├─ PolicyEngine    (classify → guardrails → hooks → rules → mode → ask → audit)
  ├─ Executors       (host | docker-sandbox | worktree)  ← где реально выполняется
  ├─ ToolRegistry    (встроенные, MCP, плагины, навыки; отложенная загрузка)
  ├─ Connectors      (MCP с OAuth: почта, диск, календарь, трекеры)
  ├─ Scheduler       (плановые задачи)
  └─ Telemetry       (OTel spans на каждый шаг, токены, стоимость)
```

Принцип: каждое действие, меняющее состояние, проходит через **PolicyEngine**,
откуда бы оно ни шло: встроенный инструмент, MCP, плагин, внешний рантайм,
стадия доски, самокоррекция, плановая задача, субагент.
