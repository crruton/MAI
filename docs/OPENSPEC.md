# OpenSpec

OpenSpec — процесс «сначала спецификация, потом код». В MAI Code он связан с
Multica: задачи из `tasks.md` попадают на доску.

## Структура

```
openspec/
  project.md
  specs/                         текущие спецификации
  changes/<name>/
    proposal.md                  проблема, решение, критерии
    design.md                    как устроено
    tasks.md                     чек-лист задач
    specs/<capability>/spec.md   требования
```

В репозитории уже есть пример:
`openspec/changes/add-offline-distribution/`.

## Команды

```powershell
npm.cmd install -g @fission-ai/openspec
openspec init
openspec validate
```

`openspec init` создаёт структуру в текущей папке. Если структура уже есть,
команда не перезаписывает файлы.

## Процесс

1. Создать изменение `openspec/changes/<name>/`.
2. Написать `proposal.md`: проблема, решение, критерии приёмки, вне scope.
3. Написать `design.md`: архитектура, альтернативы, риски.
4. Разбить работу на задачи в `tasks.md`.
5. Синхронизировать задачи в Multica.
6. Реализовать. Отметить `- [x]`.
7. Обновить `CHANGELOG.md` и, если решение архитектурное, `docs/adr/`.
8. Запустить `npm.cmd run docs:check`.

## Связь с Multica

```powershell
npm.cmd run multica:sync
```

Или панель **Multica** → **Синхронизировать OpenSpec**. Закрытые в Multica задачи
возвращаются галочкой `[x]` кнопкой **Статусы → tasks.md** (ADR 0089).

Ключ идемпотентности — маркер в описании issue:
`<!-- openspec:<change>:<task> -->`.

## Правила текста

Задачи пишутся по ASD-STE100. Это не бюрократия: короткие однозначные
формулировки лучше понимают и люди, и агенты.

| Плохо | Хорошо |
|---|---|
| «Разобраться с синком» | «Добавить sync OpenSpec → Multica» |
| «Починить, если падает» | «Добавить таймаут 30 с. Показать ошибку.» |
| «Сделать красиво» | «Перенести кнопки во второй ряд.» |

## Ограничения

- Парсер в приложении читает только `proposal.md` и `tasks.md`.
- Вложенные чек-листы и таблицы задач не поддерживаются.
- OpenSpec CLI не обязателен для sync, но нужен для `validate`.
- Статусы Multica не пишутся обратно в `tasks.md`.
