# Провайдеры и рантаймы

В списке «opencode, herdr, deepseek harness, anthropic, openai, hermes, JEV, copilot» смешаны
две разные вещи. Их нельзя делать одним механизмом.

## Два слоя

**Провайдер** — API, откуда берутся ответы модели. Наш агент сам крутит цикл, инструменты
и подтверждения; провайдеру уходит обычный `chat/completions`.

**Рантайм** — чужой агент со своим циклом и своими инструментами (CLI или демон). Мы можем
только запустить его, показать вывод и передать сообщение. Наш UI при этом превращается
в терминал.

| Кандидат | Слой | Что это | Стоимость подключения |
|---|---|---|---|
| Anthropic | провайдер | Claude API, есть OpenAI-совместимый режим | низкая |
| OpenAI | провайдер | нативный OpenAI API | низкая |
| DeepSeek (platform) | провайдер | OpenAI-совместимый API | низкая |
| GitHub Copilot | провайдер | OAuth device flow + `api.githubcopilot.com` | средняя, неофициально |
| OpenCode | рантайм | CLI-агент, уже установлен | средняя |
| herdr | рантайм | менеджер терминалов для агентов, уже установлен | средняя |
| DeepSeek harness | рантайм | CLI-обвязка DeepSeek | средняя |
| Hermes | рантайм | агент Nous Research | средняя |
| JEV | рантайм | сторонний CLI-агент | средняя |

Вывод: провайдеры — дёшево и полезно, их стоит сделать. Восемь нативных интеграций
рантаймов — перебор; нужен один общий механизм «внешняя команда» и пресеты к нему.

## Как устроено

### Реестр провайдеров

Провайдеры хранятся в `%APPDATA%\mai-code\settings.json`. Ключи на диске
зашифрованы хранилищем ОС и выглядят как `enc:v1:…` (ADR 0031); в примере ниже
они показаны открыто для наглядности. У модели можно указать необязательные
поля: `"vision": true` — принимает изображения (иначе определяется по имени),
`"price": { "input": 3, "output": 15 }` — цена за 1 млн токенов для `/cost`.

```json
{
  "providers": {
    "mai": {
      "name": "MAI",
      "baseURL": "https://api-ai.mai.ru/v1",
      "apiKey": "sk-...",
      "models": [{ "id": "deepseek-v4.1-flash", "name": "", "context": null }]
    },
    "agentrouter": {
      "name": "AgentRouter",
      "baseURL": "https://agentrouter.org/v1",
      "apiKey": "sk-...",
      "models": [
        { "id": "claude-opus-5-5", "name": "Claude Opus 5.5", "context": 200000 }
      ]
    }
  }
}
```

- При старте MAI и AgentRouter создаются из `.env` (`LLM_*` и `AGENTROUTER_*`), если
  в настройках ещё нет реестра.
- В дропдауне модели сгруппированы по провайдерам: `MAI · DeepSeek V4.1 Flash`,
  `AgentRouter · Claude Opus 5.5`. В историю и в API уходит ключ `провайдер/модель`.
- Список моделей берётся из `GET {baseURL}/models` и кэшируется на 5 минут. Если шлюз
  не отдаёт список, используется статический список из настроек провайдера.
- Часть шлюзов смотрит на `User-Agent`: AgentRouter отвечает 401 всем, кроме клиента
  Claude Code. Заголовок задаёт `providerUserAgent()` (`lib/config.js`) — из настроек
  провайдера, иначе по его id, иначе по хосту `baseURL`. MAI на заголовок не реагирует.
- Некоторые модели не принимают `POST /v1/chat/completions` и требуют
  `/v1/responses` (OpenAI Responses API). Агент определяет это по первой ошибке
  шлюза, повторяет шаг через `lib/responses.js` и держит выбор до конца сессии.
  Моделям GPT-5+ `temperature` не отправляется — шлюз отвечает 400. См. ADR 0026.
- Окно «Провайдеры» («Кто выполняет ▾» → «Провайдеры и ключи…»): проверка (`GET /models`), добавление, редактирование, удаление.
  Ключ наружу не отдаётся — только признак «ключ есть» и первые символы.
- Anthropic подключается через OpenAI-совместимый эндпоинт; Copilot потребует отдельной
  авторизации и в этот слой не укладывается.

Ограничение: OpenAI-совместимый режим покрывает чат и tool calling, но не всё: у Anthropic
нет `reasoning_content`, у Copilot своя авторизация, у Gemini — свой формат. Поэтому
«совместимость» — это базовый уровень, а не полный паритет.

### Внешние рантаймы

Одна вкладка «Рантаймы» вместо восьми отдельных интеграций. Рантайм — это запись:

```json
{
  "runtimes": {
    "opencode": {
      "name": "OpenCode",
      "command": "opencode",
      "args": ["run", "--format", "json", "{prompt}"],
      "parser": "opencode-json",
      "enabled": true
    },
    "herdr": {
      "name": "herdr",
      "command": "herdr",
      "args": ["agent", "prompt", "{target}", "{prompt}", "--wait"],
      "target": "",
      "enabled": false
    }
  }
}
```

Подстановки: `{prompt}`, `{model}`, `{projectDir}`, `{target}`. Если `{prompt}` не указан,
запрос добавляется последним аргументом.

Что уже работает:

1. Процесс запускается в папке проекта, stdout и stderr стримятся в чат.
2. Кнопка «Остановить» убивает дерево процессов (`taskkill /T /F`), таймаут — 30 минут.
3. Ответ рантайма сохраняется в сессию как сообщение `role: "runtime"` и переживает перезапуск.
4. Парсер `opencode-json` вытаскивает текст из JSON-событий OpenCode, чтобы в чате был
   обычный текст, а не сырой лог.
5. Пресеты: OpenCode, herdr, Claude Code, Codex CLI, Gemini CLI, «своя команда».

Ограничения:

- Это не PTY: интерактивные TUI-агенты нужно запускать в неинтерактивном режиме
  (`opencode run`, `claude -p`, `codex exec`).
- Своего цикла инструментов у рантайма в нашем UI нет — инструменты и подтверждения
  остаются на стороне внешнего агента.
- Формат вывода у каждого CLI свой; для незнакомых агентов показывается сырой текст.

## Локальные модели

Окно «Провайдеры» («Кто выполняет ▾» → «Найти локальные модели») само ищет серверы на этом компьютере: Ollama (11434), LM Studio
(1234), colibri или vLLM (8000), llama.cpp (8080), Jan (1337) — запрос
`/v1/models`. «Добавить» создаёт провайдера с моделями из ответа; ключ не нужен.
Модели без вызова инструментов работают через текстовый протокол (ADR 0078,
0100). Автоматического переключения «локально/облако» нет.

## Что осталось

1. **GitHub Copilot** — отдельно и последним: device flow, неофициальный API,
   токены живут около часа.
2. **Пресеты DeepSeek harness, Hermes, JEV** — добавляются как «своя команда»
   без отдельного кода; готовые пресеты появятся, когда будут известны их флаги.
3. **PTY-терминал** — если понадобится полноценный интерактив, а не поток вывода.
