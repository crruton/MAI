# Руководство пользователя

Состояние: версия 0.2.0, 20.11.2026. Как работать с MAI Code каждый день:
режимы разрешений, диалог с агентом, команды, контекст, откат, инструкции
проекта, субагенты и хуки. Установка и ключи — в [README](../README.md#быстрый-старт).

## 1. Первый запуск в папке

1. Выберите папку проекта: кнопка с папкой внизу боковой панели.
2. Приложение спросит **«Доверять этой папке?»** и покажет, что в ней нашлось:
   плагины, MCP-серверы, `AGENTS.md`, память, навыки.
   - **Доверяю** — загрузить всё это. Выбирайте для своих папок и проверенных
     репозиториев. Доступно только роли admin.
   - **Ограниченно** — работать без кода и инструкций проекта: плагины, MCP,
     хуки, пакеты, свои команды и типы субагентов проекта не загружаются, режим «Без
     вопросов» не действует. Рекомендуется для чужого кода — если в папке есть
     плагины или MCP, этот вариант подсвечен.
3. Решение действует и для вложенных папок. Изменить или забыть — «Настройки» →
   «Доверие к папкам». Песочницы, созданные кнопкой «＋ Новый проект», доверены сразу.

У папки в боковой панели метка: «ограниченно» или «не доверена».

### Код или задача

Рядом с режимом разрешений — переключатель **Код / Задача**.

- **Код** — программирование: агент читает проект, правит код, гоняет тесты.
- **Задача** — работа с документами и данными: отчёты, таблицы, разбор
  файлов. Агент уточнит задачу, сохранит результат новым файлом рядом с
  исходными (не перепишет их без просьбы), не будет трогать git и объяснит
  результат простыми словами.

Права одинаковые: режим разрешений и правила действуют в обоих видах.
Переключатель без открытого чата задаёт вид для новых чатов.

### Если работа прервалась

Закрыли приложение (или оно упало), пока агент работал, — у чата в списке
появится «⏸», а в самом чате — «Работа прервалась … Продолжить». Агент
проверит, что уже сделано (список задач, файлы), и продолжит с того места.
Сам он без кнопки не продолжает.

### Плановые задачи

`/schedule` — задачи по расписанию: название, что сделать, когда (по будням,
каждый день или каждые N минут) и вид. Задача берёт текущую папку (она должна
быть доверенной).

- Выполняется сама, пока открыто приложение; результат — новый чат «⏰ …» и
  уведомление.
- Спросить некого, поэтому задача работает в режиме **«Только разрешённое»**:
  делает только то, что разрешено правилами. Например, чтобы она могла писать
  сводку, добавьте правило `write_file(сводка.md)` или `create_document(Отчёты/**)`
  (`/permissions`).
- Приложение было закрыто в нужное время — задача выполнится после запуска,
  если прошло меньше суток.
- «Запустить» — выполнить сейчас; «Журнал» — когда и чем закончились запуски.

### Документы Word и Excel

Попросите, например: «сведи продажи из этих трёх таблиц в одну, с итогами» или
«сделай из заметок отчёт в Word». Агент:

- создаёт `.docx` (заголовки, списки, таблицы) и `.xlsx` (несколько листов,
  числа, формулы — Excel посчитает их при открытии, первая строка закреплена),
  а также `.csv`;
- читает присланные `.docx` и `.xlsx` — текст и таблицы;
- «правит» документ так: читает, меняет и сохраняет заново — оформление
  исходного файла при этом не сохраняется, поэтому результат лучше сохранять
  под новым именем (в режиме «Задача» агент так и делает).

Перед записью приходит обычный запрос с текстом будущего документа.

### Результаты

Когда агент создал или изменил файлы, у поля ввода появляется
**📄 Результаты · N**: список файлов этого чата (создан / изменён / удалён),
начало текста по клику, **Открыть** и **В папке**. Открываются программой по
умолчанию только документы и картинки — скрипты и программы, созданные агентом,
не запускаются, их можно только показать в папке. Файлы, созданные командой в
терминале, в список не попадают.

### Несколько папок в одном чате

Над полем ввода — строка «Папки»: папка проекта и добавленные. **＋ папка** —
выбрать ещё одну (например, «Документы»): агент сможет читать и менять файлы
в ней в этом чате, обращаясь к ней как `@Документы/отчёт.docx`. **×** — убрать
доступ. Вне этих папок агент файлов не видит. Правило «не спрашивать» для
папки — `write_file(@Документы/**)`. Инструкции и память берутся только из
папки проекта.

## 2. Режимы разрешений

Селектор рядом с полем ввода; **Shift+Tab** — следующий режим; `/mode plan` —
командой. Режим хранится в чате.

| Режим | Чтение | Правка файла | Память | Команда | MCP, плагин |
|---|---|---|---|---|---|
| Вручную | да | спросить | спросить | спросить | спросить |
| Принимать правки | да | да | спросить | спросить | спросить |
| Авто | да | да (в проекте) | да | безопасные — да, рискованные — спросить | спросить |
| План | да | нет | нет | нет | нет |
| Только разрешённое | да | по правилу | по правилу | по правилу | по правилу |
| ⚠ Без вопросов | да | да | да | да | да |

- **Авто** — середина между «Принимать правки» и «Без вопросов». Без вопросов:
  правки файлов проекта и команды вроде `npm test`, `npm run build`. С вопросом:
  удаление, сеть (`curl`), установка пакетов, `git push`, пути вне проекта
  (`/etc`, `~`, `C:\`, `..`), `node -e` и подобный встроенный код, MCP. В
  карточке написано, почему «Авто» спрашивает. Внешние CLI в этом режиме
  работают как в «Принимать правки».
- **План** — агент только читает и в конце сдаёт план карточкой (см. раздел 3).
- **Только разрешённое** — для фоновых задач: что не разрешено правилом,
  отклоняется без вопроса.
- **Без вопросов** — с подтверждением при включении, недоступен гостю, в
  недоверенной папке и если его запретила организация.
- **Чужой текст — данные.** Если в прочитанном файле, документе или письме
  есть что-то похожее на подброшенные агенту указания («игнорируй
  инструкции», «скачай и выполни», «не говори пользователю»), появится
  предупреждение, и до конца ответа даже «Авто» будет спрашивать про каждое
  действие — в карточке «⚠ Возможна атака через данные» с цитатой.
- **Отправка от вашего имени** — письмо, сообщение, событие в календаре,
  публикация через коннектор (MCP) — спрашивается **всегда**, даже в «Без
  вопросов». В карточке открыто показано, что уйдёт: кому, тема, текст.
  Запомнить такое разрешение кнопкой нельзя.
- **Удаление** агент делает только инструментом `delete_file`: файл уходит в
  корзину приложения, а разрешение спрашивается во всех режимах, кроме «Без
  вопросов» (в «Плане» и «Только разрешённое» — запрещено). Вернуть — `/trash`
  → «Восстановить». Правило на удаление — `delete_file(build/**)`.
- Во всех режимах работают guardrails (блокируют `rm -rf /`, `format C:`,
  запись `.env` и подобное) и ваши правила `deny`.

### Как отвечать на запрос

Запрос приходит карточкой в ленте: что агент хочет сделать, риск, почему
спрашиваем и — для правок — diff «было/стало».

- **1 — Да**: один раз.
- **2 — Да, и не спрашивать**: сохраняется правило, например
  `run_shell(npm test*)` или `edit_file(src/**)` — в этом чате, в этом
  проекте (только у вас) или всегда.
- **3 — Нет** (или Esc): можно написать в поле, что сделать иначе, — агент
  получит это пояснение.

Рекомендованный ответ подсвечен и в фокусе: для высокого риска (удаление,
сеть, установка пакетов, `git push`) рекомендуется «Нет».

### Правила

Правило — `инструмент` или `инструмент(маска)`: `run_shell(npm test*)`,
`write_file(src/**)`, `mcp__github__*`. Три списка: `allow`, `ask`, `deny`;
`deny` сильнее всего, `ask` сильнее `allow`. Для составной команды (`a && b`)
правило `allow` должно покрыть каждую часть.

Правила приходят с пяти уровней и складываются (ADR 0038):

| Уровень | Файл | Для кого |
|---|---|---|
| Организация | `%ProgramData%\mai-code\managed-settings.json` (macOS — `/Library/Application Support/mai-code/`, Linux — `/etc/mai-code/`) | все на машине; из приложения не меняется |
| Пользователь | поле `permissions` в `settings.json` | вы, во всех проектах (меняет admin) |
| Проект | `<проект>\.mai-code\settings.json` | вся команда — файл в git |
| Проект, только у меня | `<проект>\.mai-code\settings.local.json` | вы, в этом проекте; файл сам добавляется в `.mai-code\.gitignore` |
| Чат | — | этот чат |

Правила проекта действуют только в доверенной папке. Запрет с любого уровня
сильнее любого разрешения: `deny` организации не снимет ни правило проекта, ни
режим «Без вопросов». Пример файла проекта:

```json
{ "permissions": { "allow": ["run_shell(npm run lint)", "run_shell(npm test*)"], "deny": ["edit_file(.env*)"] } }
```

Файл организации может также запретить «Без вопросов» (`"disableBypassMode": true`)
и добавить хуки (`"hooks"`, как в разделе 10) — они выполняются всегда.

**`/permissions`** — панель: все действующие правила с уровнем, кнопка
«Убрать» для правил чата, «только у меня» и пользователя, и проверка «что
будет с этим вызовом»: выберите инструмент, введите команду или путь — панель
ответит «разрешено / спросит / запрещено» и назовёт правило и уровень.

## 3. Диалог с агентом

- **Enter** — отправить, **Shift+Enter** — новая строка.
- Пока агент работает, **Enter** ставит сообщение в очередь: агент прочитает
  его перед следующим шагом. Сообщение из очереди можно убрать ✕; если агент
  закончил, не взяв его, текст вернётся в поле ввода.
- **Esc** — остановить агента. Команда `run_shell` останавливается вместе со
  всеми дочерними процессами.
- **↑** в пустом поле — последнее сообщение.

Что появляется в ленте:

| Карточка | Что делать |
|---|---|
| **Агент спрашивает** | выбрать вариант; рекомендованный стоит первым, подсвечен и уже выбран — достаточно Enter; 1–4 — выбор, «Другое…» — свой ответ |
| **План готов** | выбрать альтернативу (рекомендованная подсвечена) и «Выполнить: принимать правки» / «вручную» — режим переключится сам; «Доработать план» — вернуть замечания |
| **Разрешить действие?** | см. раздел 2 |
| **Задачи агента** над полем ввода | агент ведёт план многошаговой работы: текущая задача выделена, выполненные зачёркнуты |
| Карточка инструмента | «Edit main.js +3 −1», «Bash npm test»; раскрыть — аргументы, diff, вывод; пока команда идёт, вывод виден вживую |
| **Контекст сжат** | ранняя часть диалога заменена сводкой (раздел 5) |

Если окно не в фокусе, приходит системное уведомление: «Нужно разрешение»,
«Агент спрашивает», «План готов», «Агент закончил».

### Как агент работает с файлами

- Ищет файлы по маске (`glob`: `**/*.docx`), читает, правит точечными
  заменами — можно несколько за раз.
- Открывает картинки (если модель их видит) и читает текст PDF; для скана
  подскажет OCR.
- Не правит и не перезаписывает файл, который не прочитал: если файл
  изменили вы, пока агент работал, он перечитает его.
- Читает страницы (`web_fetch`) и ищет в интернете (`web_search`) — с вашего
  разрешения; «Да, и не спрашивать» запоминает сайт (`web_fetch(docs.python.org)`).
  Поисковик — «Настройки» → «Поиск в интернете»: DuckDuckGo без ключа, свой
  SearXNG или Brave Search с ключом. Адреса вашей локальной сети агенту
  недоступны, пока вы это не разрешите там же.
- Долгие команды (сервер разработки, `watch`-сборку) агент запускает в
  фоне и проверяет их вывод по ходу работы; разрешение — как на обычную
  команду, в запросе написано «(в фоне)». При выходе из приложения такие
  команды останавливаются.
- Длинный вывод (большой лог, огромный результат поиска) агент получает
  кратко, а целиком он лежит в `@вывод` — агент дочитает нужное место сам.

## 4. Команды, файлы и память из поля ввода

`/` открывает меню команд (стрелки, Tab — подставить, Enter — выполнить).

| Команда | Что делает |
|---|---|
| `/help` | команды и клавиши |
| `/clear` | новый чат |
| `/resume [поиск]` | найти и продолжить чат из любого проекта |
| `/model <часть названия>` | сменить модель |
| `/mode <режим>` | сменить режим разрешений |
| `/init` | агент изучит проект и напишет `AGENTS.md` |
| `/memory` | открыть память |
| `/export` | скачать чат (MD, TXT, DOCX, XLSX) |
| `/context` | из чего состоит контекст модели |
| `/compact [что сохранить]` | сжать раннюю часть диалога |
| `/cost` | токены и стоимость чата |
| `/hooks` | настроенные хуки |
| `/permissions` | правила разрешений по уровням, проверка вызова |
| `/trash` | корзина: удалённые агентом файлы, восстановление |
| `/schedule` | плановые задачи |
| `/connectors` | каталог коннекторов |
| `/agents` | типы субагентов |
| `/packages` | пакеты плагинов: список, установка, включение |
| `/<навык>` | выполнить задачу по навыку |

**Свои команды** — файл `.mai-code/commands/review.md` становится `/review`:

```markdown
---
description: Ревью изменений
argument-hint: <путь>
---
Проведи ревью $1: ошибки, безопасность, тесты. Полный запрос: $ARGUMENTS
```

Глобальные команды — папка `commands` в `%APPDATA%\mai-code`. Команды проекта
работают только в доверенной папке; встроенные имена не переопределяются.

**`@файл`** — после `@` появляется список файлов проекта. Агент получит ссылку и
сам прочитает файл (копия в запрос не вставляется).

**`# текст`** — не уходит агенту, а записывается строкой в память проекта
(рекомендуется) или глобальную.

## 5. Контекст и стоимость

- Индикатор **«контекст N%»** у поля ввода: жёлтый с 70%, красный с 85%.
  Число — по данным провайдера за последний запрос плюс оценка новых сообщений.
- С **80%** перед следующим шагом ранняя часть диалога сжимается моделью в
  сводку: цели, решения, изменённые файлы, ошибки, что осталось. Сжатые
  сообщения остаются в чате под карточкой «Контекст сжат», но модели больше не
  уходят. Вручную — `/compact что сохранить обязательно`. Выключить
  автоматическую — `"autoCompact": false` в `settings.json`.
- `/cost` — токены по моделям, включая кэш. Цена считается, если у модели
  провайдера задано `"price": { "input": 3, "output": 15 }` (долларов за
  1 млн токенов).

### Если модель недоступна

При перегрузке (429, 503) или обрыве связи агент повторяет шаг до трёх раз —
вы увидите «503: … — повтор через 5 с». Не помогло, или модель вообще
недоступна (неверный ключ, нет такой модели, закончились средства) — дальше
ответит **запасная модель** из «Настройки» → «Запасная модель»
(`провайдер/модель`), если она задана. Об этом тоже будет уведомление.

## 6. История: чаты, правка, откат

- В списке — чаты текущего проекта; «этот проект» ↔ «все проекты»; поиск — по
  заголовку и тексту сообщений.
- **✎** у своего сообщения — изменить и отправить заново: сообщение и всё после
  него заменятся новым запросом. Файлы не трогаются.
- **↺** у своего сообщения — вернуться к этому месту. Окно покажет, какие файлы
  вернутся и какие будут удалены:
  - **Код и диалог** (рекомендуется, если были правки);
  - **Только диалог** — текст сообщения вернётся в поле ввода;
  - **Только код** — чат остаётся.

Откат возвращает правки, сделанные `write_file` и `edit_file`, в том числе
субагентами. **Изменения командами `run_shell` откат не возвращает** — для них
используйте git. Файлы больше 5 МБ в чекпоинт не попадают.

## 7. Инструкции проекта и память

| Файл | Для чего |
|---|---|
| `AGENTS.md` в корне | правила проекта; строка `@docs/rules.md` подставляет файл |
| `AGENTS.local.md` в корне | личные правила, не для git |
| `AGENTS.md` в подпапке | правила этой папки — приходят агенту, когда он впервые трогает её файлы |
| `.mai-code/memory.md` | память проекта: проверенные уроки и решения |
| `%APPDATA%\mai-code\AGENTS.md`, `memory.md` | глобальные правила и память |

Всё проектное — только в доверенной папке. Подробнее о памяти — [MEMORY.md](MEMORY.md).

### Навыки

Навык — папка `.mai-code/skills/<имя>/` (или глобальная, или из пакета) с
`SKILL.md`: инструкция, как делать определённую работу. Агент видит описания
всех навыков и загружает нужный сам; `/имя задача` — вызвать навык явно.

```text
deploy/
  SKILL.md        ---
                  name: deploy
                  description: выкладка на стенд
                  allowed-tools: run_shell(bash scripts/deploy.sh*)
                  ---
                  Сначала прочитай checklist.md, затем запусти scripts/deploy.sh.
  checklist.md
  scripts/deploy.sh
```

- Файлы рядом с `SKILL.md` агент читает, только когда они нужны.
- `allowed-tools` — что навыку можно без вопроса, пока идёт этот ответ агента:
  появится уведомление «Навык … разрешил …». Слишком широкие правила
  (`run_shell` без маски, `*`) не выдаются; запреты `deny` и guardrails сильнее.

## 8. Субагенты

Агент сам решает поручить подзадачу субагенту (инструмент `agent`). У
субагента свой контекст; основной агент получает только итог — поиск по
большому проекту не засоряет историю. Ход работы субагента виден в карточке
«Agent explore …».

| Тип | Что умеет |
|---|---|
| `explore` | найти файлы, код, факты — только чтение |
| `plan` | изучить код и вернуть план — только чтение |
| `general` | выполнить подзадачу с правками и командами |

Разрешения субагента — те же, что у чата: тот же режим, правила, хуки; запросы
приходят в ту же ленту. Несколько субагентов только для чтения работают
параллельно. Свой тип — `.mai-code/agents/reviewer.md`:

```markdown
---
description: Ревьюер кода
tools: read_file, grep, list_files
---
Ищи ошибки, уязвимости и пропущенные тесты. Верни список с путями и строками.
```

## 9. Пакеты

Пакет собирает в одно целое команды, типы субагентов, навыки, плагины, хуки и
MCP-серверы — например, «набор для ревью»: команда `/review`, агент-ревьюер и
хук с линтером. `/packages` показывает установленные пакеты, что в каждом есть
и откуда он (глобальный или проекта).

- **Установить** — в окне `/packages` укажите папку с `mai-package.json` или
  git-URL. Пакет копируется в `%APPDATA%\mai-code\packages\<имя>\`.
- **Выключить** — снять флажок: файлы остаются, но команды, агенты, навыки,
  плагины, хуки и MCP пакета не загружаются.
- **Пакет проекта** — папка `.mai-code/packages/<имя>/` в репозитории;
  загружается только для доверенной папки и сильнее глобального с тем же именем.
- При одинаковых именах побеждает проект, затем пакеты, затем глобальные
  команды и агенты.

Пакет с плагинами, хуками или MCP помечен «исполняемый код»: такие ставьте
только из проверенных источников. Установка, удаление и включение — роль admin.

### Каталоги

Каталог — список пакетов команды в git-репозитории (или папке) с файлом
`mai-marketplace.json`. В `/packages` → «Каталоги» вставьте адрес и нажмите
«Добавить»: появятся пакеты каталога с версиями.

- **Установить** — пакет из каталога ставится как обычный.
- **Обновить** — в каталоге вышла версия новее установленной.
- **Обновить каталоги** — скачать свежие списки.
- Если в источнике пакет с другим именем или версией, чем обещает каталог,
  установка отклоняется.

Пример каталога — в [README](../README.md#пакет-пример).

Свой пакет:

```text
review-kit/
  mai-package.json      {"name": "review-kit", "version": "1.0.0", "description": "Ревью кода"}
  commands/review.md
  agents/reviewer.md
  skills/review/SKILL.md
  hooks.json
```

## 10. Хуки

Хук — ваша команда на событие агента: не давать трогать `.env.prod`, гнать
линтер после правки, не принимать работу без зелёных тестов. Настройка —
`.mai-code/hooks.json` (доверенная папка) или поле `hooks` в `settings.json`;
пример и протокол — [README](../README.md#хуки), решение — ADR 0035. Хук не
может разрешить то, что запретили guardrails, правило `deny` или режим «План».

Готовые хуки лежат в `examples/hooks/` — скопируйте папку в свой проект и
`hooks.json` в `.mai-code/hooks.json`:

| Хук | Что делает |
|---|---|
| `no-push-main.mjs main release` | агент не сможет запушить в `main` и `release` — получит отказ «работайте в dev и выкатывайте через pull request» |
| `require-docs.mjs electron renderer` | если изменён код в этих папках, а CHANGELOG.md и ADR — нет, агент не закончит работу, пока их не добавит |

## 11. Внешние агенты (OpenCode, Claude Code, Codex, Gemini)

Выбираются в списке рядом с моделью. Режим разрешений чата действует и на них:

- Claude Code, Codex, Gemini — через свои флаги;
- остальные — только в docker-режиме (проект монтируется только на чтение в
  «Плане» и «Вручную») или в «Без вопросов».

Если рантайм не может соблюсти режим, запуск отклоняется с объяснением.
Подробнее — [RUNTIMES.md](RUNTIMES.md).

### Коннекторы

`/connectors` (или «🔌 Каталог коннекторов» в окне MCP) — готовые подключения:
Linear, Notion, Sentry (вход в браузере), GitHub (персональный токен —
кнопка «Где взять токен»). «Подключить» — и сервис доступен агенту.
Организация может добавить свои коннекторы (например, внутреннюю 1С) — они
помечены «от организации». Токены хранятся зашифрованными. Письма,
сообщения и публикации через коннектор агент отправляет только после вашего
подтверждения.

### Где хранится MCP-сервер

При добавлении в окне «MCP» выберите «Где»: **для всех проектов**
(`settings.json`) или **в этом проекте (только у меня)** —
`.mai-code/mcp.local.json`, в git не попадает. Общие для команды серверы —
`.mai-code/mcp.json` в репозитории. У каждого сервера в списке подписана его
область; при одинаковом имени сильнее «только у меня», затем проект.

### MCP-серверы со входом

Удалённый MCP-сервер (поле `url`) может требовать входа. Тогда в окне «MCP»
у него статус **«нужен вход»** и кнопка **Войти**: откроется браузер, войдите
как обычно на сайте сервиса и вернитесь в приложение — сервер подключится.
Вход запоминается (зашифрованно) и продлевается сам; **Выйти** — забыть его.
Браузер никогда не открывается сам: только по кнопке.

## 12. Вложения и изображения

Кнопка «+» или перетаскивание. Файлы копируются в `.mai-code/uploads/` проекта,
агент читает их сам. Изображения (PNG, JPEG, GIF, WebP) модели с поддержкой
изображений получают как картинку; остальные — путь и распознанный текст
(кнопка «текст» у картинки, [OCR.md](OCR.md)).

## 13. Ключи, роли, безопасность

- Ключи провайдеров, токены Vault и MAS в `settings.json` зашифрованы
  хранилищем ОС (на Windows — DPAPI). Уровень защиты — «Настройки» → «Ключи и
  токены». При переносе `settings.json` на другую машину ключи нужно ввести
  заново.
- Локальная роль admin/guest — режим интерфейса, а не защита от владельца
  машины. Реальные права — при входе через Keycloak.
- Все решения о разрешениях пишутся в журнал `audit.jsonl`.

### Команды агента в Docker

«Настройки» → «Команды агента» → «выполнять run_shell в Docker-песочнице»
(нужен запущенный Docker Desktop; меняет только admin). Тогда каждая команда
агента идёт в одноразовый контейнер: проект виден как `/workspace` и
меняется по-настоящему, остальной диск, ключи и сеть — нет (сеть можно
включить). В конце вывода команды написано, где она выполнилась.

- Внутри контейнера — Linux: `ls`, а не `dir`, даже на Windows.
- Команды, которым нужен ваш компьютер (например `git *` — ключи и настройки
  git), впишите в «На хосте (маски)».
- `npm install` без сети не скачает пакеты — включите сеть или разрешите команду
  на хосте.
- Docker не запущен — команда не выполнится вовсе (а не на компьютере молча).
- Рекомендуется вместе с режимами «Авто» и «Без вопросов».

## 15. Если что-то не так

| Что видно | Почему и что делать |
|---|---|
| Агент не видит `AGENTS.md`, плагины или MCP проекта | папка не доверена — «Настройки» → «Доверие к папкам» |
| «OpenCode не умеет соблюдать текущий режим» | переключите рантайм в docker-режим, задайте `permissionArgs` или режим «Без вопросов» |
| Ключ провайдера пропал после переноса настроек | ключи зашифрованы для этой учётной записи — введите заново |
| «Проект занят: чат агента уже меняет файлы» | в папке уже идёт пишущий прогон (чат, самокоррекция, рантайм) — дождитесь или остановите |
| «Хук PreToolUse отклонил вызов» | так настроен хук — `/hooks` покажет, какой |
| Откат не вернул файл | файл менялся командой `run_shell` или был больше 5 МБ |
| Режим «Без вопросов» недоступен | роль guest, папка не доверена или запрет в настройках организации — подсказка на пункте режима |
| Команда запрещена, хотя вы её разрешили | запрет (`deny`) на другом уровне — `/permissions` → «Проверить» покажет правило и уровень |
| Плановая задача ничего не сделала | ей не хватило правил: в журнале чата — «Только разрешённое… отклонено»; добавьте правило `allow` |
| Агент удалил нужный файл | `/trash` → «Восстановить» (хранится 30 дней) |
| MCP: «нужен вход» | нажмите «Войти» в окне «MCP» |
| «Порт 33418 для возврата из браузера занят» | закройте программу на этом порту или задайте `"oauth": { "callbackPort": … }` в `settings.json` |
| «Вход не завершён за 5 минут» | вход в браузере не закончили — нажмите «Войти» ещё раз |
| «Команды агента настроены на Docker-песочницу, но Docker недоступен» | запустите Docker Desktop или выключите песочницу в «Настройки» → «Команды агента» |
| В песочнице «command not found» или нет сети | в образе нет программы или сеть выключена — другой образ, включить сеть или маска «на хосте» |
| «Папка не доверена — правила проекта не сохраняются» | «в этом проекте» работает только в доверенной папке |
| Команда или агент из пакета не появились | пакет выключен в `/packages` или это пакет проекта в недоверенной папке |
| «Пакет уже установлен» | окно предложит заменить установленную версию |
| «Каталог обещал …, а в источнике …» | каталог и пакет разошлись — сообщите владельцу каталога |
| «нет mai-marketplace.json — обновите каталог» | нажмите «Обновить каталоги» |
