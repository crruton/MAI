# Repowise

[Repowise](https://github.com/repowise-dev/repowise) — локальный индекс кода, git-истории,
тестов и решений. Агент спрашивает индекс вместо того, чтобы читать файлы и делать grep,
и тратит меньше токенов. MAI Code не встраивает Repowise внутрь: он вызывает CLI и
подключает его MCP-сервер.

## Установка

Нужен Python 3.11+ и `uv` (или `pipx`):

```powershell
uv tool install repowise --python 3.12
# или
pipx install repowise
```

`uv` кладёт бинарь в `%USERPROFILE%\.local\bin`, который не всегда есть в PATH у
GUI-приложения. MAI Code ищет `repowise.exe` там явно, поэтому перезапуск оболочки не
обязателен. Проверка:

```powershell
& "$env:USERPROFILE\.local\bin\repowise.exe" --version
```

## Индексация

```powershell
cd <проект>
repowise init --yes --no-prose --no-editor-setup
repowise update
repowise doctor
```

Кнопка «Индексировать» в MAI Code вызывает ровно эту команду. Флаг `--no-editor-setup`
важен: без него `repowise init` дописывает MCP-сервер в глобальные конфиги Claude/VS Code
и ставит git-хуки. MAI Code подключает MCP сам и не должен менять чужие настройки.
Если интеграция с редактором всё-таки нужна, её включают вручную:

```powershell
repowise init --yes --no-prose
# либо только хуки, уже после индексации:
repowise hook install
```

Индекс лежит в `<проект>/.repowise`. Его стоит добавить в `.gitignore`, если он большой;
в этом репозитории он не коммитится.

## Четыре способа использования

### 1. MCP-сервер (основной)

Доска **Хранилище → Repowise → Подключить MCP** записывает в настройки:

```json
{
  "command": "<путь к repowise>",
  "args": ["serve", "--no-ui"],
  "cwd": "<проект>"
}
```

Дальше инструменты Repowise доступны встроенному агенту как `mcp__repowise__*`.
Плюс: не нужно менять код агента, инструменты появляются и исчезают вместе с сервером.

Подключение ограничено по времени: 30 секунд на `initialize` и 15 секунд на список
инструментов. Если `repowise serve --no-ui` не отвечает (в 0.60.0 такое встречается),
кнопка вернёт ошибку, а приложение продолжит работать без MCP — зависания окна нет.

### 2. Встроенные инструменты

Если в `settings.json` включить `repowise.enabled = true`, агент получает четыре
инструмента:

- `repowise_ask` — вопрос по кодовой базе;
- `repowise_context` — карточки файлов: слой, hotspot, зависимости, история;
- `repowise_risk` — что затронуто в диапазоне git и какие тесты запустить;
- `repowise_search` — гибридный поиск по коду и документации.

Это дублирует MCP, но работает без MCP-менеджера и удобно для точечных сценариев.

### 3. Дистилляция вывода

При `repowise.distill = true` инструмент `run_shell` оборачивает простые команды
(без `|`, `&`, `<`, `>`) в `repowise distill <команда>`. Длинный вывод тестов и установки
сжимается, ошибки сохраняются. Сложные shell-конструкции не оборачиваются, чтобы не
сломать семантику.

### 4. Дашборд

Кнопка «Открыть дашборд» запускает `repowise serve` в папке проекта и открывает URL в
браузере. Это отдельный процесс; при выходе из MAI Code он останавливается.

## Как это сокращает расходы

- Агент получает карточки файлов и зависимостей вместо чтения десятков файлов.
- `risk` подсказывает, какие тесты запустить, — меньше лишних прогонов.
- `distill` уменьшает объём вывода тестов/сборки в контексте.
- Индекс общий: одна база для всех агентов и людей в проекте, без повторной индексации
  каждым клиентом.

Точный эффект зависит от проекта и модели; в README Repowise есть бенчмарки, но
переносить их на конкретный репозиторий без замеров нельзя.

## Ограничения

- Repowise — Python-приложение с большим деревом зависимостей (tree-sitter, LanceDB,
  scipy и др.). Установка занимает минуты и требует Python 3.11+.
- Индекс нужно обновлять (`repowise update`); автоматического обновления по файловым
  событиям в MAI Code нет.
- `repowise ask` может обращаться к настроенной в Repowise модели. Если это внешний
  провайдер, запрос уходит туда — проверяйте конфигурацию Repowise, а не только MAI Code.
- MCP-сервер запускается в папке проекта; при смене проекта его нужно переподключить.
- В Repowise 0.60.0 `repowise doctor` иногда сообщает «no initialize response within 20s»
  и выходит с кодом 1, хотя индекс собран и `ask`/`search` работают. Это проблема самого
  `serve`, а не индекса; встроенные инструменты и `distill` при этом доступны.
- Автоматической установки git-хуков нет: `repowise init` вызывается с
  `--no-editor-setup`. Если нужны хуки, ставьте их вручную (`repowise hook install`).
- Без Repowise приложение работает обычными инструментами (`read_file`, `grep`,
  `list_files`); деградация плавная.
