# Инструкции для агентов в репозитории MAI Code

Этот файл читает MAI Code (и другие агенты) при работе с проектом. Правила
обязательны для человека и для агента.

## Обязательный процесс

1. **ADR.** Любое решение, которое меняет архитектуру, модель угроз, формат
   данных или внешнюю зависимость, оформляется как `docs/adr/NNNN-kratkoe-imya.md`
   по шаблону `docs/adr/0000-template.md`. Номер — следующий свободный.
   Статусы: `proposed`, `accepted`, `superseded`, `rejected`.
2. **Changelog.** Любое изменение поведения, инфраструктуры, CLI, IPC или
   публичных файлов добавляется в `CHANGELOG.md` в раздел `[Unreleased]`
   (`Added`, `Changed`, `Deprecated`, `Removed`, `Fixed`, `Security`).
3. **OpenSpec.** Крупная задача сначала оформляется изменением в
   `openspec/changes/<name>/` (`proposal.md`, `specs/`, `design.md`, `tasks.md`).
   Только после этого код и задачи в Multica.
4. **Multica.** Задачи формулируются по ASD-STE100: короткие предложения,
   активный залог, одна инструкция на предложение, без идиом и жаргона.
   Синхронизация: `npm.cmd run multica:sync` или панель «Multica».
5. **Проверка.** Перед коммитом: `npm.cmd run docs:check`, ручной запуск
   затронутых сценариев, `git diff --check`.
6. **Отчёт о работе.** Агент не заканчивает ответ и не прерывает работу без
   отчёта. В отчёте три части: что сделано (файлы и функции), что проверено
   (команда и результат), что осталось (следующий шаг). Если работа не
   завершена, агент пишет это прямо и называет причину. Молчаливый обрыв
   запрещён.
7. **Один проход.** Агент выполняет весь запланированный объём работы за один
   проход. Агент не останавливается после каждого файла и не ждёт слова
   «продолжи». Независимые вызовы инструментов идут одним блоком, параллельно.
   Остановка допустима в трёх случаях: нужен секрет, нужно решение
   пользователя, обнаружен блокер. При остановке агент называет причину.
8. **«Продолжи» — это сигнал сбоя.** Слово «продолжи» от пользователя означает,
   что агент остановился раньше времени. Это дефект работы агента, а не
   нормальный ход диалога. При таком слове агент:
   - не задаёт уточняющих вопросов и не просит разрешения;
   - не пересказывает уже сделанное;
   - сразу берёт следующий конкретный шаг из своего же плана и выполняет его
     до конца, включая проверку и отчёт.

   Запрещено заканчивать ответ вопросом «продолжать?», «какой этап делать?»,
   «скажите, что дальше», если в задаче уже есть названный следующий шаг.
   Если следующий шаг не назван, агент выбирает его сам по дорожной карте и
   обосновывает выбор одной строкой.
9. **Ветки: `dev` и `main`, других нет.** Разработка идёт только в `dev`.
   Прямой push в `main` запрещён: на ветке должна стоять защита GitHub
   (`restrict_pushes`), а агент push в `main` не делает ни при каких
   настройках. В `main` попадает только проверенное: перед слиянием в `dev`
   прогнаны `npm.cmd test`, `npm.cmd run test:responses`,
   `npm.cmd run test:export`, `npm.cmd run docs:check` и затронутые сценарии
   (то же гоняет `.github/workflows/ci.yml`). Слияние — через pull request
   `dev` → `main`. Временные ветки по задачам не заводятся; если задача
   крупная и ветка нужна, она удаляется сразу после слияния в `dev`.

## Технические правила

- Работай только внутри папки проекта. Не читай и не меняй чужие песочницы.
- Не коммить секреты: `.env`, `*.key`, `settings.json`, `sessions.json`,
  `mai-api-key.txt`, токены Keycloak/Multica.
- Новые IPC-каналы добавляй в `electron/preload.cjs`, `electron/main.js` и
  документируй в `docs/ARCHITECTURE.md`.
- Для опасных операций (запись, shell, docker, git push) проверяй роль
  `requireAdmin()` в main-процессе, а не только в UI.
- Интеграции с внешними сервисами должны деградировать: таймаут, понятная
  ошибка, приложение продолжает работать.
- Не обещай в документации того, что не проверено. Пиши «не проверено» или
  «требует внешней инфраструктуры».

## Стиль документации

- Русский язык, короткие абзацы, таблицы для сравнений.
- Команды — в блоках с указанием оболочки (PowerShell или bash).
- У каждой страницы есть заголовок и дата актуальности, если она важна.
- Внутренние ссылки — относительные, проверяются `npm.cmd run docs:check`.
