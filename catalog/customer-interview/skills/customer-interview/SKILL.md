# Интервью заказчика

`<docs>` — репозиторий документации продукта. Если отдельного нет — папка `docs/` основного репозитория.

Цель интервью — общее с заказчиком понимание продукта: каждое решение, от которого зависят объём, приоритеты,
ограничения, критерии успеха и поведение в user stories, принял или подтвердил заказчик, а не додумал молча владелец
продукта.

Метод — скилл `grilling`. Решения продукта образуют дерево: каждое тянет за собой зависимые. Раунд — фронтир, то есть
вопросы, все предпосылки которых уже решены, у каждого — рекомендованный ответ. Интервью идёт, пока фронтир не пуст.
Где `grilling` расходится с этим скиллом, действует этот скилл: заказчик отвечает асинхронно в issue, у раунда свои
формат и лимит.

## Перед раундом

1. Построй дерево решений по brief'у и черновику PRD, сверяясь с чек-листом качества из навыка `product-prd`: проблема
   и ценность → персоны → объём по модулям → сценарии user stories, включая ошибки, права, пустые и граничные
   данные → НФТ и метрики в числах → приоритеты и roadmap. Со второго раунда восстанови дерево из PRD (решения,
   допущения `A…`) и прошлых раундов в issue: между прогонами ты его не помнишь.
2. Факты ищи сам: brief, ответы прошлых раундов, `<docs>` (PRD, исследования, ADR, PBC), код продукта
   (только чтение), рынок — скилл `product-discovery`. Заказчика спрашивай о решениях и о фактах, которые знает
   только он: цели, аудитория, числа, сроки, бюджет, юридические и другие внешние ограничения.
3. Ветки «как реализовать» — не заказчику: это вопросы техлиду. Требования к ним (разделы 04–08) пиши сам.
4. Мелкое решение, которое не меняет объём, прими сам допущением `A…`, но не молча: такие допущения выноси в раунд
   одним пунктом со списком — «Принимаю допущения A3–A7, да?».
5. В раунд бери только фронтир. Вопрос, ответ на который зависит от другого вопроса этого же раунда, — в следующий.

## Раунд вопросов

Один комментарий в issue PRD с упоминанием заказчика — без него он не получит уведомление (или одно сообщение
в чате, если заказчик говорит там):

```markdown
## Раунд N: <о чём>

Черновик PRD: <ссылка на MR>. Что изменилось с прошлого раунда: <коротко>.
Ответьте по номерам; «да» — принять рекомендацию.

### <Тема> (раздел PRD)
**Q-N.1.** <вопрос так, чтобы «да» принимало рекомендацию>
Почему важно: <на что влияет ответ>.
Варианты: а) …; б) …; в) свой вариант.
➡️ Рекомендую а). Основание: <brief / `<docs>` / исследование / предположение>.

Дальше: <какие ветки откроют ответы этого раунда>.
```

- Не больше 10 вопросов за раунд: из фронтира — самые влиятельные (целевая аудитория, ценность, объём), остальные —
  в следующий раунд.
- Каждый вопрос — один предмет, с вариантами и рекомендацией. Основание рекомендации пиши всегда: «предположение»
  показывает заказчику, где ты угадываешь, и его «да» не превращает догадку в требование незаметно.
- Открытый вопрос, без вариантов и рекомендации, — когда варианты придумать нельзя или ответ — факт, который знает
  только заказчик (цель, число для метрики, срок, бюджет), а основания у тебя нет.
- Просить примеры, приоритеты (Must / Should / Could), числа для метрик и НФТ, имена конкурентов и аналогов.
- Issue — в `blocked`, пока заказчик не ответит. Опубликовал раунд — заверши прогон: ответ тебя разбудит.

## После ответов

1. Внеси ответы в PRD: решения — в «Ключевые продуктовые решения» `00-overview.md`, закрытые допущения — убери
   или переформулируй, детали — в нужные разделы. Запись в `CHANGELOG.md`.
2. В issue — короткая сводка: что изменилось в PRD по ответам, ссылка на коммит.
3. Пересчитай дерево: решённые вопросы открывают зависимые, ответ может добавить ветки. Фронтир не пуст или ответ
   противоречит прошлым решениям — следующий раунд. Противоречие называй прямо: «в раунде 1 решили X, сейчас Y —
   что оставляем?».
4. Вопрос остался без ответа — повтори его в следующем раунде один раз. Снова без ответа — спроси, можно ли
   принять рекомендацию как допущение.

## Конец интервью

Интервью закончено, когда фронтир пуст — все ветки дерева пройдены, ни одно решение не додумано молча, — и PRD
проходит чек-лист качества. Последний раунд — подтверждение: список ключевых решений и допущений одним сообщением
и вопрос «Всё верно, PRD можно отдавать в работу?». Ответ «да» — PRD готов.
